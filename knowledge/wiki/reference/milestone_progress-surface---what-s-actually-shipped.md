# MILESTONE_PROGRESS surface — what's actually shipped

`state/shared/MILESTONE_PROGRESS.md` (human) and `.json` (machine) are generated by `H:/prism/scripts/build-milestone-progress.mjs`. They scan every milestone envelope in `mcp-server/data/milestones/*.json` (~613 files), grep `git log --all --since=60.days` for `[<MS_TAG>]/U-<UID>` patterns, and produce a per-milestone shipped/pending breakdown.

**When to consult:**
- Before flagging a unit as missing in an audit — check if it's in the `shipped` array of its milestone (already in git, just envelope status didn't update).
- When deciding what to work on next — sort milestones by `pending` desc and `lastShippedDate` desc.
- When a roadmap planner asks "what's the real status of MS-X?" — `derivedStatus` field gives the git-grounded answer.

**Drift fields per milestone:**
- `claimedStatus` — whatever the envelope JSON's `status` field says (often stale).
- `derivedStatus` — `not_started_real | in_progress_real | completed_real | no_units` derived from git.
- `drift` — `consistent | claims_not_started_but_has_shipped_units | claims_completed_but_units_pending`.

**When to regenerate:**
- After any commit batch with unit IDs that touch milestone envelopes.
- Daily as a cron candidate.
- Before any 10-agent flagship audit pass — saves the audit chat from re-deriving gaps that already shipped.

**Limitations:**
- Only catches commits whose subject matches `[<TAG>]/U-<UID>`. Informal "wire batch" units (e.g., `U-WIRE-LATHE-BATCH7`) won't link to envelopes that don't list them. That's intentional — those aren't in any roadmap.
- 60-day window. Older shipped units fall out. Bump `SINCE` in the script if needed.
