# Tribal × Obsidian × system-viz utilization protocol

The three knowledge surfaces — `knowledge/tribal/` (4,245 tip files), `knowledge/memories/` (84 Obsidian-style subdirs, the in-repo 2nd brain), and `state/shared/system-viz/system-graph.json` (the live 10-layer 627-edge codebase map) — are independently mature but operationally disconnected. This memory codifies how to USE them together so the next chat does not re-derive the playbook.

**Why:** The 2026-05-09 round-2 knowledge-memory scrutiny + `tribal-utilization-audit.mjs` confirmed three disconnects: (1) the tribal-embed-index covers only 381 of 4,245 tips (9%); (2) tip files lack `domain:` and `customer:` frontmatter so the system-viz join produces 0 tips for every non-EDM cluster; (3) `OBSIDIAN_VAULT` is unset on this machine so the `tribal-obsidian-mirror.mjs` script cannot externalise tips to a phone-readable vault. Together these mean the trio currently behaves as three islands rather than one compounding artefact.

**How to apply (per-surface usage rules):**

- **Tribal tips** (`knowledge/tribal/*.md`) — the cheap-retrieval layer. Query via `tribal-rerank.mjs --query "<text>" --domain <slug> --k 3` (logs to `tribal-citation-log.jsonl` so L4/L6 hooks know which tips actually fire). Never grep the directory directly — the index is the entry point. If the rerank returns <3 hits with low cosine, the domain is tribally thin → escalate to wiki query or Claude reasoning. The 9% index coverage means most queries currently miss; running `tribal-embed-index.mjs --update --full` is the highest-leverage one-shot fix.

- **Obsidian-style memories** (`knowledge/memories/<type>/<slug>.md`) — the durable belief layer. Three types per the global CLAUDE.md schema: `feedback/` (corrections + confirmed approaches), `project/` (current-work facts), `reference/` (pointers to external systems or audited state). The `wiki-precheck-inject` hook auto-surfaces top-3 entries on UserPromptSubmit when keywords match — that is the consumption path; do not Read the entire memories tree. When writing, put the rule first, then `**Why:**` and `**How to apply:**` lines so future chats can judge edge cases.

- **system-viz** (`state/shared/system-viz/system-graph.json`, query via `scripts/system-viz-query.mjs coverage-by-domain --json`) — the structural layer. Use it to (a) check before creating an engine (does the domain already have 100+? → /dedup first), (b) identify orphaned engines (in-graph but zero inbound edges), (c) plan blast-radius before edits (neighbors query). The graph is regenerated by claude-0413eca6 — do not touch from this lane; consume read-only.

**The compounding loop the trio is supposed to close:**

```
shop-floor outcome  →  /shop-knowledge captures tribal tip
                    →  tribal-embed-index --update reindexes
                    →  domain hint backfilled from filename + content
                    →  tribal-rerank starts citing it (citation log grows)
                    →  cite-frequency promotes the tip into wiki/code-tribal/
                    →  wiki entry attaches [[wiki-link]]s to engines
                    →  system-viz nightly regen colours those engines tribal-rich
                    →  next chat's audit sees tribal density, prefers cheap path
                    →  if Obsidian env is set, tribal-obsidian-mirror.mjs externalises
                       the same tips to phone for shop-floor lookup
```

Three breaks today: (a) the index is 9% coverage so step 3 is starved; (b) tips have no `domain:` field so step 4's domain weighting falls back to "general"; (c) OBSIDIAN_VAULT unset breaks step 9. Closing in that order yields the compounding behaviour the cyrilXBT post (referenced by `reference_obsidian_compound_audit_2026-05-07`) describes.

**Maintenance cadence (when each runs):**

- Tribal index: nightly cron + on-demand after any /shop-knowledge or /distill-tribal write. Currently has no cron — manual until a `wiki-morning`-style cron is wired.
- Obsidian memories: written by chats at decision/correction time + auto-injected by `wiki-precheck-inject` and `memory-rag-inject`. The PostToolUse `memory-mirror-to-vault` hook copies new memories to the vault if env is set.
- system-viz: regenerated by `/system-viz` skill (manual) or scheduled by claude-0413eca6's lane. Auto-injected on SessionStart via `BUILD_STATE.json` summary.

**Diagnostics:**

- `node H:/prism/.claude/scripts/tribal-utilization-audit.mjs` — single-shot report (index coverage, citation activity, customer-tag coverage, Obsidian env, per-domain density join). Output lands at `state/shared/tribal-utilization-report.json` and the recommendations array is the prioritised gap list.
- `node H:/prism/.claude/scripts/tribal-density-router-bridge.mjs --domain <slug>` — quick cheap/mixed/escalate verdict for a single domain.
- `node H:/prism/scripts/system-viz-query.mjs coverage-by-domain --json` — structural side of the join.

**Anti-patterns to avoid:**

- Grepping `knowledge/tribal/*.md` directly. The corpus is too large; the index exists for a reason.
- Writing tribal tips without `domain:` and (where applicable) `customer:` frontmatter — they end up un-routable and fall through to the "general" bucket.
- Reading the full `knowledge/memories/` tree at SessionStart. The auto-inject hooks are keyword-gated; trust them.
- Editing `state/shared/system-viz/*` from any lane other than claude-0413eca6's — the graph regenerator owns it.
- Treating "OBSIDIAN_VAULT unset" as broken. The in-repo `knowledge/memories/` tree is the authoritative 2nd brain. The env-set vault is an OPTIONAL phone-mirror, not a requirement.

**Open units that close the gaps** (file as roadmap candidates — do not invent new IDs that overlap):
- `U-TRIBAL-INDEX-FULL-SWEEP` — full re-embed of all 4,245 tips
- `U-TRIBAL-DOMAIN-BACKFILL` — heuristic domain tagger that reads tip body + adds `domain:` frontmatter
- `U-TRIBAL-CUSTOMER-BACKFILL` — map filename prefixes to JM Die customer list (118 customers, 478 directories per the round-2 audit)
- `U-OBSIDIAN-VAULT-DECIDE` — either set the env or strip the mirror script and document `knowledge/memories/` as the only 2nd brain
- `U-VIZ-TRIBAL-OVERLAY` — extend `system-viz-query.mjs` with a `tribal-density` mode that joins the embed-index against the graph

## THE INJECTION SYSTEM — meta-awareness layer (added 2026-05-17, lima)

The three surfaces above (tribal, memories, system-viz) are *data*. They reach a chat through an **injection layer** — 39 SessionStart + 25 UserPromptSubmit + 1 SubagentStart hooks that auto-surface relevant slices into context. The operator's 2026-05-17 ask: chats should be *aware of the awareness system* and consume it deliberately, not let injections wash past. That passive-wash is the exact "writer-without-reader" failure the 2026-05-17 token-savings audit named — applied to the injection layer itself.

**The consumption rule (the "as intended" part):** an injection is not decoration. When a surface injects, it has done a search/lookup *for you* — acting on it instead of re-deriving is the entire point. Re-Grepping after `master-index-precheck-inject` already gave you the hits is pure waste.

### SessionStart injectors — fire ONCE per session, set the frame
| Injection | Surfaces | Consume by |
|---|---|---|
| `claude-brief-inject` | `CLAUDE-BRIEF.md` — what PRISM is, product vision, gaps | Trust it for architecture; do NOT re-derive PRISM structure from compacted memory |
| `awareness-snapshot-inject` | `AWARENESS-SNAPSHOT.md` — built/orphan/drift counts | Read before deciding "does X exist / need building" |
| `build-state-inject` | `BUILD_STATE` — built / needs-wiring / pending / frontend | Check before creating an engine |
| `inventory-check-guard` | live engine/dispatcher/action counts | Use these numbers; never hardcode counts |
| `session-start-auto-resume` | this chat's handoff `## RESUME` after /compact | Anchor to it — it is your prior exit-state |
| `roadmap-resume`, `gsd-inject`, `coordination-startup-banner` | roadmap slice · session lifecycle · peer fleet state | Orient before picking work |

### UserPromptSubmit injectors — fire EVERY prompt, the live layer
| Injection | Surfaces | Consume by |
|---|---|---|
| `master-index-precheck-inject` | top-5 system-graph hits for your prompt | **USE these instead of Grep/Glob/Agent.** This is the search-first path. |
| `wiki-precheck-inject` | top-3 wiki entries on keyword match | **READ the entry before re-deriving.** `/wiki-query <name>` for full text. |
| `audit-viz-first-inject` | auto-runs `system-viz-query find` before you Grep, on audit intent | **TRUST the result** — don't re-Grep what it already found |
| `skill-auto-trigger` | top-K skill suggestions for the prompt | Invoke the skill if it matches; suggestions, not auto-runs |
| `ollama-pipeline-injector` / `ollama-task-offloader` / `ollama-auto-router` | Ollama routes for mechanical text work | Route summarize/explain/classify off Claude per the suggestion |
| `chat-bus-inject` | peers online + files claimed by other chats | **RESPECT claims — never edit/commit a peer-claimed file.** Compact mode default (`PRISM_CHAT_BUS_COMPACT=1`, 2026-05-17). |
| `close-out-audit-suggest` / `loop-iteration-inject` / `pick-prefresh-inject` / `goal-prereq-inject` | close-out debt · loop state · pickup freshness · /goal preflight | Act on the specific reminder each carries |

### Edit/Write-time + SubagentStart
| Injection | Surfaces | Consume by |
|---|---|---|
| `memory-relevance-inject` (PreToolUse:Edit/Write) | memos matching the file you're about to edit | Scan for a memo that **contradicts** what you're about to do; that's the high-value catch. (Hook has no telemetry — value unmeasured; `PRISM_MEMORY_RELEVANCE=0` to disable.) |
| `subagent-start-context` (SubagentStart) | per-task master-index + tribal presearch for the spawned subagent | The subagent gets its own search bundle — brief it on the *task*, it self-orients |

### Knobs (every injector is tunable)
`PRISM_MASTER_INDEX_INJECT=0` · `PRISM_AWARENESS_INJECT=0` · `PRISM_CHAT_BUS_COMPACT=1` · `PRISM_MEMORY_RELEVANCE=0` · `PRISM_SKILL_AUTO_TRIGGER_DISABLE=1` · `PRISM_OLLAMA_PIPELINE_INJECT=0` · `PRISM_AUDIT_VIZ_FIRST_DISABLE=1`. The full hook list is in `C:/Users/wompu/.claude/settings.json` `hooks.{SessionStart,UserPromptSubmit}`.

### Anti-patterns specific to the injection layer
- **Grepping after `master-index-precheck-inject` already answered.** The injection IS the search; re-running it is the writer-without-reader waste.
- **Letting `chat-bus-inject` claims wash past, then editing a peer-claimed file.** The claim list is load-bearing; read it.
- **Ignoring `wiki-precheck-inject` and re-deriving a documented concept.** If the wiki entry exists, read it first.
- **Treating SessionStart digests as noise.** `CLAUDE-BRIEF` / `AWARENESS-SNAPSHOT` / `BUILD_STATE` are the frame — re-deriving PRISM's state from conversation memory after /compact is how stale assumptions creep in.
- **Adding a new injection hook to "fix" a gap.** The token-savings audit found ~500 hooks never fire. The injection layer is over-supplied, not under-supplied — tune or consume existing injectors before wiring another.
