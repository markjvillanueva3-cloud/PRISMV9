**Quick‑Check Checklist for “Chat Sessions Keep Logging Out” on the MCP Server**

| # | What to Verify | Why It Matters |
|---|----------------|----------------|
| 1 | **Session Timeout Settings** (e.g., `session_timeout`, `keep_alive_interval`) | If set too low, users will be dropped after a short period. |
| 2 | **Authentication Service Health** (`auth-service` or LDAP/AD) | A failing auth service can cause repeated re‑authentication failures. |
| 3 | **Load Balancer / Reverse Proxy Config** (Nginx, HAProxy, etc.) | Incorrect `proxy_read_timeout`, sticky sessions, or missing `X-Forwarded-*` headers can terminate sockets. |
| 4 | **Network Latency / Packet Loss** between client and server | High jitter can trigger TCP timeouts on the chat socket. |
| 5 | **Server Resource Utilization** (CPU, RAM, I/O) | Over‑utilized resources may drop connections or delay heartbeats. |
| 6 | **MCP Server Logs** (`/var/log/mcp/*.log`) | Look for `session expired`, `heartbeat timeout`, or `auth failure` messages. |
| 7 | **TLS/SSL Handshake Errors** | Mis‑configured certificates can cause abrupt disconnects. |
| 8 | **Firewall / Security Group Rules** | Ensure ports (e.g., 3100, 443) allow sustained TCP connections. |

---

### Step‑by‑Step Diagnostic

1. **Reproduce the Issue**
   - Open a chat session and keep it idle for > `session_timeout`.  
   - Note the exact time of disconnection.

2. **Check MCP Server Config (`/etc/mcp/server.conf`)**
   ```bash
   grep -E 'session_timeout|keep_alive' /etc/mcp/server.conf
   ```
   - If `session_timeout=30s`, raise it to 5–10 min for testing.

3. **Inspect Auth Service Logs**
   ```bash
   journalctl -u mcp-auth.service | tail -n 50
   ```
   - Look for repeated “invalid token” or “user not found”.

4. **Review Load Balancer / Proxy Settings**
   ```bash
   cat /etc/nginx/conf.d/mcp.conf
   # or
   cat /etc/haproxy/haproxy.cfg
   ```
   - Ensure `proxy_read_timeout` ≥ `session_timeout + 30s`.  
   - Verify sticky‑session (`ip_hash;` or `stick-table`) is enabled.

5. **Network Diagnostics**
   ```bash
   ping -i0.2 <mcp-server-ip>
   mtr -r -c 10 <mcp-server-ip>
   ```
   - Look for packet loss > 1% or high latency spikes.

6. **Resource Monitoring**
   ```bash
   top -b -n1 | grep mcp
   iostat -xz 1 5
   ```
   - If CPU > 80% or disk I/O stalls, consider scaling resources.

7. **TLS Verification (if using HTTPS)**
   ```bash
   openssl s_client -connect <mcp-server-host>:443 -servername <host>
   ```
   - Check for handshake errors or certificate mismatches.

8. **Firewall Rules**
   ```bash
   iptables -L -n | grep 3100
   # or
   ufw status verbose
   ```
   - Ensure no rate‑limit or timeout rules are killing idle connections.

---

### Common Fixes

| Symptom | Likely Cause | Quick Fix |
|---------|--------------|-----------|
| “User logged out after X minutes of inactivity” | `session_timeout` too low | Increase to 5–10 min. |
| Disconnections on load‑balanced setup | Sticky sessions missing | Enable `ip_hash;` or use session cookies. |
| Auth failures every few minutes | Expired JWT tokens | Extend token lifetime or refresh logic. |
| Random disconnects with high latency | Network jitter | Optimize routing, add a closer edge server. |
| TLS handshake errors | Outdated cert chain | Renew certificates and reload services. |
