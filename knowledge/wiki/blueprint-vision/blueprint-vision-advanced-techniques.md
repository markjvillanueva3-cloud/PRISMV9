# Blueprint-Vision Advanced Techniques

The WORLD-LEADER-DEPTH layer for the blueprint-vision galaxy: the state-of-the-art STRATEGIES an expert drawing-interpreter + extraction-pipeline architect reaches for once the intro theory and the common gotchas are already handled. DISTINCT from the two siblings -- read them first:

- `blueprint-vision-foundations.md` -- intro theory (GD&T five families, FCF structure, MMC/LMC *definitions*, NIST digital thread, machine-vision/signal/optics/statistics grounding). This entry does NOT re-define those.
- `blueprint-vision-applied-practice.md` -- common practitioner gotchas (datum-order-matters, bonus-exists-only-with-modifier, square-vs-round zone, projected-zone, basic dims, worst-case-vs-RSS *choice*, line-types, title-block override, DPI / adaptive-threshold / deskew, the multi-read-consensus *principle*).

Each technique below = the advanced method + WHEN an expert reaches for it + the trade-off DIRECTION + an inline-cited free source + one line on how THIS galaxy applies it. Because this is a drawing-reading / extraction (non-cutting) domain the knowledge is qualitative strategy; every numeric value stays owner-gated for xray.

## 1. Datum-reference-frame establishment ORDER as a constraint-sequencing algorithm

- **Establish the DRF as an ordered 3-2-1 immobilization sequence, not a set of three datums.** The expert reads the primary datum as engaging FIRST and locking three degrees of freedom (one translation + two rotations), the secondary engaging SECOND and locking two more (one translation + one rotation), the tertiary engaging LAST and locking the final degree of freedom -- each lower-precedence datum "only control[s] the degrees of freedom not already controlled by higher precedent datums." WHEN an expert reaches for this: any position/orientation/profile callout that references a multi-datum frame, especially when reconstructing the inspection setup. Trade-off DIRECTION: honoring the engagement order reproduces the real fixturing geometry (toward correct accept/reject); flattening it to an unordered set loses the setup and lets non-functional parts pass. The datum simulator "sequentially engag[es] each datum feature in prescribed order," so the extractor's reconstruction must replay that same order. [confirmed via [GD&T Basics -- Datum Reference Frame](https://www.gdandtbasics.com/datum-reference-frame/)]
  - PRISM application: the FCF parser stores datum letters as an ordered tuple with an attached per-datum DOF-lock annotation, so a downstream virtual-setup / CMM-plan consumer can replay primary->secondary->tertiary engagement rather than treating A/B/C as interchangeable.

- **Choose/expect datums "in the order that the part would assemble in real life."** WHEN: validating that an extracted datum order is plausible -- a frame whose order does not mimic the assembly interface is a flag for a mis-read or a questionable drawing. Trade-off DIRECTION: assembly-mirroring order biases toward functionally meaningful inspection; convenience order biases toward parts that gauge fine but do not fit. [confirmed via [GD&T Basics -- Datum Reference Frame](https://www.gdandtbasics.com/datum-reference-frame/)]
  - PRISM application: a low-confidence flag fires when extracted datum precedence contradicts a known mating-interface hint, routing the frame to human review rather than silent acceptance.

## 2. MMC virtual-condition + functional-gauge strategy (bonus-tolerance exploitation)

- **Compute the VIRTUAL CONDITION boundary and treat it as a fixed-size functional go-gage.** Virtual condition is "the worst-case material envelope a part can occupy while remaining functional" -- it combines the MMC size limit with the geometric tolerance allowance so that "when the part is in its worst tolerances, the [geometric control] AND size of the hole/pin will always assemble together." A functional gage built AT that boundary "effectively verifies both size and geometry simultaneously." WHEN an expert reaches for this: clearance / assembly features called MMC, where the design intent is fit, not a numeric inspection value. Trade-off DIRECTION: gauging at virtual condition maximizes accept rate while guaranteeing assembly (toward yield + guaranteed fit); inspecting the same feature RFS needlessly rejects functionally-good parts. [confirmed via [GD&T Basics -- Maximum Material Condition (MMC)](https://www.gdandtbasics.com/maximum-material-condition/)]
  - PRISM application: when the extractor detects an MMC modifier on a clearance feature, it emits a "virtual-condition-gaugeable" semantic flag (boundary = MMC-size combined-with geometric-tolerance, computed downstream from the OWNER-gated constants) so a quoting/inspection consumer can plan a fixed functional gage instead of a variable measurement.

- **Exploit bonus tolerance as departure-from-MMC-toward-LMC: a feature failing at RFS may pass at MMC.** "When a feature departs from MMC toward LMC, the tolerance zone expands proportionally" -- so "a part that would fail inspection at RFS ... may pass when MMC is applied, provided the feature size has moved away from maximum material condition." WHEN: deciding accept/reject on a borderline geometric value where the actual size is known to be away from MMC. Trade-off DIRECTION: claiming the available bonus moves toward higher yield without compromising fit; the opposite error (inventing bonus with no modifier, or denying bonus that the modifier grants) is the false-accept / false-reject failure already catalogued in applied-practice -- this entry adds the *exploitation strategy*, not just the existence rule. [confirmed via [GD&T Basics -- Maximum Material Condition (MMC)](https://www.gdandtbasics.com/maximum-material-condition/)]
  - PRISM application: the parsed (modifier, nominal, actual-size) triple lets a consumer compute allowable-zone-as-a-function-of-size; the extractor's job is to preserve the modifier glyph + the size context so bonus can be claimed, never to bake a single tolerance number.

## 3. Profile-of-a-surface as the catch-all zone-band control

- **Read profile as a boundary BAND around the true (basic-defined) profile, and detect whether it is bilateral (default, equally disposed) or unequally-disposed (circle-U).** Profile "confines all surface points within parallel surfaces that mirror the design's true contour." By default the band divides equally on each side; the circle-U symbol redistributes it unequally (the source's example directs more tolerance to one side -- e.g. where adding material is critical vs where removal is acceptable). WHEN an expert reaches for this: any profile FCF, where missing the circle-U silently re-centers the zone and changes which side of the surface the material must live on. Trade-off DIRECTION: honoring unequal disposition protects the functional side of a contour (toward correct fit on the critical face); assuming bilateral when circle-U is present mis-locates the entire allowable band. [confirmed via [GD&T Basics -- Profile of a Surface](https://www.gdandtbasics.com/profile-of-a-surface/)]
  - PRISM application: the profile parser carries a `disposition` field (bilateral | unequally-disposed) plus the side-allocation cue, never collapsing both into a single centered band.

- **Recognize that a datum-referenced profile simultaneously controls FORM + ORIENTATION + LOCATION -- "the catch-all symbol."** Form emerges from the band width, orientation from the datum angular relationship, location from the basic dimensions positioning the true profile in the DRF. WHEN: a complex/freeform surface where designers used profile in place of several separate controls. Trade-off DIRECTION: treating one datum-referenced profile callout as the single control over all three attributes (toward faithful intent) beats decomposing it into separate form/orientation/location records that double-count or drop a constraint. [confirmed via [GD&T Basics -- Profile of a Surface](https://www.gdandtbasics.com/profile-of-a-surface/)]
  - PRISM application: a datum-referenced profile is emitted as ONE multi-attribute control node (form+orientation+location), so a tolerance-analysis consumer does not re-derive three conflicting controls from one frame.

## 4. Composite position -- two-tier PLTZF / FRTZF interpretation

- **Parse a composite (two-stacked-segment) position FCF as a pattern-locating tier over a feature-relating tier, with DIFFERENT datum behavior per tier.** The upper segment ("Pattern Locating") sets the whole pattern's position to the DRF with the more generous zone and "behaves the same as a normal position tolerance"; the lower segment ("Feature Relating") with the tighter zone "refines the location and orientation of the holes only in relation to each other." Critically, lower-frame datums (when present) "only refine orientation, not location," and the lower segment "must mirror the upper segment's datum sequence." WHEN an expert reaches for this: any hole pattern where one stacked FCF carries two different tolerance values against the same characteristic -- the classic signature of a composite control. Trade-off DIRECTION: respecting the tier split lets the pattern float against the datums while holding hole-to-hole spacing tight (toward both manufacturability AND assembly of the pattern); flattening the two tiers into one tolerance over-constrains pattern location or under-constrains inter-hole spacing. [confirmed via [GD&T Basics -- Composite Position](https://www.gdandtbasics.com/composite-position/)]
  - PRISM application: a stacked same-symbol FCF is extracted as a two-segment composite node (upper=pattern-locating, lower=feature-relating) with per-segment datum semantics, NOT as two unrelated position callouts -- otherwise the feature-relating refinement is lost.
  - (Note: GD&T Basics' dedicated composite-tolerance URLs 404'd this session; the two-tier strategy was confirmed from the reachable composite-position page. The position page also confirmed that position always references the true position established by basic dimensions [[GD&T Basics -- Position](https://www.gdandtbasics.com/position/)], the basic-dimension origin a composite control floats relative to.)

## 5. Tolerance-stack DIRECTION + sensitivity (beyond the worst-case-vs-RSS choice)

- **Build the 1-D stack as a SIGNED dimensional loop: assign each contributing dimension a + or - direction by whether it opens or closes the gap, before summing.** Each component "add[s] to or subtract[s] from the overall assembly variation depending on its role in the assembly chain"; the analysis is "a dimensional chain problem ... tracking which direction each tolerance acts relative to the final gap measurement." The expert's first move is "understanding the assembly logic first: identify which components control the gap direction, then apply cumulative analysis." WHEN an expert reaches for this: any multi-part gap/interference analysis, where getting a sign wrong flips an interference into a clearance. Trade-off DIRECTION: a correctly-signed loop is the precondition for BOTH worst-case and RSS to be meaningful (the method choice -- already in applied-practice -- is downstream of getting direction right); an unsigned "just add the tolerances" gives a number that can be wrong in sign, not just magnitude. [confirmed via [FIRGELLI -- Tolerance Stack-Up Calculator (Worst Case and RSS)](https://www.firgelliauto.com/blogs/engineering-calculators/tolerance-stack-up-calculator-worst-case-and-rss)]
  - PRISM application: when the extractor feeds a stack analyzer, each dimension carries a direction sign derived from the assembly chain (not just a magnitude), so the loop closes correctly before any WC/RSS roll-up.

- **Use RSS's squared-magnitude weighting as a SENSITIVITY signal -- larger tolerances dominate the stack disproportionately.** "Larger tolerances dominate the final stack-up more heavily than smaller ones ... since the calculation squares each tolerance before summing." WHEN: deciding which single feature to tighten to shrink an out-of-spec stack. Trade-off DIRECTION: tighten the largest contributor first (toward maximum variation reduction per unit of added manufacturing cost); tightening a small contributor wastes cost for little gain. [confirmed via [FIRGELLI -- Tolerance Stack-Up Calculator (Worst Case and RSS)](https://www.firgelliauto.com/blogs/engineering-calculators/tolerance-stack-up-calculator-worst-case-and-rss)]
  - PRISM application: a stack-analysis output ranks contributors by squared share so a quoting/DFM consumer can advise WHICH dimension to revisit -- a sensitivity ranking, not just a pass/fail.

## 6. Multi-VLM ensemble-consensus arbitration (extraction-fidelity strategy)

- **Run DIVERSE base readers, not repeats of one, and combine by (weighted) voting -- this is textbook ensemble learning.** Ensemble methods "obtain better predictive performance than ... any of the constituent learning algorithms alone," and "ensembles tend to yield better results when there is a significant diversity among the models" -- "combining identical or highly correlated models fails to generate the performance gains." Combination is by voting/averaging, and "a weighted averaging approach can outperform any of the individual classifiers." WHEN an expert reaches for this: the stochastic OCR/VLM failure regime (smudge, glare, hand-marks) where a single pass fails silently -- which the applied-practice CLT note motivates as *averaging*; this entry adds the strategy refinement that the readers must be DIVERSE model families and the votes can be WEIGHTED by per-model reliability. Trade-off DIRECTION: a panel of diverse VLMs with >=2-agree-corroborated arbitration drives toward robust dimension fidelity (a 1-of-N read is a hallucination candidate); a panel of near-identical readers gains little over one and wastes compute. [confirmed via [Wikipedia -- Ensemble learning](https://en.wikipedia.org/wiki/Ensemble_learning)]
  - PRISM application: the galaxy's multi-VLM consensus stage deliberately mixes distinct VLM families (diversity), treats a dimension agreed by >=2 independent reads as corroborated, flags a 1-of-N value as a hallucination candidate, and can weight each model's vote by its measured reliability. The agreement threshold + per-model weights are owner-gated.

## 7. Born-digital-vs-OCR routing + segmentation-aware extraction (the front-end that decides HOW to read)

- **Route a PDF page by whether it already carries an embedded text layer (born-digital) before ever invoking OCR.** PyMuPDF retrieves "embedded text directly" via `get_text()`; OCR "becomes necessary for image-based PDFs" that have no text layer. WHEN an expert reaches for this: any PDF intake, where a born-digital page's embedded text is machine-exact and an OCR pass on it only INTRODUCES error. Trade-off DIRECTION: extracting the embedded text layer when present preserves exact dimension fidelity (toward zero-loss for digital prints); blindly OCR-rasterizing every page degrades born-digital pages to an OCR error rate they never had. [confirmed via [PyMuPDF -- Text Extraction recipes](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)]
  - PRISM application: the intake router probes each page for a text layer; born-digital pages take the text-layer path (authoritative), image-only pages fall through to the rasterize + multi-VLM/OCR path -- a per-page decision, not a whole-document mode.

- **Treat Otsu global binarization as valid only under its BIMODAL-histogram assumption, and route away from it when the assumption breaks.** Otsu's method assumes a histogram "consist[ing] of two peaks" (foreground ink vs background paper). WHEN an expert reaches for this: choosing binarization per image -- a clean scan with two clear peaks is Otsu's home turf; a gradient-lit phone photo or faded copy violates bimodality. Trade-off DIRECTION: routing non-bimodal images to adaptive/local thresholding (the applied-practice remedy) is now *triggered by a histogram test*, not applied blindly -- this entry supplies the routing RATIONALE behind the gotcha. [confirmed via [OpenCV -- Image Thresholding tutorial](https://docs.opencv.org/4.x/d7/d4d/tutorial_py_thresholding.html)]
  - PRISM application: the binarization stage inspects the intensity histogram; a clean bimodal page uses global Otsu, a non-bimodal page is routed to adaptive thresholding -- a measured branch, not a fixed pipeline.

- **Constrain the recognizer with the right Page Segmentation Mode AND a character whitelist for structured drawing regions.** Tesseract "expects a page of text" by default, but "If you're just seeking to OCR a small region, try a different segmentation mode" -- a single uniform block, a single line, a single word, or sparse text in no particular order -- and "selecting the appropriate mode significantly improves accuracy on structured documents." Separately, when "you will only encounter a subset of the characters ... such as only digits," a character whitelist "helps improve accuracy when the character set is known." WHEN an expert reaches for this: region-specific reads -- a dimension callout (digits + a few symbols), a single-line title-block field, an FCF compartment -- where the generic full-page mode mis-segments. Trade-off DIRECTION: matching PSM to the region's layout and whitelisting its expected character set drives toward fewer phantom glyphs and correct line segmentation (toward dimension-string fidelity); the default full-page mode plus the full character set invites the smudge-read-as-a-digit failures the applied-practice catalogued. [confirmed via [Tesseract OCR -- Improve Quality](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)]
  - PRISM application: after region/layout detection, each crop (dimension, title-block field, FCF compartment) is recognized with a region-appropriate segmentation mode and a per-region character whitelist (digits/decimal/tolerance-symbols for a dimension; letters for a datum), rather than one global recognizer pass over the whole sheet.
