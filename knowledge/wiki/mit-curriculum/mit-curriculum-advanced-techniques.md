## 1. Prerequisite-graph sequencing — build the learner path as a topological sort, not a hand-ordered list

The foundations entry establishes that MIT's GIRs encode a prerequisite scaffold (Calculus before manufacturing). The *advanced* move is to stop hand-ordering courses and instead model the corpus as a directed graph and compute the order algorithmically.

- **Technique — model courses as a DAG and topologically sort it to produce a valid learner path.** Vertices are courses/subjects; a directed edge `u -> v` means "u is a prerequisite of v." A **topological sort** then yields "a linear ordering of vertices such that for every directed edge (u,v), u comes before v in the ordering" — exactly a schedule that never places a course before its prerequisites. WHEN an expert reaches for it: any time the path is more than a handful of courses, or the prerequisite web branches/converges (Calculus feeding both physics and manufacturing). TRADE-OFF DIRECTION: a topological sort produces *a* valid order, not a unique one — more independent branches means more equally-valid orderings, so you layer a secondary ranking (domain relevance, difficulty) on top to pick among them; the cost is you must maintain the edge set, but the payoff is the ordering is provably dependency-correct instead of trusting a human's mental model. (Wikipedia: Topological sorting — "for every directed edge (u,v)... u comes before v.") → PRISM hit: the academy learner-path builder should derive its course order from a topological sort of the OCW-subject prerequisite graph keyed on the `Course N.xxx` index, not from a manually sequenced list.

- **Technique — run cycle detection as a curriculum-integrity gate before you ever publish a path.** A topological ordering "exists exclusively when the graph contains no cycles — that is, when it forms a directed acyclic graph (DAG). If cycles exist, no valid ordering is possible." So a cycle in your prerequisite edges is not a scheduling inconvenience — it is a *data error* (a mis-entered prerequisite, or two courses each listed as the other's prereq). WHEN: every time the prerequisite edge set changes. TRADE-OFF DIRECTION: Kahn's algorithm gives cycle detection for free (if it cannot drain every vertex, the remainder is a cycle), so the integrity check costs nothing extra beyond the sort you already run — the discipline is to *treat a sort failure as a blocking error*, not silently emit a partial path. (Wikipedia: Topological sorting — Kahn's algorithm removes in-degree-zero vertices iteratively; a non-empty remainder is a cycle.) → PRISM hit: the academy path-build step should fail loud (R12) when the prerequisite graph is cyclic, surfacing the offending edge for lima rather than shipping a path that skips a prerequisite.

## 2. Learner-path scheduling beyond order — spacing and granularity as design levers

Ordering is necessary but not sufficient; the expert also decides *when material recurs* and *how big each unit is*.

- **Technique — schedule review with expanding (spaced) intervals, not a single linear pass.** Spaced repetition presents material "at expanding time intervals to counteract natural memory decay"; the spacing effect means "with each expanded interval of repetition it becomes more difficult to retrieve the information... this creates a deeper level of processing... in long-term memory." WHEN an expert uses it: building a *retention* path (a learner who must still know the material weeks later), as opposed to a one-shot reference read. TRADE-OFF DIRECTION: expanding intervals deliberately accept *lower immediate-review accuracy* in exchange for *superior long-term retention* — the opposite of cramming/massed practice, which inflates short-term recall and collapses later. So the lever is set toward wider spacing when durable mastery is the goal, narrower when only short-term familiarity is needed. (Wikipedia: Spaced repetition — expanding intervals favor long-term over short-term retention.) → PRISM hit: an academy curriculum that revisits a Course-2 manufacturing concept should re-surface it on widening intervals (interleaved with later material) rather than presenting it once and moving on; the *interval schedule numbers* are owner-gated.

- **Technique — tune learning-object granularity against the reusability paradox instead of defaulting to "whole course."** Reusable units are "self-contained," "context-independent," and metadata-tagged so they can be recombined — but David Wiley's **reusability paradox** states "if a learning object is useful in a particular context, by definition it is not reusable in a different context." WHEN: deciding how finely to chunk an OCW course for the academy — per-lecture, per-topic, or per-course. TRADE-OFF DIRECTION: smaller/more-granular objects "enhance reusability but risk fragmentation and loss of coherent learning experiences"; larger objects "provide richer pedagogical context but sacrifice flexibility" — so the expert chunks *finer when the same concept must serve many domains* (a generic math primer reused across mill/lathe/wedm paths) and *coarser when pedagogical coherence dominates* (a single integrated manufacturing-systems narrative). The choice is a deliberate dial between cross-context reuse and in-context coherence, never a fixed default. (Wikipedia: Learning object — reusability paradox + granularity trade-off.) → PRISM hit: the corpus-to-lesson splitter should pick OCW chunk size per intended-reuse-breadth (shared-primer = fine-grained, domain-narrative = coarse), and tag each chunk with discovery metadata so the path builder can recombine it.

## 3. License-aware aggregation — treat CC compatibility as remix engineering, not a footnote

Applied-practice covers the single-source attribution/SA gotchas. The *advanced* discipline is engineering a *multi-source* corpus where works under different open licenses are deliberately combined.

- **Technique — run every remix through the CC license-compatibility chart and adopt the most-restrictive resulting terms.** Combining CC works "requires careful attention to compatibility... not all licenses can be mixed." The compatibility chart is a matrix (first work's license across the top, second down the side; checkmark = combinable, X = not); the load-bearing rule is "Use at least the most restrictive licensing of the two... for the new work." WHEN an expert reaches for it: any lesson that *blends* (not merely quotes) OCW content with a second open source. TRADE-OFF DIRECTION: combining a `BY-SA` source (which *requires* the derivative stay shareable and "can therefore be used commercially") with OCW's `BY-NC-SA` (which *prohibits* commercial use) is a flagged X — "a fundamental contradiction" — so the more-restrictive NC wins and the blend inherits the strictest constraint; the direction is always *toward the most-restrictive license present*, never an average. (Creative Commons wiki: license compatibility chart — most-restrictive-terms rule; BY-SA + BY-NC-SA conflict.) → PRISM hit: the corpus-aggregation layer must evaluate the compatibility cell for every pair it blends and stamp the resulting (most-restrictive) license on the derivative — distinct from applied-practice's *single-source* SA gotcha, this is the *multi-source* matrix decision.

- **Technique — route NoDerivative-licensed sources to quote-only, never to the remix pipeline.** Works carrying the **ND** clause "cannot be remixed at all" and "may only be distributed... in their original form" with no modifications. WHEN: a high-value source you'd love to adapt turns out to be `BY-ND` or `BY-NC-ND`. TRADE-OFF DIRECTION: ND content can still be *cited/linked/quoted verbatim with attribution* (which needs no license permission and triggers no SA), but the moment you adapt it you are in violation — so the expert classifies each source by remix-eligibility *at ingest* and shunts ND material into a quote-only lane rather than discovering the restriction after building a derivative. (Creative Commons wiki: license compatibility — ND = no modifications, original form only.) → PRISM hit: the ingest classifier should tag each source `remixable | quote-only` from its license, and the lesson builder must refuse to adapt a quote-only source — pairs with applied-practice's "decide the derivative license before first publication" since CC grants are irrevocable.

## 4. Born-digital-vs-scan extraction ROUTING — detect the text layer first, OCR only as fallback

Applied-practice warns that re-OCRing born-digital text injects errors. The *advanced* technique is the routing system that decides per-document which extraction path to take — and exploits PDF structure when it exists.

- **Technique — detect the embedded text layer and route born-digital PDFs to exact text extraction, image-only PDFs to OCR.** In a native PDF "text is represented by text elements in page content streams"; by contrast "a text document which is scanned to PDF without the text being recognised by OCR is an image, with no fonts or text properties." WHEN an expert reaches for it: the very first step of ingesting any OCW PDF, before any extraction runs. TRADE-OFF DIRECTION: born-digital text extraction is *exact* (the characters are stored), OCR is a *lossy estimate* — so the router must prefer the text-content-stream path whenever a real text layer is present and fall back to OCR only for genuine image-only scans; getting the routing wrong (OCRing a born-digital file) trades exactness away for nothing. (Wikipedia: PDF — content-stream text vs image-only scanned PDF.) → PRISM hit: the corpus-ingestion step should probe each OCW PDF for an embedded text layer and stamp `extraction_method = born-digital | ocr` accordingly, so downstream consumers know the text's trust level (the per-document method field applied-practice owner-gates).

- **Technique — exploit Tagged-PDF logical structure for reading order, and reconcile the three PDF "views."** "A tagged PDF includes document structure and semantics information to enable reliable text extraction" and "defines a set of standard structure types... that allow page content... to be extracted and reused." But a PDF has "three distinct views... the physical view, the tags view, and the content view" which "can be inconsistent with each other." WHEN: extracting structured/multi-column academic notes where naive top-to-bottom reading scrambles the order. TRADE-OFF DIRECTION: when the tag tree is present and consistent, trust it for reading order (it resolves the multi-column zoning that breaks geometric extraction); when the views disagree, that disagreement is itself a flag to drop to careful zone-aware extraction rather than trusting either blindly — the lever moves toward structure-driven extraction where structure exists, geometry-driven only where it does not. (Wikipedia: PDF — Tagged PDF structure + three-views inconsistency.) → PRISM hit: the lecture-note extractor should consult the PDF tag tree for reading order before falling back to geometric column-detection, and treat tag/content-view disagreement as a low-confidence signal for owner review — sharper than applied-practice's general "multi-column is where OCR fails."

## 5. Course-version-drift tracking + OER quality rubrics — preservation-grade integrity and scored selection

Applied-practice notes that links rot and terms drift. The *advanced* practice borrows from digital preservation to *detect* drift mechanically, and from OER quality literature to *score* what's worth ingesting.

- **Technique — compute a fixity checksum per ingested artifact and re-verify on a schedule to detect silent drift/corruption.** **File fixity** is "the property of a digital file being fixed, or unchanged," and a fixity check is "accomplished by computing checksum or cryptographic hash function values for a file and comparing them to a stored value." WHEN an expert reaches for it: any corpus that must stay authentic over time — exactly PRISM's OCW snapshots, which the source can revise or withdraw under you. TRADE-OFF DIRECTION: fixity "by itself... does not ensure the preservation of a digital file" — it only *detects* change so "a repository [can] identify which corrupted files to replace with a clean copy from the producer or from a backup." So the strategy is detect-then-recover, not prevent: store a hash at ingest, re-hash periodically, and on a mismatch re-fetch from MIT rather than trusting an aged local copy. (Wikipedia: File fixity — checksum/hash comparison detects change.) → PRISM hit: the corpus record should carry a content hash alongside its `{course_number, term, instructor}` key (from applied-practice's version-pin); a periodic fixity re-check turns "the URL silently went stale" into a detected, actionable mismatch — the *cadence* is owner-gated.

- **Technique — score candidate OER against an explicit quality rubric / peer-review signal instead of ingesting everything.** Quality OER ecosystems gate on review: MERLOT resources "undergo an extensive peer review," OpenStax uses "subject matter experts... peer-reviewed," and curated collections require materials "must meet quality criteria... to be added." WHEN: choosing *which* free courses enter the corpus when more are available than you can use well. TRADE-OFF DIRECTION: the OER literature itself flags that "the evidence underlying pedagogical research conducted on OER is... of a poor quality" — so the expert does not assume free == good; they apply an explicit rubric (alignment, accuracy, peer-review provenance) and prefer peer-reviewed/curated sources over raw uploads, accepting a smaller, vetted corpus over a larger, noisier one. (Wikipedia: Open educational resources — peer review + curation quality criteria; poor pedagogical-evidence caveat.) → PRISM hit: the mit-curriculum ingest should rank OCW/OER candidates by a quality rubric (peer-review provenance, catalog-curation, domain alignment to Course 2/3/8/18) rather than bulk-harvesting indiscriminately — MIT-OCW's own editorial curation is a strong provenance signal.

- **Technique — score *technical* openness (source availability), not just legal openness, before counting a resource as remixable.** The 5 Rs (Retain, Reuse, Revise, Remix, Redistribute) are the *legal* permissions, but the literature notes that without the underlying source files "the practical ability to exercise these rights" for modification is "limited" — hence the "Open Source Educational Resources" (OSER) distinction. WHEN: deciding whether a "free" resource is genuinely adaptable for a PRISM derivative. TRADE-OFF DIRECTION: a flattened PDF may be *legally* revisable yet *technically* un-revisable (you'd have to re-typeset it) — so the expert weighs format editability alongside the license; the direction is to prefer sources that ship editable/structured originals (the born-digital + tagged-structure of §4 is exactly this signal) when adaptation is intended, and treat image-only/flattened sources as quote-only even when the license permits revision. (Wikipedia: Open educational resources — 5 Rs + OSER technical-openness gap.) → PRISM hit: the remixability classifier from §3 should also read the *format* (born-digital/tagged vs scanned-flat from §4), not only the license — legal-remixable + technically-flat = effectively quote-only for PRISM.

## Owner-gate (NOT promoted)

These are the numeric constants / thresholds deliberately left for lima (owner) + operator. Every one is a calibration, NOT a literature constant, and several touch physics-bearing content where lima's gate is load-bearing:

- **[lima-gate] Spaced-repetition interval schedule.** The *direction* (expanding intervals favor long-term retention) is promoted; the actual interval lengths and the expansion ratio for an academy retention path are an owner/operator calibration — not asserted here.
- **[lima-gate] Learning-object granularity cutoffs.** The reusability-paradox *trade-off direction* is promoted; the concrete chunk size (per-lecture vs per-topic vs per-course, any minute/word bounds) for splitting an OCW course is lima's design decision.
- **[lima-gate] Extraction-method confidence thresholds.** The *routing rule* (born-digital -> exact text; image-only -> OCR; tagged-structure -> trust tag order) is promoted; the numeric OCR/extraction-confidence cutoff at which an extracted region (especially a Course-2/Course-18 equation or a cutting parameter) gates a physics-bearing lesson vs flows through is owner/operator calibration — and per the cross-galaxy safety rule, any cutting constant recovered from an OCW note (kc1.1, Taylor C/n, SFM/RPM/IPR/chip-load/feed/DOC, coolant psi) is owner-gated to lima and lives ONLY in `mcp-server/src/physics/constants.ts`, never promoted from a fetched course page.
- **[lima-gate] Fixity re-check cadence + hash algorithm choice.** The *method* (hash at ingest, re-verify periodically, re-fetch on mismatch) is promoted; the schedule cadence and which checksum/cryptographic-hash function PRISM standardizes on are operational decisions for lima.
- **[lima-gate] OER quality-rubric scoring weights + ingest threshold.** The *strategy* (score against a rubric, prefer peer-reviewed/curated, weigh technical openness) is promoted; the rubric's dimension weights and the score threshold above which a candidate enters the corpus are lima's calibration. (The exact Achieve OER rubric dimension list could not be WebFetch-confirmed from the publisher page this pass — re-fetch the published rubric PDF before hardcoding its categories.)
- **[lima-gate] License-compatibility blend whitelist.** The *most-restrictive-terms rule* and the ND quote-only routing are promoted; the actual per-pair compatibility decisions for PRISM's specific second-source licenses (and whether to accept an SA obligation on a given derivative) are per-artifact legal calls for lima/operator — mirrors the NC/SA owner-gates in foundations and applied-practice.
