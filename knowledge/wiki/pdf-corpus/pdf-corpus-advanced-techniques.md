# PDF-Corpus Advanced Techniques

The **world-leader-depth** layer for the **pdf-corpus** galaxy: the state-of-the-art STRATEGIES an expert in document-AI / large-scale OCR reaches for *beyond* the intro theory and the common gotchas. The foundations entry ([`pdf-corpus-foundations.md`](pdf-corpus-foundations.md)) owns *what a PDF is / how OCR works / how a corpus is indexed*. The applied-practice entry ([`pdf-corpus-applied-practice.md`](pdf-corpus-applied-practice.md)) owns *what goes wrong in practice* (the text-vs-raster trap, the leading-dot JSON discard, the page-0-only bug, the non-resumable burn, mojibake, single-VLM hallucination). **Read both first** — this file does NOT repeat them. THIS entry is the advanced strategy that makes the difference at the top of the field: how an expert *architects* a corpus pipeline so it degrades gracefully, corroborates load-bearing values, recovers document structure, and improves itself over time.

Every technique below is (a) confirmed by a fetched free/legal source this session, (b) tied to WHEN an expert reaches for it and the trade-off DIRECTION, and (c) mapped to how this PRISM galaxy (xray's blueprint/print corpus) applies it. **No numeric thresholds are promoted** — DPI floors, confidence cutoffs, ensemble quorum, and ship gates are owner-gated for xray (see the Owner-gate section).

## Theme 1 — Routing strategy: decide the cheapest correct path per page, and abstain when unsure

The applied-practice entry teaches that *misrouting* text-vs-raster is a silent-total-loss bug. The advanced move is to treat routing as a first-class **probabilistic classifier** that is allowed to *refuse* the cheap path and escalate, rather than a brittle binary heuristic.

- **Born-digital-text-vs-OCR routing as a confidence-scored classification, not a hard branch.** Statistical classification "analyzes individual observations into a set of quantifiable properties known as features," and a probabilistic classifier can "output a probability of the instance being a member of each class" and "abstain when its confidence of choosing any particular output is too low." [confirmed via [Wikipedia — Statistical classification](https://en.wikipedia.org/wiki/Statistical_classification)] *When an expert uses it:* on a mixed corpus where some PDFs are clean CAD exports (decode), some are scans (OCR), and some are hybrids (a digital page with a raster stamp). *Trade-off direction:* a richer feature set (text-layer character count, image-coverage ratio, producer metadata, font presence) raises routing accuracy but costs a cheap pre-pass per page; the expert spends that pre-pass because a wrong route is a total-loss, and lets the low-confidence middle abstain into a *both-paths* fallback rather than guessing. *PRISM apply:* the corpus router classifies decode-vs-OCR per page with a confidence score; the uncertain band runs BOTH decode and OCR and reconciles, instead of silently committing to one (the structural fork the foundations entry names, here promoted to an abstaining classifier).

- **Confidence-gated re-OCR — re-run only the low-confidence regions, not the whole page.** The abstain-on-low-confidence property above is the lever: a probabilistic recognizer's per-region confidence tells you exactly which crops to re-process. [confirmed via [Wikipedia — Statistical classification](https://en.wikipedia.org/wiki/Statistical_classification)] *When an expert uses it:* at corpus scale, where re-OCRing every page at a heavier setting is unaffordable but the few low-confidence cells dominate the error. *Trade-off direction:* raising the re-OCR confidence gate catches more errors but spends more compute and risks re-processing already-correct regions; lowering it is cheaper but leaks errors — the expert tunes the gate to the corpus's measured error distribution (the gate *value* is owner-gated). *PRISM apply:* a dimension cell that comes back low-confidence is re-rasterized at a heavier setting / handed to a stronger model; high-confidence regions are accepted as-is — spending GPU where the uncertainty is.

## Theme 2 — Corroboration strategy: never trust one recognizer on a load-bearing value

The applied-practice entry establishes that a single VLM hallucinates dimensions. The advanced strategy generalizes single-model distrust into a principled **ensemble** with a diversity requirement — the difference between "we ran two models" and an ensemble that actually reduces error.

- **Multi-recognizer ensemble consensus (>=2-agree) grounded in ensemble theory, not ad hoc.** "Ensemble methods use multiple learning algorithms to obtain better predictive performance than could be obtained from any of the constituent learning algorithms alone," combining predictions by voting (e.g., "three of the four predict the positive class, the ensemble's overall classification is positive"). [confirmed via [Wikipedia — Ensemble learning](https://en.wikipedia.org/wiki/Ensemble_learning)] *When an expert uses it:* on any value whose error is expensive (a tolerance, a material code, a hole count on a print). *Trade-off direction:* more ensemble members raise corroboration confidence and coverage but cost N-times the inference; the expert picks the smallest N that gives a stable majority. *PRISM apply:* run N diverse VLM families per dimension; accept a value only when >=2 independently agree (corroborated), flag a 1-of-N value as a hallucination candidate (the xray `vision-ensemble-fuse.mjs` pattern, here as the underlying ensemble principle).

- **Ensemble DIVERSITY is the load-bearing condition — agreeing clones do not reduce error.** "Ensembles tend to yield better results when there is a significant diversity among the models," and the error lower-bound "decomposes into accuracy, diversity, and the other term" — diversity directly reduces ensemble error. [confirmed via [Wikipedia — Ensemble learning](https://en.wikipedia.org/wiki/Ensemble_learning)] *When an expert uses it:* whenever choosing *which* recognizers to ensemble — the choice is not "the best two" but "the most independent two." *Trade-off direction:* two strong models that fail on the *same* inputs (same training family, same blind spot) give false corroboration; the expert deliberately mixes recognizer families (a classical OCR engine + distinct VLM lineages) so their errors are uncorrelated, accepting that a more-diverse pool may individually be weaker. *PRISM apply:* the VLM pool for the print corpus is chosen for family diversity, not just per-model accuracy — two models that hallucinate the *same* wrong dimension would corroborate a falsehood, which an undiverse "ensemble" silently does.

## Theme 3 — Structure recovery: a document is regions and tables, not a flat character stream

The foundations entry covers geometric/logical layout analysis and the recursive X-Y cut at the *region* level. The advanced layer is recovering the **logical structure of a table** (and feeding layout + image jointly to the recognizer), which is where most engineering-document value lives (title blocks, dimension tables, BOMs).

- **Table-structure recognition — recover rows, columns, cells, and spans, not just a text blob.** A table is "an ordered arrangement of rows and columns"; a cell stores information "relating to the combination of the row and column headings it is collinear with"; complex tables combine cells across rows/columns (rowspan/colspan) and "may be grouped, segmented, or arranged... and even nested recursively." [confirmed via [Wikipedia — Table (information)](https://en.wikipedia.org/wiki/Table_(information))] *When an expert uses it:* on title blocks, tolerance tables, and BOMs where a value is meaningless without its row+column header (a number under "QTY" vs under "DIA"). *Trade-off direction:* recovering full cell-grid structure (with spanning/nesting) costs a dedicated structure-recognition stage beyond plain OCR, but flat text extraction silently loses the row/column association that gives each value meaning; the expert pays for structure on tabular regions and skips it on free-text notes. *PRISM apply:* a drawing's dimension/revision table is extracted as a cell grid with header association (so `0.500` is bound to its row's feature and its column's meaning), not concatenated into an ambiguous text run — recovering the logical table the foundations entry's geometric zoning only locates.

- **Multimodal document understanding — feed text, 2-D layout, and the page image jointly.** Document AI "combines text data, which has a time dimension, with other types of data, such as the position of an address in a business letter, which is spatial," and "transformer architecture" makes combining spatial and temporal signals easier than the historical separate CNN/RNN treatment; the field is benchmarked on form-understanding and key-information tasks (FUNSD, CORD, DocVQA). [confirmed via [Wikipedia — Document AI](https://en.wikipedia.org/wiki/Document_AI)] *When an expert uses it:* when *where* a token sits is as informative as *what* it says — a number in the title-block grid means something different from the same number in a note. *Trade-off direction:* a joint text+layout+image model is heavier and harder to train than an OCR-then-NLP pipeline, but the decoupled pipeline throws away the spatial signal at the OCR boundary; the expert reaches for the multimodal approach when layout carries meaning (engineering drawings do). *PRISM apply:* the print extractor treats a recognized token together with its bounding box and the surrounding raster region, so downstream classification of "is this a dimension / a note / a title-block field" uses position, not text alone — the layout-aware framing of the corpus, distinct from the foundations entry's character-stream IR view.

## Theme 4 — Input restoration + domain priors: improve the signal before and constrain the output after

The applied-practice entry establishes that bad input (low DPI, skew, uneven background) causes most "the OCR is wrong" reports, and that internal Otsu is suboptimal on uneven backgrounds. The advanced layer is *active restoration* of the input and *domain-lexicon constraint* of the output — two ends of the recognition stage the gotcha layer only gestures at.

- **Adaptive (local) binarization over global Otsu for uneven-illumination scans.** Global thresholding "applies the same threshold to all pixels," while local/adaptive thresholding "applies a different threshold to different parts of the image, based on the local value of the pixels" and is "particularly adapted to cases where images have inhomogeneous lighting"; named adaptive methods include Niblack (mean + std-dev of the neighborhood), Sauvola (Niblack with a dynamic contrast factor), and Bernsen (local contrast in a fixed window). [confirmed via [Wikipedia — Thresholding (image processing)](https://en.wikipedia.org/wiki/Thresholding_(image_processing))] *When an expert uses it:* on shop scans, fax-quality prints, and phone photos with shadows or uneven backlight — exactly where a single global threshold blacks out a shadowed corner or washes out a bright one. *Trade-off direction:* local methods preserve fine detail and survive uneven lighting but cost a per-region computation and add a window-size parameter to tune; the expert reaches for Sauvola/Niblack on uneven scans and keeps cheap global Otsu for clean, evenly-lit pages. *PRISM apply:* the corpus pre-binarizer selects adaptive thresholding for the noisy shop-scan subset (the foundations entry's "binarization is mandatory" step, here promoted to *which* binarizer for which input class).

- **Super-resolution / restoration to recover detail before recognition — with the hallucination caveat respected.** Super-resolution is "a class of techniques that improve the resolution of an imaging system," in single-frame (computational inference from one image) and multi-frame (sub-pixel shifts across several images) variants — but "there is no guarantee that the upscaled features actually exist in the original image," making it inappropriate where hallucinated detail could cause harm. [confirmed via [Wikipedia — Super-resolution imaging](https://en.wikipedia.org/wiki/Super-resolution_imaging)] *When an expert uses it:* on under-resolved scans where the OCR engine is starved of pixels and re-scanning the source is impossible. *Trade-off direction:* SR can lift recognition on genuinely low-res input, but a neural upscaler can *invent* a stroke that turns a `3` into an `8` — so the expert uses restoration as a recognition *aid* whose output must still pass ensemble corroboration, never as a trusted source of a load-bearing digit. *PRISM apply:* a too-small dimension crop may be super-resolved to give the recognizer more pixels, but the SR'd reading is held to the same >=2-agree corroboration as any other (the same "upscaled features may not exist" distrust as the single-VLM-hallucination lesson — applied one stage earlier).

- **Domain-lexicon constraint of the recognizer output (whitelist / word-list / dictionary toggle).** Tesseract lets you "add words to the word list... or add common character patterns," restrict recognition with `tessedit_char_whitelist` (e.g., digits only), and *disable* the sentence dictionary (`load_system_dawg`/`load_freq_dawg` = false) for non-prose text like codes and receipts. [confirmed via [Tesseract — Improving the quality of the output](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)] *When an expert uses it:* on engineering documents whose vocabulary is NOT natural-language prose — dimension grammar, material codes, GD&T symbols, standard callouts — where the default English dictionary actively *mis-corrects* a valid code into a plausible word. *Trade-off direction:* a tight domain whitelist/word-list raises accuracy inside the vocabulary but rejects anything outside it (a free-text note); the expert constrains per region type (digits-only on a dimension cell, prose dictionary on a notes block) rather than globally. *PRISM apply:* the corpus recognizer disables the prose dictionary and applies a digit/symbol whitelist on dimension regions, and switches to the domain vocabulary (material codes, tolerance grammar) as the post-OCR lexicon — the foundations entry's "constrain output to a domain lexicon" principle, here as the concrete per-region recognizer configuration.

- **Lexicon-snap post-correction via edit distance (fuzzy match to the nearest valid token).** Approximate string matching finds strings that "match a pattern approximately rather than exactly," scored by edit distance (insertions/deletions/substitutions/transpositions to transform one string into another), with spell checking an explicit application. [confirmed via [Wikipedia — Approximate string matching](https://en.wikipedia.org/wiki/Approximate_string_matching)] *When an expert uses it:* as a post-recognition pass that snaps a near-miss recognized token (a material code off by one character) to the closest entry in a known-valid set. *Trade-off direction:* a generous edit-distance window corrects more OCR slips but risks snapping a genuinely-novel token to a wrong neighbor; a tight window is safe but leaves real errors uncorrected — the expert sizes the window to the vocabulary's minimum inter-token distance and never auto-snaps a load-bearing numeric (a dimension is not spell-correctable; a material *code* against a closed list is). *PRISM apply:* recognized material/standard codes are edit-distance-matched against the closed JM vocabulary and snapped when unambiguous; dimensions are explicitly excluded from snapping (no "nearest valid number" — that would fabricate a value), pairing with the JSON-notation repair the applied-practice entry covers.

## Theme 5 — Self-improvement + honest measurement: make the corpus pipeline get better and prove it did

The applied-practice entry teaches crash-safe resumability (the engineering substrate). The advanced layer is the *learning loop and the measurement discipline* that turn a static extractor into a compounding one — and that keep its reported accuracy honest.

- **Active learning with uncertainty sampling — label the examples the model is least sure about.** Active learning lets the model "interactively query a human user... to label new data points," and because "the learner chooses the examples, the number of examples to learn a concept can often be much lower than in normal supervised learning"; the major query strategy selects examples "where the current model is least certain," and it shines when "unlabeled data is abundant but manual labeling is expensive." [confirmed via [Wikipedia — Active learning (machine learning)](https://en.wikipedia.org/wiki/Active_learning_(machine_learning))] *When an expert uses it:* on a huge unlabeled document corpus where a human can only verify a small fraction — spend that human budget where it teaches the model the most. *Trade-off direction:* uncertainty sampling maximizes information per label but "risks being overwhelmed by uninformative examples" (degenerate/garbage pages the model is uncertain about for the wrong reason); the expert filters obviously-corrupt inputs before routing the rest to human review. *PRISM apply:* the prints the ensemble is least confident about (low-agreement, low per-model confidence) are the ones surfaced for operator verification — the closed-loop training the fleet is building, here as the principled *which-prints-to-label-next* strategy rather than labeling at random.

- **Held-out / out-of-sample evaluation — never report accuracy on the data the model tuned on.** Cross-validation tests "the model's ability to predict new data that was not used in estimating it, in order to flag problems like overfitting or selection bias"; evaluating on the training set gives "an optimistically biased assessment," whereas held-out evaluation gives an honest out-of-sample estimate. [confirmed via [Wikipedia — Cross-validation (statistics)](https://en.wikipedia.org/wiki/Cross-validation_(statistics))] *When an expert uses it:* whenever quoting a corpus accuracy number to decide ship/no-ship — the number must come from documents the pipeline was not tuned against. *Trade-off direction:* a held-out split costs labeled data you cannot also train on, but an in-sample accuracy number is a lie that hides overfitting; the expert always reserves an untouched gold set and reports against it. *PRISM apply:* the print-extraction accuracy gate is measured against a held-out gold set of prints the recognizer/lexicon were never tuned on — the foundations entry's "word-level not character-level accuracy" rule extended with "out-of-sample, not in-sample."

- **Report precision AND recall (and their F-score), not a single accuracy scalar.** Precision is "the fraction of relevant instances among the retrieved instances" (TP/(TP+FP)); recall is "the fraction of relevant instances that were retrieved" (TP/(TP+FN)); there is an inverse trade-off ("perfect recall by retrieving every item... perfect precision by selecting only a very few"); the F-measure is their harmonic mean. [confirmed via [Wikipedia — Precision and recall](https://en.wikipedia.org/wiki/Precision_and_recall)] *When an expert uses it:* on any extraction quoted as a percentage — a single "accuracy" number hides whether the pipeline *misses* dimensions (low recall) or *invents* them (low precision), which have opposite fixes. *Trade-off direction:* tuning the confidence/ensemble gate tighter raises precision (fewer hallucinated dims pass) but lowers recall (more real dims abstained away), and vice versa; the expert sets the operating point by which error is costlier for the use (a missed dimension a human can catch vs a fabricated one that scraps a part) and reports both numbers plus F-score, not one. *PRISM apply:* the corpus QA harness reports precision (are extracted dims real?) and recall (did we get all the dims?) separately, so the team can see whether a regression is a *miss* or a *fabrication* — the precision/recall decomposition of the "word-level accuracy" the foundations entry mandates.

- **Routing classifier confidence band** — the score below which a page abstains into the both-paths fallback, and the feature weights (text-layer char count, image-coverage ratio, producer-metadata signal) — owner-gated.
- **Confidence-gated re-OCR threshold** — the per-region confidence at which a crop is re-processed at a heavier setting — owner-gated.
- **Ensemble quorum N and agreement count** — the exact N diverse VLM families, the >=2-of-N vs weighted-vote rule, and the per-family weighting — owner-gated (only the >=2-agree + diversity *principle* is source-confirmed).
- **Adaptive-binarization window size + Sauvola/Niblack parameters** — the neighborhood window and contrast factor for the shop-scan subset — owner-gated (only "use local thresholding on uneven illumination" is doctrine).
- **Super-resolution scale factor + when to engage it** — the resolution floor below which SR runs, and the upscale factor — owner-gated (only "SR may aid recognition but its output gets no extra trust" is doctrine).
- **Edit-distance snap window per vocabulary** — the maximum edit distance at which a recognized code snaps to a valid token, and the closed vocabularies it snaps against — owner-gated (dimensions are explicitly never snapped).
- **Active-learning query budget + uncertainty cutoff** — how many low-confidence prints per cycle go to operator review and the uncertainty score that selects them — owner-gated.
- **Held-out gold-set size + precision/recall/F ship gate** — the size of the reserved gold set and the precision/recall/F operating point that gates a corpus ship — owner-gated (only "measure out-of-sample, report precision AND recall" is doctrine).
