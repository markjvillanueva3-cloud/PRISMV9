# `/goal complete` — Stop-Hook Gate

The Anthropic-built `/goal` slash command is gated by PRISM's
`goal-complete-gate.mjs` Stop hook. The gate ENFORCES that any session
declaring "goal complete" has triaged all close-out candidates and
maintained the audit-trail. Sister pipeline to [[loop]] — together they
constitute PRISM's autonomous-work + ceremonial-end pattern.

## What the gate enforces

When a session ends after running `/goal` (any phase — `/goal complete`,
`/goal new`, `/goal status`):

```
goal-complete-gate.mjs (Stop hook, Tier-0, wired FIRST in Stop chain)
├─ Scan last 256 KB of transcript for <command-name>/goal</command-name>
├─ If /goal NOT invoked → approve immediately (fast path; most chats)
├─ If /goal WAS invoked:
│  ├─ state/shared/CLOSE-OUT-CANDIDATES.json mtime ≤ 2h
│  │    (stale → BLOCK with "/close-out-audit" instruction)
│  └─ EVERY surfaced candidate must be triaged:
│     ├─ commit body matches the unit_id in last 30 commits, OR
│     └─ unit_id present in CLOSE-OUT-DEFERRED.md
│  (untriaged → BLOCK with per-unit punch list)
└─ All triaged → approve
```

The 2h staleness threshold + explicit-triage requirement together
prevent the "I shipped goal complete but never closed the books" failure
mode that the user named in `[[feedback_roadmap_close_out]]`.

## Bypass / override

| Knob | Effect |
|------|--------|
| `PRISM_GOAL_GATE_DISABLE=1` | Off entirely (avoid; defeats the close-out doctrine) |
| `PRISM_GOAL_GATE_STALE_HRS=N` | Adjust 2h threshold (default 2) |
| `PRISM_GOAL_GATE_AUDIT_BYPASS=1` | One-shot bypass — **logged to `state/shared/goal-gate-bypasses.jsonl`** (auditable) |

Bypasses are auditable on purpose — every override is a data point for
future doctrine tuning.

## Why a Stop hook (not a skill)

`/goal` is an Anthropic built-in slash command; PRISM cannot intercept the
command itself. The Stop hook is the **only universal choke point** that
fires no matter how the session ends. Triage via commit body OR explicit
deferral list — never silent skip.

## Two-surface model

| Surface | Role |
|---------|------|
| `state/shared/CLOSE-OUT-CANDIDATES.{json,md}` | What the audit DETECTS as pending close-out (regenerated by `scripts/audit-close-out-candidates.mjs`) |
| `state/shared/CLOSE-OUT-DEFERRED.md` | What the operator (or autonomous loop) has triaged as "ok to defer / closed elsewhere / false positive" |

The gate's clearance logic is: `unionForEveryCandidate(commit-body-match
OR DEFERRED-line) === every-candidate`. Candidate-set is CANDIDATES;
clearance-set is the union of the two evidence sources.

## Refresh cadence (lesson from /loop 32fcf842)

The 2h staleness threshold is ergonomic — it allows a session to land
multiple commits without re-running the audit, but forces a fresh pass
before declaring goal-complete. In a /loop running every 10m, that
means a refresh every 12 iters maintains the gate. The pattern:

```
Every 12 iters (or when CANDIDATES.json mtime > 2h):
  node scripts/audit-close-out-candidates.mjs
```

`/loop 32fcf842` did this at iter 4 (refresh after 3.3h staleness)
and iter 16 (refresh at 2.0h threshold). Both unblocked downstream
gate clearance without manual operator action.

## Close-out triage entry format

Format documented in `CLOSE-OUT-DEFERRED.md` head:

```
<unit_id> | <session/slot/chat-id> | <ISO timestamp> | <reason>
```

`<reason>` values:
- `closed-in-commit:<sha>` — already closed in a separate commit (e.g. peer chat); not duplicating
- `closed-in-disk-verify:<evidence>` — work shipped but envelope shape drifts (deliverable empty/string); content cross-ref confirms
- `defer-to-followup:<reason>` — needs more work / cross-team coord / capacity-bound
- `false-positive:<why>` — audit flagged but verification shows spec intent unsatisfied OR drift detector misled

## Loop + goal synergy

```
/loop iters → ship units + triage close-outs → CLOSE-OUT-DEFERRED grows
                                                          │
                                                          ▼
                  /goal complete invoked → gate consults DEFERRED → clears
                                                          │
                                                          ▼
                                              session ends cleanly
```

`/loop 32fcf842` validated this pattern by triaging 12 candidates over
20 iters; the /goal pre-flight stayed clear for the entire run.

## Doctrine pins

- **Standing rule from `[[feedback_roadmap_close_out]]`**: "if we complete
  a task we need to close it out in the road map so it gets updated".
  The gate is the enforcement mechanism for this user directive.
- **Standing rule from `[[feedback_auto_close_out]]`**: audit shipped-but-
  pending in roadmaps; 5 surfaces integrated; NEVER auto-flips —
  human-verify.
- **Audit-trail mandatory** — every bypass logged; every triage carries
  evidence (commit sha / disk-verify / false-positive rationale).
