## What it checks (sampled describe/it titles)

- auth revocation-store TTL eviction
- keeps a freshly-revoked (still-live) token in the revocation set after cleanup
- evicts a revocation entry only after its TTL elapses (token already expired)
- adversarial: with a long TTL a high-churn set is NOT pruned below the live count
- default TTL (no env) is derived from accessTokenExpiry and outlives a fresh token
- revoking the same token twice keeps a single entry (Map de-dupes by tokenId)
