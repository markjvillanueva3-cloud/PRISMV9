# Quoting outbound price prior — OutboundPriceIndexEngine

`QUOTING-SYNERGY-MS0/U-QP-OUTBOUND-PRICE-PRIOR` (slot:charlie, 2026-06-01, commit `6efc2749bb`). The **outbound / calibration-TARGET** half of the quoting data ceiling — symmetric sibling of [[quoting-cost-basis-wire]] (the inbound cost half).

## Before
`state/shared/quoting/jm-sold-orders.json` — 12,761 customer POs to J.M. Die mined by `VENDOR-NETWORK-MS0/U-VDN-JM-ORDERS` (what JM **charged**; 240 verified line-items, $47,142.12 confirmed ext-revenue; OCR-noisy) — was **built but UNWIRED**. Zero engine consumers. The prior iter59 attempt to overlay outbound revenue onto the training corpus got `match_pct=0` because it tried to **join** orders to synthetic baseline records by a key that does not exist (po_number mostly null; quote_ref is OCR garbage like "Date"/"Lead"/"OMG"). See [[reference_charlie_quoting_data_ceiling]].

## After
`OutboundPriceIndexEngine` (`mcp-server/src/engines/OutboundPriceIndexEngine.ts`) loads the index (cached, fail-soft, cwd+module walk-up resolution) and exposes the **empirical distribution of real per-piece outbound prices**, confidence-gated:
- `pricePrior({minConfidence})` → `{unitPrice:Distribution, orderTotal:Distribution, includedOrders, recordsAvailable, ordersProcessed, advisoryOnly, caveat, byConfidence, confirmedExtRevenue}`
- `sanityBand({minConfidence})` → `{p5, median, p95, n}` for quote-outlier flagging
- `getTotals()` — header counts (ordersProcessed / verified / confirmed revenue / byConfidence)

`Distribution = {n, min, p5, p10, p25, median, p75, p90, p95, max, mean}` (linear-interpolated quantiles).

Wired as **`prism_quoting:outbound_price_prior`** (enum + schema + lazy-import switch). NO inline price constants — every number is computed from the AP-mined file.

## Why a distribution, not a join (the training value)
A **distribution prior sidesteps the join entirely**: calibrate the model's OUTPUT price distribution against JM's REAL sold-price distribution (quantile anchoring / distribution match) instead of against the synthetic bootstrap that drove the iter59 `factor 0.5845 / MAPE 71.1%` self-consistency. This is the real-data lever the training loop was missing.

## Units — this side is CLEAN (contrast with the cost-basis wire)
Each sold-order line-item is `qty × unit_price = ext_price`, so `unit_price` is a genuine per-PIECE outbound price (spot-verified — holds for most high-confidence rows, OCR drift on a minority). Unlike the AP cost-ledger (which blends $/bar, $/foot, $/piece — the [[quoting-cost-basis-wire]] units caveat), the sold-order unit_price is unit-homogeneous. The cross-part spread is still wide ($1–$575/piece), so a single median is **a sanity band + aggregate calibration target, NOT a per-part quote price**.

## Confidence gating (load-bearing safety)
Source tags every order `high/medium/low/none` and carries its own rule *"Never feed low-confidence prices into a live quote."* The engine defaults to `{high, medium}` and **NEVER** includes low/none by default. `minConfidence:"high"` is the cleanest verified-only subset (all 40 high-confidence orders are persisted in full).

## Header-vs-persisted honesty (R12 — scrutiny P1 fix)
The mined file persists a **curated ~500-record top-value subset** (all high-confidence orders + essentially all $47K verified revenue) while its **header** reports the full-corpus `ordersProcessed:12761` / `byConfidence` totals. The result surfaces `recordsAvailable` (persisted — what the distribution is built from) DISTINCT from `ordersProcessed` (header), plus the file's `advisoryOnly`/`caveat` self-flags, so a consumer can never mistake the partial-sample distribution for full-corpus ground truth.

## Boundary
READ-ONLY analysis — a price-distribution prior, NOT a quote emitter. It does not apply the customer-quote margin-floor gate; a downstream emitter that consumes this prior MUST still apply that gate (soul refusal `emitting-customer-quote-without-margin-floor-gate`).

## Calibration diagnostic — `compareToPredicted` (U-QP-OUTBOUND-PRICE-CALIB, commit `cd3f38be0a`)
The loop-closing read-only diagnostic: `outboundPriceIndexEngine.compareToPredicted(predicted[], {minConfidence, alignTolerance})` compares the quoting model's predicted per-piece prices to the real outbound distribution → `{medianRatio, withinBandPct, ksGap, verdict}`. Answers *"does our training output match what JM actually charges?"* WITHOUT the per-part join the iter59 overlay needed (it got `match_pct=0`). Wired **`prism_quoting:outbound_price_calibration`**.

- `medianRatio` = predicted.median / reference.median · `withinBandPct` = fraction in reference [p5,p95] · `ksGap` = two-sample Kolmogorov–Smirnov statistic (0=identical, 1=disjoint).
- ADVISORY — never a quote, never a calibration factor (a downstream consumer must still apply its own margin-floor gate). `verdict` is **median-anchored** (medianRatio vs an overridable dimensionless `alignTolerance`, default 0.15 — NOT a margin / reconciliation threshold); `ksGap`/`withinBandPct` are the shape/coverage companions — don't read `verdict` alone for full distribution match.
- 29 tests (exact KS 0/1, medianRatio, band, alignTolerance widening, drift-guard `reference === pricePrior().unitPrice`, dispatcher round-trip). 2-reviewer per-file scrutiny PASS (P2 median-anchored-verdict clarity fixed in-JSDoc, in-unit). See [[reference_charlie_outbound_price_calib_2026_06_01]].

## Shipped — docustrata quote-execution variance (U-QP-DOCUSTRATA-VARIANCE, commit `87c40bdba6`)
Consumes the **Docustrata invoice document** — the units-safest of the 3 unconsumed sources the coverage report named. Two pure functions in `QuotingTrainingLoopEngine.ts` (9 tests, `QuotingDocustrataVariance.test.ts`): `docustrataIsPlaceholder(doc)` is the **freshness preflight** (soul: `training-on-stale-bootstrap-distribution-without-freshness-preflight`) — regex `/bootstrap|manual-curation|placeholder/` on `source`+`note`, **null→placeholder** (safe, never silently consumed as real); `assessQuoteExecutionVariance(doc, {bandPct=5, topN=10})` computes `variance_pct = (actual_invoice_usd − predicted_quote_usd)/predicted_quote_usd × 100`, a **quote-execution-accuracy** metric DISTINCT from the FMV under-quote (`assessUnderQuotes`). The separation is enforced at the TYPE level — `assessQuoteExecutionVariance(doc: DocustrataDoc)` vs `assessUnderQuotes(records: PerRecordPrediction[])` are different input types, so the two grains cannot be cross-fed by accident. **Units-clean**: like-over-like ratio at the same per-invoice-line grain; `quantity` intentionally NOT applied (both $ already extended per-line — JSDoc-pinned to prevent a future re-multiply units bug). Classification axes are orthogonal and overlap by design: above/below = SIGN of variance, within-band = MAGNITUDE (`|var|≤band`) — a +2% line is both above-quote AND within-band (the iter-14 test bug was asserting these mutually exclusive; fixed the test per R12, code was correct). Placeholder source → `advisory:true` + caveat "MUST NOT feed [the live calibration factor]"; no factor mutation. Defensive: `quote<=0` skip, non-finite skip, empty/null→ok:false. **R13 split (both reviewers PASS):** the engine capability ships now; the train-cycle wire (`assessQuoteExecutionVariance` into `quoting-train-cycle.mjs --json` + flipping docustrata `consumed` in `QUOTING_DATA_SOURCES`) is DEFERRED to **U-QP-DOCUSTRATA-TRAIN-WIRE** — wiring placeholder data into the live cycle now would violate the freshness-preflight soul invariant.
