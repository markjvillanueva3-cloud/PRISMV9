# Dormant-Engine Activation Roadmap — DEA-MS0

Generated by `/goal` (R7, slot november, 2026-05-22) — the actionable follow-through
on the session's 5-spec math-research arc, whose headline finding (F0) was that
PRISM's precision-engine cluster is dormant.

**Primary slot: `november`** — owns DEA-MS0: re-runs the generator, tracks progress,
closes the milestone.

## What it is

A pickable roadmap that turns the raw unwired-engine audit into ~118 activation units
split across all **25 work slots** (the full alpha..zulu NATO fleet, golf excluded as
hygiene). Re-run the generator after `audit-unwired-engines.mjs` and counts will
auto-refresh.

| Track | Source | Units |
|-------|--------|-------|
| Type A — unwired | 616 engines on disk with zero dispatcher reference | `wire` / `wire+triage` / `triage+wire` units |
| Type B — precision cluster | ~22 actions wired-but-uncalled engine-to-engine (F0, MACHINING-MATH-INVENTIONS-AUDIT) | 6 `activate` cross-wire units (all on `november`) |
| Trilobe / eccentric | 4 unwired engines + macro G-code codegen (user addition) | 1 `wire+codegen` unit on `bravo` |

Unit type taxonomy (honest naming):
- **`wire`** — every engine in the batch has a known `suggestedDispatcher`; same dispatcher → `Wire N → prism_X`, mixed → `(mixed dispatchers — see per-engine target)`.
- **`triage+wire`** — every engine has `suggestedDispatcher: UNKNOWN`; dispatcher must be reviewed before wiring.
- **`wire+triage`** — mixed UNKNOWN + known; review UNKNOWN entries first, then wire.

Every unit lists each engine with its **per-engine target dispatcher** in the MD, so
even a spilled cross-domain engine tells the wirer where it actually goes.

## Per-slot split

Balanced assignment: each engine prefers its domain slot up to `TARGET = ceil(N/25)`
(currently 25); overflow spills to the lightest slot. This gives an even ~24-29
engine load on every slot, with `november` running heavier (48) because it carries
the 6 precision activations on top. Big domains (lathe 57, wedm 57, cam 54, mike's
ai+orchestrate 73) spill cleanly to overflow slots whose tribal-domain matches
(papa/uniform/zulu = lathe-tribal, quebec/victor = wedm-tribal,
sierra/xray = cam-tribal, oscar/tango/yankee = mill-tribal,
romeo/whiskey = cad-tribal).

The 13 domain slots (alpha=mill, bravo=lathe, charlie=wire-EDM, delta=cad, echo=cam,
foxtrot=tribal, hotel=erp, india=post, juliett=speed-feed, kilo=print-to-program,
lima=academy, mike=misc, november=precision) keep their JULIETT-12CHAT-ALLOCATION
identity; the 12 overflow slots (oscar..zulu) take cross-domain spill + UNKNOWN
triage.

## Trilobe / eccentric turning

Four unwired engines — `EccentricTurningEngine`, `TrilobeDeformationEngine`,
`ColdHeadingToolConfiguratorEngine`, `ExpandingMandrelEngine` — are carved into a
named `bravo` unit (`U-DEA-bravo-TRILOBE`). The unit is `wire+codegen`: it wires
the engines into `prism_turning` **and** generates macro-based G-code — X-axis
modulation X(C) as a parametric profile for the trilobe lobes, the eccentric-offset
transform, and polygon-turning G51.2 live-tool synchronization. Math link:
trilobe profile = parametric/trochoidal curve; eccentric = offset kinematics.

## Wiki + tribal injection

Every unit carries `domain`, `tribal` (the `tribal-by-domain-inject` key), and
`wikiKw` fields. At pickup the existing injectors — `tribal-by-domain-inject`,
`wiki-precheck-inject`, `master-index-precheck-inject` — light up on those keys, so
wiki + tribal context surfaces per unit without 120 hand-written lookups. Each
slot section in the roadmap doc also prints a visible anchor block.
