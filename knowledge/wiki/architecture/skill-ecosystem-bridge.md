## Question

PRISM has 698 slash-commands (302 local + 396 user). How are they discovered, auto-triggered, kept fresh, and archived — and what's the ecosystem gap?

## Answer (canonical — skills are the 3rd automation surface; engine-wiring + hook-ecosystem + skill-ecosystem form the trilogy)

### The 3 automation surfaces

PRISM automates through three distinct surfaces — each with its own wiring discipline:

| Surface | Count | Wiring mechanism | Bridge entry |
|---|---|---|---|
| **Engines** | 3,314 | dispatcher action enum + schema + case | [[wiring-pattern-engine-to-dispatcher]] |
| **Hooks** | 699 | settings.json event chains | [[hook-ecosystem-wiring-bridge]] |
| **Skills** (slash-commands) | 698 | `.claude/commands/` files + auto-trigger ledger | this entry |

The three are complementary: engines do compute, hooks fire on events, skills are operator-invoked workflows. A healthy PRISM needs all three surfaces wired + discoverable.

### How skills are discovered + invoked

1. **Explicit invocation** — operator types `/<skill-name>`; the Skill tool loads `.claude/commands/<name>.md`.
2. **Auto-trigger suggestion** — `skill-auto-trigger.mjs` (UserPromptSubmit hook) reads `knowledge/wiki/architecture/_skill-triggers.jsonl` and surfaces top-K skill suggestions matching the prompt's keywords. Suggestions, not auto-runs.
3. **SessionStart injection** — the ~440-skill catalog is injected at SessionStart so the model knows what exists.

### The auto-trigger ledger — a known fragility

`_skill-triggers.jsonl` maps skill → trigger-keywords. It's regenerated by `scripts/extract-skill-triggers.mjs`. The 2026-05-20 regression ([[reference_skill_trigger_ledger_revive_2026_05_20]]) is instructive: the ledger was **0 lines** — `skill-auto-trigger` was 100 % blind fleet-wide — because a fingerprint cache locked an empty file in from 2026-05-19. The fix regenerated 0 → 482 rows / 122 skills + added `skill-trigger-ledger-health.test.mjs` (fails loud on `fingerprint ∧ empty`).

**The lesson, generalized:** a regeneration script + a fingerprint cache is a fragile pair. If the fingerprint matches but the output is empty, the cache serves stale-empty forever. Every regen-with-fingerprint needs a fail-loud "fingerprint valid BUT output empty → regenerate anyway" guard. This pattern recurs (see [[reference_wiki_leafidx_failloud_2026_05_18]] — same class).

### Skill ecosystem gaps (parallel to the hook ecosystem)

| Gap class | Symptom | Fix |
|---|---|---|
| **Untriggered** | Skill exists but has no entry in `_skill-triggers.jsonl` — never auto-suggested | Add trigger keywords; regen the ledger |
| **Archived-but-needed** | Skill moved to `.claude/commands-archive/` (HS-06 archival) but still referenced | Restore via `mv` OR update the references to the archived state |
| **Frontmatter-invalid** | Skill `.md` lacks valid frontmatter — fails `command-frontmatter.schema.json` (baseline 33/167 valid per U-CK06) | Populate frontmatter (`composes_with`, `consumes`, description) |
| **Duplicate/superseded** | Two skills do the same job (forge / forge2 / forge3 / ... / forge7) | Keep the latest; archive the rest with a pointer |
| **Orphan workflow** | Skill invokes an engine/dispatcher that no longer exists | Re-point or archive |

### The frontmatter discipline

Per CLAUDE.md §KNOWLEDGE VAULT, command frontmatter is validated by `.claude/schemas/command-frontmatter.schema.json`. The baseline was 33/167 valid (U-CK06); U-CK15 populated 342 `composes_with` + 108 `consumes` across 36 commands. Frontmatter matters because:
- `composes_with` lets skills chain (the `/pick-build-close` macro composes `/pick-unit` → research → build → `/close-out-audit` → `/handoff`).
- `consumes` declares the engines/dispatchers a skill needs — enables impact analysis when an engine is renamed.
- The `description` is the auto-trigger match signature.

A skill with no frontmatter is invisible to composition + impact-analysis + auto-trigger. Closing the 134/167 frontmatter gap is real ecosystem health work.

### The archive discipline (HS-06)

Per [[feedback_never_delete_only_disable]], superseded skills are archived, not deleted: `.claude/commands-archive/<path>`. The archived skill stays restorable via `mv`. The SessionStart injection surfaces archived skills as "may be relevant" hints with the restore command. This keeps the active `.claude/commands/` lean (faster skill-load) without losing capability.

The `forge` family (forge / forge2 / .../ forge7) is the canonical example: forge7 is current; forge-forge6 are kept for history but forge7 is what auto-triggers. The version-suffix pattern signals "same skill, evolved."

### Per-slot skill wrappers (the 78-wrapper pattern)

CLAUDE.md §PER-SLOT WRAPPERS: 78 wrappers = `/{precompact,handoff,startup}-<slot>` × 26 NATO slots. Generated by `scripts/generate-per-slot-wrappers.mjs` (idempotent). Each wrapper is ~30 lines, force-takes the slot, binds the topic, delegates to the canonical pipeline. After any SLOT_NAMES expansion, re-run the generator. This is the skill-ecosystem's answer to "how do 26 chats each get slot-bound startup/handoff without 78 hand-maintained files" — generate from one template.

### Operator picks

| Priority | Action | Why |
|---|---|---|
| **P0** | Verify `_skill-triggers.jsonl` is non-empty + fresh (the 2026-05-20 regression class) | A blind auto-trigger = the whole skill-discovery layer dead |
| **P1** | Close the frontmatter gap (134/167 invalid → valid) | Unblocks composition + impact-analysis + auto-trigger |
| **P1** | Audit duplicate skill families (forge*, rgs*, checkin*) — confirm only the latest auto-triggers | Reduces operator confusion + skill-load weight |
