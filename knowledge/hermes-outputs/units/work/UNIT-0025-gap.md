## Recommended action
Do NOT build fresh `ReconditioningEconomicsEngine` / `CrossMachineTranslator` engines from the ground up — that would duplicate `ToolLifeEconomicReplacementFormula` + `ReconditioningQualityEngine` + `ToolROIEngine` (economics) and `MachineCapabilitySurfaceEngine` + `PPDialectTransferEngine` + `PPControllerCompatibilityEngine` + `MaterialEquivalenceEngine` (cross-machine), all of which are real, tested, and wired (R8/dedup violation). The genuine net-new-code gap is a **thin composition/bridge layer**, not new physics:
1. **Quoting integration (the sharpest, cleanest gap):** add a `prism_quoting` action that calls `reconditioningQualityEngine.assess()` → `ToolLifeEconomicReplacementFormula.economicLife()` and folds the resulting recondition-vs-replace $/part delta into a quote line item, alongside the existing `tool_cost_basis` action (`quotingDispatcher.ts:130`). This is the one acceptance-criterion line ("integrated with quoting") with zero existing wiring.
2. **Cross-machine composition:** one read-only orchestration action (on `prism_calc`, satisfying the "wired to calc" line, or `prism_cad` alongside its sibling `cad_machine_capability_*` actions) that sequences `MachineCapabilitySurfaceEngine.compareCapabilities()` + `PPControllerCompatibilityEngine` + `PPDialectTransferEngine` + `MaterialEquivalenceEngine` for a "translate this job from machine A to machine B" query — composition, not new modeling.
3. **Multi-lingual:** flag as [SCOPED]/deferred unless the operator names a concrete consumer (e.g., Polish/Spanish reconditioning-recommendation strings) — `LocalizationBundleEngine` is ready to receive a locale bundle once one is authored; do not build new i18n infrastructure.
4. **JM Die validation:** data-blocked exactly as UNIT-0010-gap.md already found — no reconditioning-outcome dataset exists in-repo (`jm-tool-purchases.json` is purchases, not regrind history). Flag [UNVERIFIED]/data-blocked per R12; do not fabricate a validation pass.
