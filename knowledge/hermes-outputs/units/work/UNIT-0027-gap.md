## Recommended action
Do NOT build a new `MicroNanoEngine` — four size-effect implementations plus a diamond-turning nano engine already exist and building a fifth would be a duplication-guard violation (R8/dedup). The genuine, ROI-positive work is:
1. **Fix the two broken dispatcher wires** (wire-only, small, high-value, and required for the acceptance criterion "Wired to prism_calc" to be TRUTHFULLY satisfied, not just nominally present per R12): rewrite `micro_milling_analyze` to pass `(tool, conditions)` per the real `MicroMillingEngine.analyze` signature, and rewrite `micro_milling_size_effect_calc` to call the real static method `MicroMillingSizeEffectEngine.calculateSizeEffect(tool, cut, material)` instead of the nonexistent `.calculate/.analyze/.run`. Add a dispatcher-level round-trip test for both (the current test suite never exercises them).
2. **Wire the orphaned `microDrill()`** as `micro_drill_calc` (method exists, fully unwired).
3. **The one genuinely-missing capability**: no engine bridges micro-tool process-physics (h_min, edge radius, aspect-ratio deflection limits already computed by the four existing engines) into a single queryable "smallest producible feature" prediction (min hole ⌀, min slot width, min internal corner radius) at micro/nano scale — this is distinct from both minimum-CHIP-thickness (process input, already covered 4x) and the macro-scale `ThinFloorVibrationEngine`/`DfMRulesEngine` fillet rule. This is a narrow, additive extension, not a new physics engine.
4. **Lower priority but real**: consolidate the four disjoint local constant sets (`MIN_CHIP_THICKNESS_FACTOR`, `LAMBDA_MIN_CHIP`, `MICRO_MILL_SPEEDS`/`KC1`, `DiamondTurningEngine.MATERIALS.kc_ref`) into a canonical micro/nano section of `mcp-server/src/physics/constants.ts` so the four engines stop disagreeing silently (`SIZE_EFFECT_EXPONENT` is `-0.25` in one engine, `+0.25` in another, on differing formula conventions with no cross-check).
5. **Add JM Die precision-parts validation** — currently absent entirely; the acceptance criterion is unmet by any test in the repo.
