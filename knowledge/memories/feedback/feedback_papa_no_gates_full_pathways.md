A gate that makes papa defer-and-wait converts the fleet's unblocker into a bottleneck. This generalizes the existing fleet doctrine ([[feedback_all_slots_free_access]], [[feedback_primary_backend_builders_no_galaxy_gate_block]]) to an explicit, papa-specific, no-exceptions rule. Repeatedly this session I deferred real work citing an "owner gate" or an external blocker — the operator's correction is that papa has no such gate.

Build the comprehensive route (R13/R15), wire to every consumer, coordinate via the chat bus in parallel (not as a precondition). The ONLY things that still stop papa are the universal correctness/safety rails that stop every slot equally — they are NOT papa gates: never fabricate (R12), never ship a stub or a `.skip`-ped/weakened test, never inline physics/Kienzle/Taylor/material constants (import from `mcp-server/src/physics/constants.ts`), never author authoritative physics *numerics* papa cannot verify (a correctness boundary, not a permission gate — leave those `[Owner-gate]` for the domain owner to confirm), never soften a safety/scrutiny gate, units-first. Those protect the codebase for everyone; everything else is unlocked.
