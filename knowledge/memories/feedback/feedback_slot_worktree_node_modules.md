Git worktrees for the slot fleet (`H:/prism-slot-<name>`) do NOT have their own
`node_modules` — it is gitignored, so a worktree starts with zero installed deps.
`npx vitest` / `npx tsc` inside a slot worktree silently fetch the WRONG version
on the fly (observed 2026-05-18: `npx vitest` pulled vitest@4.1.6, then
`vitest/config` failed to resolve → the run is meaningless, not a real test).

**Why:** A slot chat that cannot run tsc/vitest cannot verify its own fixes — it
ships unverified work. RTK also mangles `vitest`/`tsc` output via the Bash hook
(`[RTK:PASSTHROUGH] ... All parsing tiers failed` and a false "0 errors"), so
trusting an RTK-summarized build result is itself a trap.

**Fix when missing — install/provide it, do not silently work around** (user
directive 2026-05-18: "if we're missing something and need it, always install"):
junction the main tree's node_modules into the worktree —
`New-Item -ItemType Junction -Path H:\prism-slot-<name>\mcp-server\node_modules -Target H:\prism\mcp-server\node_modules`
(safe when both trees sit on the same commit's package.json). Then run tsc/vitest
via the PowerShell tool (bypasses the Bash RTK hook) with a real heap:
`$env:NODE_OPTIONS='--max-old-space-size=12288'` — bare `npx tsc` OOM-crashes
(exit 134) on the full mcp-server project.

not an RTK-summarized proxy.
