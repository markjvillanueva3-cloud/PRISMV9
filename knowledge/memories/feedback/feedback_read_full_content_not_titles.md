**Rule (operator directive 2026-06-11, FLEET-WIDE — all slots/galaxies):** Actually READ everything — not just titles, filenames, summaries, commit messages, digest lines, or that-it-exists. Something existing does NOT mean it is complete or correct.

**Why:** A file / engine / section / memory / wiki-entry / soul can exist with a done-sounding title or a fresh timestamp while its body is a stub, stale, wrong, partial, or auto-generated-and-untouched. Trusting the title/existence is the same shallow-search failure as claiming absence after one grep — applied to *completeness + correctness* instead of presence. (This session: nearly treated `SOUL.md` as "already updated" because the file existed with a 03:04 timestamp; only reading the body revealed it was auto-generated from a SOURCE that needed updating instead. Also nearly trusted digest "title" lines as real backlog when many were scrutiny-chatter.)

**How to apply:** Before relying on / citing / building a consumer on / marking done / reporting any asset to the operator — open it and read the ACTUAL content end-to-end (or the relevant span via offset/limit on huge files). Verify the body matches the title/claim. "It exists" / "the digest lists it" / "the title says X" / "the commit message says shipped" is never proof it works or is finished. Pairs with [[feedback_never_claim_absence_without_deep_search]] + the global CLAUDE.md HONESTY RULES "Verify a symbol before claiming it exists" bullet + R8 (read before you write) + R12 (fail loud).
