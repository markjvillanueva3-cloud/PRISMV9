**Incident (2026-06-13/14, slot golf, session 02a2de10).** Operator reported an "api server error" + asked to fix "hooks / auto firing mechanisms / oom / git".

## Root cause (observed LIVE, not theorized)
The PRISM hook stack -- **65 UserPromptSubmit + 76 Stop + ~96 per-tool PreToolUse/PostToolUse hooks**, x up to 13 live `claude.exe` chats -- detonated a cascading **bash.exe fork-storm**: a single Stop-hook snapshot caught **927 bash.exe under one claude.exe (pid 54724)** in deep bash->bash->bash chains. That storm **starved the shared MCP server on :3100** ("singleton daemon wedged / SERVER DISCONNECTED timeout") == the operator's "api server error". A 4-agent audit Workflow I launched was itself a contributor (each agent's every tool call fires the ~96-hook PreToolUse stack). The storm **self-drains** in seconds once new spawns stop (927 -> 203 -> 113 observed); :3100 rebinds via its supervisor. RAM was NEVER the problem (35%, 80GB+ free) -- it was process-count starvation, not OOM. The 2.9GB node = `tsserver.js` (editor, never reap); MCP server itself = healthy 743MB.

## Fix shipped (commit `1a059aa7b7`, [MAIN] on cad-fusion-live-ms0)
1. **`.claude/hooks/fork-storm-circuit-breaker.mjs`** (T0 PreToolUse, matcher `Bash|Agent|Task|Workflow`, wired as PreToolUse[1] -- fires early). Hard-**blocks** a spawning tool when live `bash.exe >= PRISM_FORKSTORM_CEILING` (default **400**; Workflow trips early at 0.7x = 280). Count via `tasklist` (absolute `%SystemRoot%\System32\tasklist.exe` -- a bash-spawned PATH lacks System32 and would make a bare `tasklist` throw -> -1 -> silently never fire), **TTL-cached 2500ms** (a burst pays the enumeration once). **FAIL-OPEN everywhere** (unknown count/-1/bad payload -> allow). 12/12 unit tests (`fork-storm-circuit-breaker.test.mjs`). Knobs: `PRISM_FORKSTORM_BREAKER_DISABLE=1`, `PRISM_FORKSTORM_CEILING=N`, `PRISM_FORKSTORM_TTL_MS`, `PRISM_FORKSTORM_WORKFLOW_FACTOR`, one-shot `[SCOPED]`/`--force-spawn`/`PRISM_FORKSTORM_FORCE=1`. **VALIDATED LIVE** -- it blocked a real Bash at `431 >= 400` mid-storm (better than the synthetic test).
2. **`PRISM_AGENT_FANOUT_GATE: undefined -> strict`** in `~/.claude/settings.json` (was defaulting advisory) -- the sibling `agent-fanout-pressure-gate.mjs` now BLOCKS Agent/Workflow bursts (the "4 sonnet agents in 60s" 429 pattern) instead of advising. Settings.json is EXTERNAL config (C:/Users/wompu/.claude/ + H:/.claude/ mirror), NOT a repo file -- edit C: then it mirrors; a node-script write bypasses the c->h mirror hook so cp C->H manually.

The breaker covers the arm the fanout-gate misses: the fanout-gate sees per-session Agent BURSTS, the breaker sees the SYSTEM-WIDE bash explosion from the hook-per-tool-call cascade across the whole fleet.

## UNRESOLVED -- git object corruption (needs a controlled window, do NOT hack live)
`H:/prism/.git` = **48GB = 45.08 GiB of loose objects** (383K loose; real packed history is only **861 MiB** -- so a healthy gc would shrink it to ~1-2GB). But **`git gc` FAILS on object-store corruption**: removed one empty/truncated blob (`.git/objects/87/5d61482ac89327d3845a5c0737433b6b5659b7`, 0 bytes -- killed mid-write by the fork-storm) but gc still dies on a **second missing object** (`bad tree object e36809bbd238e2894fff1e89620be0846c9a1923`). **Multiple corrupt objects** => gc cannot pack => **the 45GB is NOT reclaimed**. The 31,630 uncommitted files are REAL knowledge/wiki/memory leaves (do NOT gitignore them).

**Refined diagnosis (read-only, 2026-06-14):** all **59 worktree indexes are DIRC-valid** (the 2026-06-12 zeroed-index class did NOT recur -- [[reference_golf_git_tree_maintenance_2026_06_12]]). The blocker is a **MISSING TREE object `e36809bb`** (a subtree under tree `2c64ca38`) **reachable from main's history**: `git rev-list --objects cad-fusion-live-ms0` = REACHES-CORRUPTION; refs/heads(114) + refs/tags(49) REACH it, but **refs/remotes(39) are CLEAN** -- so the corrupt commit is among the **3,755 LOCAL-ONLY unpushed commits** (origin never got it; re-clone would lose those 3,755 but NOT reintroduce the corruption). The COMMIT chain is intact (`rev-list` WITHOUT `--objects` passes -- that's why an earlier per-ref commit-only scan falsely read "clean"); only a TREE (a historical directory snapshot) lost its object when git was killed mid-write by the storm. **Working-tree files are all present on disk** -- only the in-history snapshot object is gone. `prune` won't help (reachable, not dangling garbage). Recovery is OPERATOR-DECISION + QUIET-WINDOW: either (a) locate `e36809bb` on another machine/backup/clone and `git hash-object -w` it back, or (b) authorized history repair (rewrites SHAs -> breaks all 13 chats' main-based branches -> must coordinate the whole fleet). The 45GB stays un-reclaimed until then; git OTHERWISE WORKS for new COMMITS (the breaker commit `1a059aa7b7` landed fine -- HEAD's tree is intact; only `gc`/`push`/`rev-list --objects` that walk ALL history hit the missing object). The breaker now prevents NEW such corruption (no more git killed mid-write by a storm).

**IMPORTANT (2026-06-14): `git push` IS blocked too** -- a dry-run `git push --dry-run` FALSELY succeeds (it doesn't fully pack objects), but the REAL `git push origin cad-fusion-live-ms0` dies with `fatal: bad tree object e36809bb` + `remote end hung up` and transfers NOTHING (still 3,770 ahead). So push AND gc are both blocked by the same lost object; the 3,770 commits are NOT auto-backupable by a normal push.

**Operator decision (2026-06-14): SNAPSHOT-NOW + REPAIR-LATER.**
- **Snapshot backup (DONE this session):** branch `backup/golf-snapshot-2026-06-14` = a single flat commit of **HEAD's tree** (`git commit-tree $(git rev-parse HEAD^{tree}) -p origin/cad-fusion-live-ms0`), pushed to GitHub. It BYPASSES the corruption (HEAD's tree is clean; no `git add` so the golf-slot lane-guard doesn't block it) and gives off-machine data safety of the committed state NOW. It is a flat snapshot, NOT granular history. The 13k uncommitted files (other chats' live WIP) are intentionally excluded -- their chats commit them.
- **Full repair (QUEUED for a coordinated quiet window -- NOT done live):** (1) pause/quiesce all ~13 chats; (2) find the corrupt commit: `git rev-list cad-fusion-live-ms0 | while read c; do git ls-tree -r $c >/dev/null 2>&1 || { echo $c; break; }; done` (it's OLDER than the recent 120; the corrupt subtree is `e36809bb` under tree `2c64ca38`); (3) recover `e36809bb` if it exists on any backup/clone (it appears LOST -- local-only, killed mid-write, not on origin), ELSE rewrite history past it (`git filter-repo` / `git rebase --onto` to drop/replace the corrupt commit) -- this REWRITES commit SHAs from the corrupt commit forward -> **force-push + every chat hard-resets/re-clones**; (4) then `git gc` reclaims ~45GB. Because step 3 rewrites shared history, it MUST be operator-coordinated, never live. Lane-guard kill switch (`PRISM_GIT_ADD_LANE_DISABLE=1`) must be set in the HOOK env, not inline in the bash command (inline does NOT reach the PreToolUse hook).
