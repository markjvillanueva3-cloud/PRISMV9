**Regression caught by end-to-end verification (2026-06-01, slot:alpha). A multi-session-old patch premise was FALSE.**

> **✅ FIXED (same session, commit `8998f53693`, U-TRIBAL-SLOT-DOMAIN-WIRE):** the correct architectural fix shipped — `activeSlotName(chatId)` in `wiki-domain-bias.mjs` + exported `SLOT_TRIBAL_DOMAIN` (23 slots → nearest VALID rerank domain) consulted FIRST in the tribal hook's `main()`, heuristic fallback for unmapped slots, `getDomainTokens` untouched. Resolves the slot-token hijack at the resolution layer (NOT a DOMAIN_MAP band-aid). E2E: foxtrot→mill (was backend-dev). 80 tests incl. a `SLOT_TRIBAL_DOMAIN`-validity guard. (Ollama-down means tips don't physically inject until recovery — orthogonal, fleet-wide.)

The standing patch-sibling `HOOK-PATCH-TRIBAL-DOMAIN-MAP-EXPAND.md` claimed: adding `speed-feed`/`database`/`business` to `tribal-by-domain-inject.mjs` `DOMAIN_MAP` is a "pure wiring gap, zero content authoring" that unlocks tribal injection for oscar/juliett/hotel (citing "182 / 12,497 / 1,569 tips in the index"). Operator authorized applying it. I applied it (authorized cross-worktree bypass), VERIFIED through the real rerank seam, found it **regresses** those slots, and **reverted**.

**Two false assumptions:**
1. **"Rich corpus" was a keyword-SUBSTRING miscount.** Live `tribal-embed-index.json` (33,044 entries) `domain` field values: `general 18924 · cam 5346 · mill 3138 · cad 3133 · lathe 1077 · engine-reference 575 · wedm 526 · backend-dev 325`. **ZERO** `speed-feed`/`database`/`business`. The "182/12497/1569" counted prompts/text MENTIONING those words, not `domain`-tagged entries. (Prior-session reviewer B had already hinted: "speed-feed is not a domain-field value in the index.")
2. **`tribal-rerank.mjs` fails loud on unknown `--domain`.** `VALID_DOMAINS = {mill,lathe,wedm,cad,cam,backend-dev,general}` (line ~131) → any other value `process.exit`s with "unknown domain". The hook resolves the slot domain via DOMAIN_MAP then calls `runRerank(prompt, domain)` → `--domain speed-feed` → rerank exits non-zero → `runRerank` catches `{ok:false}` → hook injects NOTHING. Strictly worse than today (no DOMAIN_MAP match → `general` → real general tips).

**Net:** the "fix" would flip oscar/juliett/hotel from "general tips" to "zero tips." A one-line hook edit that LOOKS like wiring is actually a 3-component build: (1) tag corpus entries `domain:"<new>"` [binding constraint; business/database likely have NO manufacturing-tribal corpus → general is honest], (2) extend `tribal-rerank.mjs VALID_DOMAINS`, (3) THEN DOMAIN_MAP. Interim: map to nearest EXISTING valid domain (juliett→backend-dev, oscar→mill/cam, hotel→general) — domain-owner's call.

**DEEPER FINDING (3rd verification round) — the actual current behavior is a SLOT-TOKEN HIJACK, not a "general" fallback.** `domain = inferTribalDomain(getDomainTokens({chatId}))`. `getDomainTokens` tokenizes the slot's `topic` + `branch` (NOT the prompt) + the SHARED `CURRENT_POSITION.md` title. Live `chat-slots.json`: oscar/juliett/hotel/foxtrot have `topic: undefined`, `branch: "slot/<name>"`. `tokenize("slot/oscar")` → `["slot","oscar"]`, and **`"slot"` IS a token in the `backend-dev` match set** (line 97, intentionally — "harness/runtime infra"). So EVERY topicless slot-worktree chat routes to **backend-dev** (incl. foxtrot=mill!), getting backend-dev tips regardless of its real domain. This is the [[reference_foxtrot_tribal_slot_fallback_gap_2026_05_28]] class, confirmed live.

**Why NO DOMAIN_MAP token edit is a safe fix (all 3 variants have a hazard):** (1) new domains → rerank fail-loud + no corpus; (2) domain-vocab tokens (`feed`/`sfm`/`chipload`) → STEAL peer cutting slots (lathe/wedm also do feeds/speeds) via first-match; (3) slot-NAME tokens (`oscar`→mill) → `CURRENT_POSITION.md` is read for ALL slots, so a slot-name appearing in its shared title pollutes the whole fleet's routing + many NATO names are common words.

**Correct fix (architectural, multi-component, hook+domain-owner-owned, fleet-regression-tested):** rework `getDomainTokens` (`.claude/helpers/wiki-domain-bias.mjs`) to derive the domain from the slot's AUTHORITATIVE galaxy — the system already maps oscar→speed-feed, juliett→database, hotel→business via the slot-context-bundle / `CHAT-SLOT-DOMAINS.md` — then map galaxy→nearest-valid-rerank-domain (speed-feed→mill/cam, database→backend-dev, business→general until a corpus exists). PLUS build domain-tagged corpora for the gap domains (or accept nearest-domain) + extend `tribal-rerank.mjs VALID_DOMAINS` only if genuinely new domains land. Do NOT touch the fleet hook with a token band-aid under loop pressure — it risks regressing the 8 already-working slots.

**LESSON (reusable):** "the corpus exists" by keyword-substring ≠ "the corpus is domain-tagged AND the consumer accepts that domain." And "no dedicated domain" ≠ "no routing" — verify the ACTUAL token→domain resolution against live slot state, not the assumed path. Before declaring a wiring gap, trace the FULL chain: slot token source (topic/branch/shared-position) → DOMAIN_MAP first-match → rerank accepted-value set (fail-loud?) → corpus domain tags → inject seam.
