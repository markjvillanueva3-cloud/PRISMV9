# Dispatcher duplicate-case audit (slot:alpha 2026-06-22, surfaced by `npm run build`)

The authoritative build emits **10 `duplicate-case` warnings** across 4 dispatchers. In a JS switch the FIRST `case "X"` wins, so the LATER one is DEAD — meaning the action runs the EARLIER handler and the later block never executes. This is the dispatcher-false-wire / dead-duplicate-case class (sibling of the xproc fall-through regression). **NOT edited autonomously by alpha** — resolution is owner-gated (which handler is canonical is a per-domain contract decision), and the files are peer-owned + some actively worked.

## Resolution protocol for each owner (R12 — don't mask a bug)
For each pair: read BOTH handler bodies. (a) If the dead later block is an inferior/identical duplicate of the winning earlier one -> delete the dead block (behavior-preserving, clears the warning). (b) If the dead later block diverges and was the INTENDED behavior (a domain rewrite that got shadowed) -> the action is silently running STALE logic; decide which handler is canonical, keep that one, delete the other (and fix the routing). Deleting the dead block WITHOUT this check silences the warning while potentially leaving the wrong handler live.
