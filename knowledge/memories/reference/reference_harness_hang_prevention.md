**Symptom:** after a while, Write/Read/Grep/Bash/hook tool calls hang and the turn never ends. Worsens across the session and with more concurrent chats.

**Root cause (diagnosed 2026-05-11):** Windows fork-storm. Each tool call cold-started 20–30 `node.exe` hook processes; ×8 concurrent chats = 150–250 simultaneous spawns → Windows process-table / DLL-init saturation (`STATUS_DLL_INIT_FAILED 0xC0000142`) → spawns stall, hook processes orphan instead of exiting, bundle hard-timeout fallback adds +1s each. Orphans accumulate → everything crawls → hang. **The Stop hooks meant to reap orphans never run because a hung session never fires the Stop event** (chicken-and-egg).

**What's now wired to prevent it (round 2 — 2026-05-11, "permanent fix"):**
- `node-process-janitor.mjs` → PreToolUse `.*` (self-throttled via `H:/prism/state/shared/.hook-janitor-stamp`; ~20ms no-op hot path, real sweep ~1/min). **Hardened:** now also kills (a) `bash.exe`/`sh.exe` Git-for-Windows wrappers whose cmdline references `.claude/hooks|helpers` and are >45s old — these double-fork bash wrappers are what actually wedge on stdio; (b) orphan MCP servers (`@playwright/mcp`, `mcp-http-bridge.mjs`) whose **parent PID is dead** AND >45s old — never touches a live session's MCP (its parent = the live Claude harness). New `--full` flag (skip throttle, always sweep) for the scheduled task.
- **DEAD PostToolUse entries removed entirely** (2026-05-11 round 2). The previous fix kept ~35 dead entries as `exit 0 && <original>` — but on Windows the *bash fork itself* (CreateProcess + DLL init) is the expensive part, so 44 bash forks per tool call still stormed. Now `C:/Users/wompu/.claude/settings.json` (canonical; mirrors to `H:/.claude/settings.json`) PostToolUse = **9 entries, 0 dead** (the 2 posttool bundles + 7 small per-matcher trackers). The 33 bundle-absorbed sub-hooks still run via `posttool-edit-bundle.mjs` + `posttool-bash-read-bundle.mjs` (concurrency-6 pools); `ollama-terminal-watcher.mjs` is gone for good. `stop_on_hook_unregistration.mjs` was upgraded so it doesn't block: it now treats a hook as "still registered" if it appears in `bundles/*.mjs` SUB_HOOKS *or* in the `INTENTIONALLY_DISABLED` set in that hook (currently just `ollama-terminal-watcher.mjs`) — and it dropped the raw-count check (bundling legitimately lowers the count). Backups: `C:/Users/wompu/.claude/settings.json.bak-deadhooks-<stamp>` (+ H: copy).
- `hook-runner.mjs` (`.claude/hooks/bundles/lib/`): on sub-hook timeout it now does `taskkill /T /F /PID <child>` (Windows tree-kill) in addition to `child.kill(SIGKILL)` — SIGKILL doesn't kill grandchildren (eslint/git/powershell a hook spawned), which were a real orphan source.
- **Three** Windows Scheduled Tasks now (independent of Claude sessions): **"PRISM Hook Janitor"** runs `node-process-janitor.mjs --full` **every 2 min** (the new one — covers bash + orphan MCP; installer `.claude/helpers/install-hook-janitor-task.ps1`), plus the existing every-5-min **"PRISM Zombie Reaper v2"** (`stop_close_prism_nodes_v2.mjs`) and **"PRISM Node Orphan Cleaner"** (`node-orphan-cleaner.mjs`). `Disable-ScheduledTask` to pause; each installer takes `-Uninstall`.

- **M5 follow-ups — assessed, NO CHANGE NEEDED (don't re-open without new evidence):**
  - **M5a** (`autonomous-loop-defer.mjs` throttle) — measured: with the 5-min window and the prune logic, the rate log stays ~3-4 KB, so the per-call cost is `readFileSync(~3.7KB) + appendFileSync(one line)` ≈ <1 ms; telemetry only writes on warn/ask/deny (not on the `allow` hot path). Throttling the analysis would need a count-cache side-file + staleness handling for a sub-millisecond gain. Not worth it.

**Knobs if it recurs:**
- `PRISM_HOOK_BUNDLE_CONCURRENCY` (default 6) and `PRISM_POSTTOOL_BUNDLE_CONCURRENCY` (default 6) — lower to 3–4 under heavy multi-chat load.
- Immediate sweep: `node H:/prism/.claude/hooks/node-process-janitor.mjs --full` (no stdin needed in `--full` mode). Check `tasklist | grep -c node.exe` — >20 with few active chats = orphan buildup.
- If a Stop block ever complains about removed hooks after legit bundling, add the filename to `INTENTIONALLY_DISABLED` in `stop_on_hook_unregistration.mjs` *with a reason*, or add it to the relevant bundle's SUB_HOOKS.
- Stale git worktree locks: `H:/prism/.git/worktrees/agent-*/index.lock` older than ~1h are dead-subagent garbage — safe to `rm`. `agent-worktree-stale-unlock.mjs` (SessionStart) unlocks but does not remove. ~50 registered worktrees (`git worktree list | wc -l`) also slows every git-touching hook; prune deliberately.
- `hook-saturation-alert.mjs` exists (queueing-theory ρ>0.8 alert) but is **not wired** — could be added to a posttool bundle's SUB_HOOKS for early warning.
