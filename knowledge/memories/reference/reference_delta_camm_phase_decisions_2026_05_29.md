## §measure-before-claim (R12 — the session's hardest lesson, 2026-05-30)
I stated an UNMEASURED bound-count **3 separate times** this session: "137" (`f43a977b44`), "142" (`10b5ca4de0`), and "81" in the very commit meant to fix overclaiming (`2aa14cf530`). Each time the registry file was actually correct; only my prose lied. **The rule is not "measure then write" — it is: never emit a number into a commit message, handoff, or report unless I ran `git show <sha>:<file>` or read the live file IN THE SAME tool batch that produces the number.** Bound counts cost one `node -e` to measure. There is no excuse for a guessed metric. Git commit messages are immutable — a wrong number there is permanent debt that needs a measured-corrections table (see the handoff). This pairs with [[feedback_delta_topology_before_tolerance]]'s honesty discipline.
- **§creator-class-gap-audit (the RIGHT ceiling test, 2026-05-30):** to find ALL remaining bindable ops, do NOT fuzzy-match op-id↔method-name — Fusion feature classes share a generic `createInput`, which never token-matches the op-id, so a name matcher silently misses every feature class (it found 0 of the 11 real ones). ## Bridge contract (verified, reusable for hyperCAD/Mastercam-equivalent bridges)
