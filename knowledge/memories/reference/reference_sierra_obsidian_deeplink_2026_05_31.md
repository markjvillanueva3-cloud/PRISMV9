**STALE-LOCK DISCRIMINATOR REFINEMENT (extends the [[reference_sierra_dead_edge_id_mismatch_2026_05_30]] regression lesson).** Committing took many retries under heavy fleet contention (9 peers, 96% commit memory, commits taking minutes). A `.git/index.lock` blocked me. Before removing it I confirmed STALE via THREE discriminators — distinct from the 2026-05-30 regression where I wrongly swept a LIVE peer's lock: (1) **size 0** (a live commit writes a ~7MB index COPY into the lock immediately; an empty lock = a git that created the lockfile but stalled/crashed before writing), (2) **mtime FROZEN** ~2.5 min (not advancing), (3) **HEAD advanced PAST it** (a927526c→8f7670f1) — peers were committing successfully via their **slot-worktree indexes** (`.git/worktrees/<name>/index.lock`, a SEPARATE path), proving the main-tree `.git/index.lock` was an orphan no live process held. Removed it → my commit + a peer's both landed cleanly. **Rule: empty-size + frozen-mtime + HEAD-moving-independently = safe to remove; non-empty + freshly-touched = LIVE peer, wait.** Reinforces [[feedback_commit_to_slot_worktree]] (peers on worktrees don't contend the main index — I was on the shared tree in [MAIN] mode).
