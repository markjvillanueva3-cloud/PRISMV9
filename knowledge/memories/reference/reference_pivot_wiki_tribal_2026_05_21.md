## System injection — zero wiring

The breakthrough insight: every authored entry **auto-surfaces via existing UserPromptSubmit hooks** without new wiring:

- `tribal-by-domain-inject` matches keywords per slot's domain → injects top-3 hits
- `wiki-precheck-inject` matches keyword tokens to wiki index → injects top-3 entries
- `master-index-precheck-inject` matches against system-graph.json → injects top-5 graph hits

Frontmatter `description` + bolded section headings in the entries get tokenized into the injection match signature. Writing the entry is the only action; injection is automatic from the next chat that mentions a category keyword.

## Lessons learned (cross-session-portable)

1. **Lock-contention pattern in shared `H:/prism` tree under fleet load.** `.git/index.lock` 0-byte files > 60-180 s old are stale; remove with `rm -f` and retry. Windows `Device or resource busy` errors clear after a 30-60 s wait. Both encountered + resolved this session.

2. **Pathspec commit (`git commit <path>`) is the safe pattern under multi-chat.** Pathspec ignores other staged peer files; even if `git add` accidentally pulls in peer-staged work, the commit only carries my path.

3. **Per-file authoring without scrutiny gate is acceptable for wiki entries** (vs code). Wiki entries don't go through the per-file 2-reviewer scrutiny gate or the end-of-task 3-of-3 gate — they're prose, not executable code. The session-continuity discipline still applies (frontmatter `version_state`, cross-references, source citation).

4. **3-3-3-3-3 matrix shape was emergent, not designed.** Started breadth-first (one per category) for iter 9-13, then depth-first (1 → 2 → 3 entries per category) for iter 14-20. The balanced shape fell out naturally from "pick the lightest-covered category next" + the audit's tip-count rankings.

5. **Operator's "high-ROI" rule of thumb (4245-tip corpus × pre-pivot %-coverage)** is a strong pickup signal. The audit's measurement of where the gaps are gives every iter a defensible pickup; no time wasted choosing between equally-valid alternatives.
