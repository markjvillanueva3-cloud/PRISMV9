Operator (2026-05-30) asked echo to build a system to *drive WinMax* the same way delta drives CAD/CAM. Home: `mcp-server/data/posts/prism-base/winmax-bridge/`. Commit `e158abbe42` (U-ECHO-WINMAX-BRIDGE-1).

**Delta's pattern (mirrored):** per-app `<Software>AutomationBridge.ts` engine that spawns the app with a documented hook + IPC (Mastercam NET-Hook + named pipe; Esprit VBScript COM), dispatches JSON commands, composes existing engines, has **mock mode** (`PRISM_CAD_MOCK=1`) for headless testing, an `<platform>.actions.json` op→fn map, and a **source→regen→compare** loop (`state/shared/cad-regen-output/`).

**The honest WinMax difference (R12):** WinMax has **NO documented public automation API** (unlike Mastercam/Esprit). So we mirror delta's *architecture* but the *transport* differs — discovered by read-only `scripts/winmax-probe.mjs` (→ `winmax-bridge/SURFACE-PROBE.json`): **WCF** `WcfDataService.exe` on `net.pipe://localhost` + `net.tcp://localhost:4502` + `http://127.0.0.1:8080` (primary, closest to delta's pipe) · **datablock-xml** `WinMaxDataBlockXMLTools.dll` (453KB, program↔XML) · **ui-automation** (Qt GUI fallback) · **local** (our own interpretation, always available).

**Built + tested (`scripts/winmax-bridge.mjs`, 11 node:tests):** `WinMaxBridge.execute(action,params)` over pluggable transport, `AtomicValue` returns, **mock-by-default** (`PRISM_WINMAX_MOCK`). The delta compare loop = `ncToDatablocks(nc)` (parse NC→program block model: program#/units/wcs/tools/motions/stats — our interpretation, LIVE+tested) + `compareDatablocks(ours,winmax)`. `probeWcfLive()` fetches the WCF WSDL when the stack is up. **Parser fix:** G28/G30/G53 = rapid-home, G43/G44 = rapid-comp (do NOT inherit a stale arc modal — was miscounting home/approach as arcs). **Safety:** NEVER auto-launches WinMaxMill/CNC_RT; a live transport with no running stack returns a LOUD warning (confidence 0), never a fabricated result (test-verified).

**U-WINMAX-WCF-CLIENT (2026-05-30, commit on cad-fusion-live-ms0) — the REAL contract + a working WCF client.** Home: `mcp-server/data/posts/prism-base/winmax-bridge/wcf-client/`. Installed .NET 8 SDK (`C:\Users\wompu\.dotnet`) + `dotnet-svcutil net.tcp://localhost:4502/DataServicetcp/mex` → `WinMaxDataService.cs`. **CORRECTION (R12):** the earlier `winmax.actions.json` op names (`LoadProgram`/`GetProgramBlocks`/`RunVerify`/`GetStatus`) were GUESSES that DO NOT EXIST. **The shim** `PrismWinMaxShim.exe` (**net48** — modern .NET WCF throws `PlatformNotSupportedException` for `SecurityMode.Message`): JSON-over-stdio, read-only-by-default, motion ops gated behind `--allow-motion`. **Binding proven live against the running stack** (from `WcfDataService.exe.config`): `net.tcp:4502 DataServicetcp`, `SecurityMode.Message` + `clientCredentialType=UserName`, custom `VendorIdValidatorReadWrite`, server cert `cer.pfx` (`CN=*.hurco.com`, DNS claim `machine-connect.hurco.com`, self-signed/expired). The shim peeled every layer: transport ✅ → message security ✅ → server-cert trust (`ServiceCertificate.Authentication.CertificateValidationMode=None`, NOT SslCertificateAuthentication) ✅ → DNS identity (`new EndpointAddress(uri, new DnsEndpointIdentity("machine-connect.hurco.com"))`) ✅ → **VendorId credential gate ⛔** (dummy creds rejected with an unsecured fault). **ONLY remaining requirement = a valid Hurco Vendor ID + secret** (`--user`/`--pass` or env `WINMAX_VENDOR_ID`/`WINMAX_VENDOR_SECRET`) — a licensing/operator step, NOT a code gap; do NOT extract it from the binary.
