**LESSON (reusable, fleet-wide) -- two tsc configs give wildly different results; only one is authoritative.** Chasing a "RED build" I ran a bare `node node_modules/typescript/bin/tsc --noEmit` from the repo root (cwd had been reset to `H:/prism` by a PowerShell tool call). That used the **repo-root `tsconfig.json`** (`include: ["src/**/*.ts"]`) and reported **61 errors** across `routes/edm.ts`(20), `routes/api-ext.ts`(10), `core/hooks/index.ts`(8), `PostProcessorPipelineEngine`(4), etc. -- with **phantom line numbers** (e.g. `EDMMultiPassStrategyEngine.ts(913,...)` when the live file is **422 lines**; `MachineStrategyConstraintEngine.ts(549-551)` claiming `"X"/"Y"/"Z"` pushes where the live lines are `powerCheck`/`derating.push`). The wrong line numbers prove the root config is compiling **stale/worktree copies** (a `.claude/worktrees/brave-euclid/mcp-server/` copy exists), NOT the live `mcp-server/src`.

**The AUTHORITATIVE build is `mcp-server/tsconfig.json`** (what `npm run build:incremental/verify` uses via npm cwd). Running it explicitly:
`node --max-old-space-size=16384 H:/prism/mcp-server/node_modules/typescript/bin/tsc -p H:/prism/mcp-server/tsconfig.json --noEmit`
-> **exactly 1 error**: `mcp-server/src/engines/InventorCADCodeGeneratorEngine.ts(148,3): TS2353 'maxOpsPerScript' does not exist in type 'CADCapabilityMatrix'`. The 61 root-config errors + the `never[]` cluster (OptimizationTier/EDMMultiPass/Fixture/WEDMComplete) are **NOT** in the real build -- do not chase them.

**RULE:** to check the real mcp-server build, ALWAYS use `-p H:/prism/mcp-server/tsconfig.json` (or `npm run build:verify` from `mcp-server/`), never a bare repo-root `tsc`. Also: `build:incremental`'s `.tsbuildinfo` can mask OR mislocate errors (it once reported the InventorCAD error while a parallel root run did not) -- clear `*.tsbuildinfo` if results look inconsistent. Sibling stale-cache class: the constant-compaction/byte-estimate regressions.
