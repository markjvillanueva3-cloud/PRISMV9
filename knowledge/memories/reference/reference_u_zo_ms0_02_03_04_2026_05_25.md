### U-ZO-MS0-04 — `loadLoopState(sessionId)` + `findActiveLoops(opts)`

Reads `state/shared/loop-state/loop-<sid>.json` files. Gives the Zulu sweep the per-slot "running loop?" signal — without it, a `/compact` may interrupt an autonomous `/loop`.

- `KNOWN_LOOP_SCHEMA_VERSIONS = ["1.0.0"]` allowlist — unknown schemaVersion → `reason: "schema-version-unsupported"` (reviewer B P1-F, prevents silent decision-drift if writer renames status field).
- `isValidSessionId(s)` UUID regex anchored — `sessionId: null` on invalid (NOT reflected).

## Lesson — test path-normalization on Windows

Initial test run failed 6/99 with `Expected true got false` because record-map keys used `path.resolve(path.join(soulsDir, slot + ".md"))` (= `H:\test\souls\bravo.md` after Windows resolution) while the impl's reader was called with `path.join(soulsDir, slot + ".md")` (= `\test\souls\bravo.md`, un-resolved). Mismatched key in `records[p]` lookup.

Fix: `makeReader` now path-resolves BOTH the record-key (on insert) AND the reader-lookup path. Plus the `calls.get(p)` / `.has(p)` accessor resolves at the call site so existing MS0-01 cache-tests that pass un-joined keys keep working.

Worth filing as a future test-helper pattern: any test that exercises a reader called with a `path.join`-derived filePath must use a path-resolving `makeReader` — naive `records[p]` lookups silently miss on Windows.
