**SHIPPED 2026-06-20 (slot:alpha) -- `8d344941fe` `[TOKEN-SAVINGS]/U-AUDIT-VIZ-DEDUP`.**

**What:** `.claude/hooks/audit-viz-first-inject.mjs` now ADOPTS the existing shared `scripts/lib/injection-dedup.mjs` lib (the alpha-authored `U-PSN-INJECTION-DEDUP-LIB` family that slot-domain-awareness-inject already uses). The hook fires on most prompts (audit verbs `audit`/`ghost`/`unwired` are common in directive/boilerplate text -- observed ~12x identical fires in one session) and pays an EXPENSIVE `system-viz-query` subprocess (8s timeout) per fire. **Divergence from the sibling (R11-surfaced, justified):** slot-domain hashes its CHEAP static block; audit-viz keys the dedup on the INPUT `hashBlock("${matched}::${noun}")` BEFORE the subprocess -- so a dedup-hit emits a 1-line marker and SKIPS BOTH the subprocess AND the re-injection. New pure exported `decideAuditVizEmit({cache,sid8,matched,noun,now,ttlMs,dedupDisabled})` -> action `emit|marker|bypass`; `recordEmit` runs ONLY after a successful query, so a `marker` provably implies a prior successful injection. Fail-soft (dedup-disabled / missing session_id / sidecar read+write error) -> emit/bypass path = zero regression. Knob `PRISM_INJECTION_DEDUP_DISABLE=1`.

**Validation:** 9/9 new unit tests (`audit-viz-first-dedup.test.mjs`, happy + 5 failure + 2 adversarial that LOCK the input-keying contract) + 31/31 existing rate-gate (no regression). LIVE A/B through the real hook: run1 -> full block; run2 (identical, within 5min TTL) -> dedup marker (subprocess skipped); `=1` -> bypass (full block). Per-file 2-arm + 2-of-3 (A/B/C) all PASS, 0 P0/P1.

**PRE-EXISTING FLEET BUG surfaced by scrutiny arm C (NOT introduced by this commit -- a precisely-scoped NEXT UNIT):** `pruneExpired` (`scripts/lib/injection-dedup.mjs`) is **tag-agnostic** -- it drops every entry older than the CALLER's `ttlMs`, across ALL hookTags. But the **shared** `state/shared/dashboards/injection-dedup-cache.json` is pruned-and-written-back by ~11 adopters each with its OWN TTL: audit-viz=5min, slot-domain=5min, **galaxy-claudemd-inject=30min**, **psn-prompt-checklist-inject=24h**. So any audit-intent prompt makes audit-viz prune with 5min and write the whole truncated cache back -- **evicting a still-live 6min..24h sibling entry** -> that sibling re-emits its full block next prompt (a dedup MISS = wasted tokens). Self-healing, never corruption/safety. **Fix (separate fleet-wide unit, do NOT fold into an adopter):** either (a) make `pruneExpired` per-tag TTL-aware (carry each tag's TTL), or (b) each hook prunes ONLY its own tag's bucket before write-back (read-merge-write your tag, never re-prune foreign tags) -- option (b) is cleaner + lib-local. This is a genuine token-economy bug in alpha's domain; high-value because the longer-TTL adopters (galaxy-claudemd, psn-prompt-checklist 24h) are exactly the big blocks whose dedup it silently defeats. Sibling lib: [[reference_route_decay_splice_wired_2026_06_12]]; family: [[reference_mcp_route_suppress_isverbosebash_2026_06_20]].
