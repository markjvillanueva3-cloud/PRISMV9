H7 of [[audit-system-synergy-2026-05-09]] shipped: `memory-index-search` is a direct BM25-lite search over `H:/prism/knowledge/memories/{feedback,reference,project,user,patterns,mistakes,inbox}/` (~492 files at audit time). Closes the gap where `master-index-precheck-inject.mjs` only surfaces memories that some system-graph node has pre-joined via `knowledge.memoryEntries[]` — free-floating memories (just-written, never linked) are invisible to that path. `memory-relevance-inject.mjs` is PreToolUse:Edit-only and derives terms from FILE PATH, not user-prompt content. Three surfaces, three scopes, additive.

**R12 dogfooding**: built this lib because I just wrote [[reference_h8_misattribution_2026_05_20]] and a query like *"what do we know about shared-tree misattribution"* in the next session would hit ZERO existing surfaces until `regen-viz` rebuilt the graph. Live-fire of the lib correctly surfaces the misattribution memo + 2 siblings (`feedback_scrutiny_codex_captures_peer_work` + `reference_cte_peer_absorption_2026_05_20`).

**Pure-core + injected-IO pattern** (same shape as [[reference_u_stop_hook_aggregator_2026_05_20]] which I shipped 6 hours earlier — the H8 lesson learned):
- `scripts/lib/memory-index-search-lib.mjs` — 7 pure exports (`tokenize`, `STOPWORDS`, `buildMemoryRecord`, `scoreMemoryRecord`, `enumerateMemoryFiles`, `runMemoryIndexSearch`) + `__test_constants` for hermetic verification
- `scripts/lib/memory-index-search-lib.test.mjs` — 32 `node:test` cases incl. tokenizer (6), record builder (8), scorer (7), enumerator (4), end-to-end search (7) with fake-vault helper
- `.claude/hooks/memory-index-precheck-inject.mjs` — UserPromptSubmit consumer (~95 LOC; mirrors `master-index-precheck-inject.mjs` pattern)

**Scoring** (W_NAME=3.0, W_DESC=2.5, W_BODY=1.0, W_TYPE=0.5) and **tokenizer** match `master-index-search-lib.mjs` verbatim — search semantics blend predictably across the two surfaces. STOPWORDS Set is RE-EXPORTED, but the canonical Set lives in master-index-search-lib; this lib carries its own copy to keep the import graph one-way (avoid cycles).

**Wiring status — DEFERRED (honest scope R12).** Cold-parse of all 492 memories takes ~8.7 s on the work PC — exceeds the UserPromptSubmit 5 s timeout class. The hook is built + tested + committed but **NOT wired in settings.json**. Live-fire confirms correct ranking; sidecar fast-path is needed before wiring.

**Follow-up unit queued: `U-MEMORY-INDEX-SIDECAR`** — pre-built `state/shared/memory-index-sidecar.json` (slug + namespace + description + opening per file, ~2 MB) regenerated by a Stop hook or post-commit hook when memories change. The lib's `runMemoryIndexSearch` would prefer the sidecar (sub-50ms parse) and fall back to live scan on staleness — mirrors `master-index-search-lib.mjs`'s `tryLoadSidecar` pattern. Once shipped, wire `memory-index-precheck-inject` into `UserPromptSubmit` chain in both `C:` + `H:` `.claude/settings.json` after `master-index-precheck-inject`.

**Safety properties:**
- `DEFAULT_MAX_TOTAL_BYTES = 8 MB` DoS guard (4× headroom over the 2 MB worst case for 492 files × 4 KB body cap)
- `DEFAULT_MAX_BODY_BYTES = 4 KB` per-file body cap (a pathological 1 MB memory reads at most 4 KB)
- Per-namespace + per-file fail-soft (`readdirSync` EACCES / `readFileSync` ENOENT skip silently)
- `MEMORY.md` + `MEMORY-ARCHIVE.md` filtered (those are the index, not memories)
- Deterministic alphabetical tie-break on equal score (byte-identical output across runs)
- Stopwords + min-token-length (≥3) prevent low-signal high-fanout queries

**Knobs:** `PRISM_MEMORY_INDEX_INJECT=0` (off), `PRISM_MEMORY_INDEX_K=N` (top-K, default 3, bounded 1..10), `PRISM_MEMORY_INDEX_MIN_TOKENS=N` (min content tokens to fire, default 2).
