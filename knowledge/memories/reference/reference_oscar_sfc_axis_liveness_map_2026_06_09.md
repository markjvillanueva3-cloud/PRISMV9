## Power-axis ROOT CAUSE (deeper than a forward)
Power is **advisory, NOT a clamp**, on the recommendation path: `UltimateSpeedFeedEngine.ts:2291-2304` warns + recommends "reduce MRR" when `power > 90% available` but does NOT reduce the returned Vc/feed/MRR. Only the separate `best`-evaluator optimizer (line 3157 `Pmax`) treats power as a hard constraint — and the orchestrator default reads `alternatives.balanced` from the ADVISORY path. So making spindle/machine power actually clamp the recommendation is a physics + product-design decision (clamp vs warn), physics-reviewer + S(x) gated — NOT a surgical forward.
