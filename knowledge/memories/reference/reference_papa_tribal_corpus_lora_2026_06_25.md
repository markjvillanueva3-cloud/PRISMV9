**Shipped (slot:papa, 2026-06-25 autonomous overnight, commit `5d9dbbc91c` U-PAPA-TRIBAL-CORPUS-LORA).**

**The gap.** The per-domain `state/shared/*-tribal-corpus.jsonl` files (cam 809, tooling 313, mill 71, post-processor 63, lathe 18, cad 12, speed-feed 8, database-expansion 7, blueprint-vision 7, wedm 2 = ~1310 entries) were ABSENT from LoRA training. Their `tip` field is a POINTER ("CAM training reference (kind=...): read AUTOGEN-EXTRACT-SPEC-<slug>.md ... then ingest source file") -- ALL 809 cam tips verified pointer-style. Feeding the pointer text as LoRA `output` would be GIGO (teaches the model to say "read X.md", not the knowledge). The real knowledge is in the `source` PDF the pointer references. Distinct from `domain-knowledge-lora` (which covers only the 65 Ollama-rescued RESIDUAL specs, the non-cadcam domains) and `cam-master-training-set` (a different cam corpus).

**The fix.** `scripts/tribal-corpus-to-lora-dataset.mjs` -- SIBLING of `domain-corpus-to-lora-dataset.mjs`. Reads each tribal entry's REAL `source` PDF (pdftotext) -> domain-tagged Alpaca `{instruction,input,output}` pairs. REUSES the domain-corpus converter's exports (`pdfToText`, `buildPairsForEntry` = distill+GIGO-gate, `parseCursorState`/`partitionForDistill` = reap-resumable cursor) -- NO duplication of distill/GIGO/cursor logic (R8). Grouped by slug into the `{slug, domains[]}` multi-domain entry shape (so the slug-keyed cursor + multi-label emit both hold; live: 0/897 slugs have conflicting sources). **Overlap-guard** skips any `(slug,domain)` already in `domain-knowledge-dataset.jsonl` -> strictly additive (R16). GIGO: emits ONLY when the PDF yields usable text (>= MIN_TEXT_CHARS real words); the pointer `tip` is never read in code (only in comments) so it CANNOT leak into a training row.

**Shipped result (cad/cam, R13 verifiable raw core).** 821 cad/cam entries -> **398 raw PDF-grounded pairs** (390 cam + 8 cad; 423 scanned/image PDFs correctly GIGO-gated as no-text), 0 pointer-leaks, folded into the fleet LoRA corpus via `assemble-fleet-lora-corpus.mjs` (**-> 6513 rows, 0 dup, 0 invalid**). 16/16 R9 tests; 3-of-3 scrutiny PASS. Registered as `tribal-knowledge-lora` (advisory, w=0.5) in `build-fleet-training-corpus-inventory.mjs`.

**Follow-ons:**
1. **Quality upgrade (= the LOOP/CRON's job, NOT a foreground chat run -- learned the hard way):** `--distill --out` turns the 398 raw rows into Ollama Q&A (keep_alive fix [[reference_papa_lora_distill_burst_wedge_2026_06_24]]). A foreground FULL run (~398 Ollama calls, ~26min) was KILLED twice mid-flight (exit 255, no-output = the whole bash subprocess tree reaped/idle-killed ~5min in at 69/398); a bounded `--limit 12` run completes clean in ~30s and yields real cad/cam Q&A (5/12) -- so the reap is specific to the LONG SILENT run, not the code. The distill completes via the RESUMABLE cursor across MANY short loop/cron runs (the same mechanism that landed domain-knowledge's 97 distilled incrementally). `U-PAPA-TRIBAL-DISTILL-PROGRESS` (`09ff81009a`) added per-chunk `console.error` progress logging (PROGRESS_EVERY=25, stderr-only so it never pollutes the jsonl) so those runs are observable + idle-kill-resistant. A mid-distill kill truncates the raw down to the partial distilled (a COUNT regression) -- restore via raw `--out` (fast, no Ollama, un-reapable) if a run dies and leaves the dataset short; the dataset is gitignored/regenerable. Lesson: a long silent Ollama batch belongs to the reaper-aware loop/cron in short increments, never a single foreground chat turn (R5/spiral).

   **ATOMIC distill-to-temp ATTEMPTED + REVERTED (`65628c77bf` -> revert `17f972870a`) -- a future dedicated unit, NOT a quick patch.** The idea (stream `--distill` to `outPath.inprogress`, atomic-rename onto the live dataset only at full coverage, so a reaped/partial run never regresses the live 398) is SOUND, but the per-file scrutiny (arm A) caught a real P0 data-loss BEFORE it shipped, so it was reverted. **The two design constraints any proper attempt MUST solve (they arise from the deferred-retry self-heal x coverage-swap x parseCursorState-counts-LINES interaction):** (P0 multi-run clobber) after a complete swap the cursor is full + `.inprogress` is gone; a re-run that re-processes only the retryable raw-fallback entries builds a FRESH NARROW `.inprogress` and -- since coverage is still full -- renames it over the full live dataset, destroying the published rows. (P1 incomplete publish) a raw-fallback-under-cap entry writes a cursor LINE but NO stream row (deferred), so `seen>=total` (coverage) can be true while the stream is MISSING those entries' rows -> swaps an incomplete set labeled COMPLETE. Fix directions: reset/retire the cursor on swap (so a post-swap re-run is a fresh full cycle, not a narrow clobber) AND ensure the stream has a row for every text-bearing entry before swapping (don't defer raw-fallback rows in atomic mode, OR require `pending`-excluding-no-text == 0). Until then the distill stays the loop's truncate-then-accumulate job (raw-restore recovers a reaped partial). Lesson: an atomic-swap over a resumable-with-deferred-retry stream is a real state-machine -- coverage alone is not "complete"; a deferred row makes "seen" lie.
2. **`--domains all` widening (UNBLOCKED -- arm-A P2 FIXED in `88193cc818` U-PAPA-TRIBAL-CURSOR-DOMAINSET):** the resume cursor WAS keyed on `slug` alone, so a wider `--domains all` run appended onto the cad/cam cursor would SKIP already-cursored slugs and silently drop ~364 newly-grouped (slug,domain) labels (a slug carries domains across corpora -- a CIMCO post is in BOTH cam + post-processor). FIX: `cursorPathFor(outPath, domainsArg)` keys the cursor by the sorted domain-set -> each `--domains` invocation resumes independently; a fresh `--domains all` run gets its own empty cursor, truncates, and rebuilds the COMPLETE dataset (cad/cam included). Default + explicit `cad,cam` share one cursor. So `--domains all --distill --out` is now safe to run (loop/cron job; ~897 slugs, resumable). A residual reverse-order clobber (a fresh narrower set truncating a populated wider output) is guarded by `clobberLostDomains` + a LOUD R12 warn (`U-PAPA-TRIBAL-CLOBBER-GUARD` `c266744b25`) -- recoverable via a fresh `--domains all`, never silent. 18/18 tests.

**Lesson:** a per-domain tribal corpus whose tips are PURE POINTERS is dark LoRA data -- the producer index exists, but the knowledge never reaches training until something distils the SOURCE the pointer names. Reuse the proven sibling converter's primitives (don't re-impl distill/GIGO/cursor), group by the natural key the cursor uses, and overlap-guard against the existing LoRA dataset so the two feeders stay strictly additive.
