**SFC-JM-ACCURACY pipeline (slot:oscar, 2026-06-24).** Built the operator's "utilize ALL JM die parts and programs first to run full live tests of parameters ... programs are mostly written by amateurs so don't trust the speeds/feeds, use them as the GUIDELINE to test against" deliverable. Three committed units (extract -> corpus -> analyze) + a cron-able refresh runner:

1. **`scripts/lib/sfc-program-param-extract-lib.mjs`** (U-SFC-NC-PARAM-EXTRACT, 7/7 tests) -- pure NC->cutting-param extractor. Modal scan over `tokenizeNc`+`detectUnits` (reused from `cnc-ground-truth-lib`, no fork) + `NC_TEXT_EXTS` gate (from `cnc-program-gt-lib`, blocks binary .mcx text-scrape). Emits distinct programmed `(tool, spindleMode css/rpm, S, feedMode per_min/per_rev, F)` sets. G50 rpm-clamp excluded from cutting spindle; Txxyy lathe tool unpacking (`resolveToolNumber`). The two existing NC libs extract DIMENSIONS, not speeds/feeds -- this was a genuine gap.
2. **`scripts/sfc-jm-program-corpus.mjs`** (U-SFC-JM-CORPUS, 3/3 tests) -- resumable corpus harness. Walks the REAL `H:/PRISM/JM DIE` tree (the `jm-die-full-program-index.json` is a PARTIAL 17k-NC subset; live tree has ~119k .nc + ~35k .min). SFC-domain gate excludes wire/sinker EDM + grind/waterjet/laser/plasma. Kill-safe resume (row append BEFORE cursor mark). main() import-guarded.
3. **`scripts/lib/sfc-corpus-analyze-lib.mjs` + `scripts/sfc-jm-corpus-analyze.mjs`** (U-SFC-JM-ANALYZE, 5/5 tests) -- two-pass streaming analyzer. Per-`(machineClass x spindleMode)` bucket: shop distribution + Tukey IQR fences (shop-relative outliers, unit-agnostic within a bucket) + absolute `GROSS_BOUNDS` physical screen (JM inch convention LABELED).
4. **`scripts/sfc-jm-accuracy-refresh.mjs`** (U-SFC-JM-REFRESH) -- chains incremental corpus + analyze; durable cron `de63fb85` (nightly 3:13 AM, auto-expires 7d -- re-register or convert to a PRISM scheduled-task for permanence).

**LIVE RESULT (full corpus):** 154,414 programs -> **1,171,812 as-programmed ops**, 0 errors, 42 EDM skipped. Machine split: lathe 136,385 / unknown 17,447 / mill 568 / mill_turn 13. **lathe|css dist: 455,880 ops, p25-p75 = 150-250 sfm (median 250)** -- physically-sensible conservative carbide turning. **470 gross-physical-error ops** (54 css-too-high, 109 feed-too-high, 235 feed-too-low, 67 rpm-too-low, 5 css-too-low) + 105,534 spindle / 66,111 feed shop-relative outliers. Report: `state/shared/SFC-JM-CORPUS-ANALYSIS.json` (topOutliers carry file paths).

**KEY DATA TRUTHS:** units mostly `unknown` (153,753) -- Okuma .MIN omits G20/G21; JM convention = INCH (apply LABELED, never silently for safety). materialHint present on only 130/34,786 index entries -> a full material-resolved PRISM-SFC physics comparison needs a material+tool-geometry join (JM part-library / tooling-manifest) and is the NEXT unit. POST PROCESSORS `.cnc` vanilla templates pollute slightly (a 433333-spindle template surfaced as a top outlier) -- consider excluding `POST PROCESSORS` topFolder.

**5. U-SFC-JM-PHYSICS-CMP (SHIPPED, the physics test-against)** -- `scripts/lib/sfc-taylor-vc-lib.mjs` (4/4: Vc=C/T^n band classify, takes C/n, NEVER inlines) + `scripts/lib/sfc-material-infer.mjs` (6/6: path/name+COMMENT -> ISO group, labeled confidence) + `scripts/sfc-jm-physics-compare.mjs` (CLI; wires CANONICAL_TAYLOR from constants.ts under tsx self-reexec). Wired into refresh stage 3. Material confidence lifted by U-SFC-JM-MATERIAL-COMMENTS (mine program comments, not just path) + precision fix U-SFC-MATINFER-PRECISION (drop bare 625/718/304/2024 collision numbers -- a live run had falsely classified 5076 ops as superalloy S from part/program NUMBERS).
**FINAL LIVE (precision+clamp-corrected, 509,381 lathe CSS ops):** 88% cooler than carbide-Taylor (43% conservative + 45% very-conservative), 8.8% in-band, 3.3% (16,942) aggressive. **CRUCIAL clamp-aware split (U-SFC-PHYSCMP-CLAMP-AWARE): only 42 of those are UNCLAMPED** (high-confidence true over-speeds, top ratio only ~1.11 = mild) -- the other **16,900 are G50-rpm-CLAMPED** (programmed CSS is an UPPER bound; effective Vc = rpm*pi*D is capped far lower). The earlier headline "T-D2 1500sfm = 5.7x too hot" was a CLAMPED op (G50 S1500 precedes G96 S1500) -- the effective speed is rpm-capped, NOT 5.7x. byIso now P/H/N/M only (S superalloy false-positives eliminated). **HONEST CONCLUSION: JM lathe programs run overwhelmingly CONSERVATIVE; ~42 mild unclamped over-speeds to review, NO gross unclamped errors.** Report: `state/shared/SFC-JM-PHYSICS-COMPARE.json` (topAggressive ranks unclamped first). **R12 caveat: material still ~99% DEFAULTED to P-carbide** (only ~2.9k/509k matched a grade token even with comment-mining) -- so the "conservative" finding assumes carbide; HSS/hardened programs legitimately run cooler. LESSON: a CSS-target comparison MUST be clamp-aware (G50) + the inference heuristic MUST gate collision-prone numeric tokens behind material words (live-data validation caught both).

**6. U-SFC-JM-STOCK-PRIOR + U-SFC-PHYSCMP-MATSTATE (SHIPPED, the conclusion-correcting capstone).** The "JM runs 88% conservative" finding was an ARTIFACT of defaulting unknown-material ops to P-carbon-steel. Deep-searched JM material data (R8/never-claim-absence): `jm-die-stock-material-catalog.json` (QuickBooks purchases 2014-2026, 2212 stock lines) shows JM stock is **93.7% TOOL STEEL (ISO H)** -- H13(831)/M2(375)/D2(275)/S7(244)/M4/A2/O1... -- only 5.4% P. `scripts/lib/sfc-jm-stock-prior.mjs` (3/3) derives the modal ISO (H); `inferIsoGroup` gained a `defaultIso` param; corpus defaults unknowns to H. BUT the deeper truth (R12/uncertainty): die tool steel is rough-TURNED ANNEALED (soft, P-like machinability) and hardened LATER for grinding/hard-turning -- and programs do NOT record hardness state. So physics-compare now reports BOTH bounds: **byBandSoftBound (annealed/unknown->P): 88% conservative + 3% aggressive** (the operative reading for lathe roughing) vs **byBand (hardened/unknown->H): 45% conservative + 30% in-band + 24% aggressive**. Of ALL aggressive flags only **169 are UNCLAMPED** (rest G50-capped upper-bounds). **HONEST FINAL CONCLUSION: JM lathe runs conservative-to-in-band; the true band is hardness-state-dependent (P<->H range); at most ~169 unclamped over-speeds to review; the definitive answer needs per-op hardness state captured in the data.** LESSON: a CSS-vs-Taylor comparison for a die shop is fundamentally hardness-state-dependent -- a single default material is falsely precise; report the P<->H range.
