### TWO R12 bugs found via the "fidelity didn't move" diagnostic + fixed (same commit)
1. **Oracle bug:** `sequence_fidelity` used a last-wins rank Map → re-visited families fabricated inversions even when gen==ref. Rewritten as **Kendall concordance on first-appearance order** (robust to repeats) + exposes real `inversions`. Regression test added. The earlier "0.9013/42 inversions" was partly this artifact.
2. **Loop bug:** the planner **preserves input order by design** (annotates `order_rank` + warns, doesn't sort), so feeding JM's order made gen==ref — the loop never tested PRISM ordering. `cam-offline-loop-run.mjs` now sorts generated by `order_rank` (PRISM's canonical plan) vs JM's actual order. Only now does `LATHE_OP_ORDER` affect fidelity.
Lesson: a loop metric that doesn't respond to the thing it's supposed to measure is the tell — chase it (don't trust the number).
