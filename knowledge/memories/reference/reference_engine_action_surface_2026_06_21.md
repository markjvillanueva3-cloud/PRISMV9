**SHIPPED (commit fd49523511):**
- `scripts/lib/engine-action-surface.mjs` (pure lib) + `.test.mjs` (13/13). Extracts Map<engineStemLower, Set<actionName>> from dispatcher `.ts` case bodies + projects to embeddable text. LIVE: **2155 engines / 6667 links**, leak-free.

**WHY (the leg #10 lever):** the GNN's 768-d nomic TEXT embeddings separate only **1/7** dispatcher classes (an engine's *description* is near-non-discriminative for class). The action NAMES an engine backs carry DIRECT dispatcher-class signal -- the evidence-backed dense feature the separability probe identified. ([[reference_gnn_embed_separability_diagnostic_2026_06_21]], cheap structural features ruled out in [[reference_gnn_structural_feature_probe_2026_06_21]].)

**LEAK DISCIPLINE (india soul, anti fake-0.98):** built from dispatcher case bodies (engine <- action), NEVER the node's own label. An unwired ghost backs no action -> **empty surface BY DESIGN** (a training signal on WIRED refs, generalized to ghosts via GraphSAGE message-passing). `actionSurfaceText` returns "" for any engine with no backing action.

**2 LESSONS (compounding):**
1. **R12 precision -- a bare engine-name regex over-attributes helper calls.** `\bEngine\b` matched the helper CALL `getEngine(name)` -> `getengine` was falsely the TOP engine with 2849 actions. Fix: require method-access (`Engine.` / `Engine?.`) so a call `getEngine(` (identifier then `(`, not `.`) is excluded. The sibling `generate-action-engine-edges.mjs` tolerates the loose regex ONLY because it resolves every match against real graph engine nodes (dropping non-engines); a lib without that graph-resolution needs the tighter pattern.
2. **A RECALL gap can be validity-affecting, not cosmetic (scrutiny arm-A P2, fixed in-commit not deferred).** ~half the engine population is accessed PascalCase-static (`XEngine.method()`), captured by neither the lowerCamel nor the `new X(` pattern -> they'd get an empty surface for a PARSING reason, indistinguishable from a genuine unwired ghost, which would make the downstream separability measurement test a CRIPPLED feature and likely false-negative-reject it. Fix: a precise PascalCase static-CALL pattern requiring `.lowerIdent(` (excludes type position `XEngine.SomeType` + constant `XEngine.CONFIG`). Recovered 1876->2155 engines / 5448->6667 links with NO getengine noise. R16: close a downstream-invalidating gap before it bites, even when the gate would let you defer it.

**DEFERRED P2 (logged, bounded, no live impact):** engine refs inside string-literals/comments are matched (over-attribution noise -- strip comments/strings in a follow-up); same-line two-case cross-attribution (does NOT occur in the live corpus -- only fallthrough label stacks); nested-switch over-attribution (bounded noise among WIRED engines, never a ghost leak); exported g-flagged regexes are a `.exec/.test` footgun (lib only uses `matchAll`).
