OSCAR closed-loop-learning readiness audit (slot:oscar, 2026-05-31, 7-reader workflow `wf_1c4c7e16-c49`, 1.19M subagent tokens, all evidence-cited). Answer to operator "are we ready for closed loop learning in your domain?": **NOT YET — ~35% ready. The scaffold is real and in places more sophisticated than the quoting precedent, but the loop is structurally OPEN at 3 joints and the empirical tell is decisive: `state/outcomes/speed_feed.jsonl` has 1,757 events, 100% `recommendation_emitted`, 0 actuals — the loop has never closed on a single real datapoint.**

**Per-stage readiness:** predict 25 · capture 30 · store 40 · learn 28 · NN 12 · vendor 35 · precedent 62.

**The 3 open joints (dependency order — the critical path):**
1. **No actuals producer (ROOT BLOCKER).** Nothing writes `domain:'speed_feed'` ACTUAL events (tool life, chatter y/n, Ra, cycle-time, spindle-load) stamped with the prediction's `lineage_id`. The actual-bearing bridges (`shopFloorOutcomeBridge`, `MTConnectToOutcomeBridgeEngine`) emit only wedm/mill/lathe + a *different* bus (FeedbackBus `outcome.recorded`), never speed_feed, never SFC lineage. Until actuals flow, nothing downstream can learn.
2. **Split-brain store + R12-lie stub.** The one SFC actuals API (`SpeedFeedOutcomeFeedbackBridgeEngine.recordActuals`, `prism_calc:sfc_outcome_record_actuals`) writes a VOLATILE in-memory ring (lost on restart), keyed by {machine,material,dia} NOT lineage_id, missing chatter/Ra/cycle-time. Its `tryBusCapture()` is a no-op stub returning `true` without writing (bus_capture_ok=true is a lie). The real residual consumer `SFCParameterRefinementEngine` reads the PERSISTENT bus → the two never meet. Plus ~136-250 orphaned `.speed_feed.jsonl.*.tmp` (~1.5GB) — OutcomeCaptureBus rewrites the whole shard per event (juliett tmp-leak class).
3. **No read-back injection.** `speedFeedNineAxisOrchestratorEngine.run` / `UltimateSpeedFeedEngine.calculate` (the saleable path) have NO learned-correction input field and never call `SpeedFeedDeepLearningEngine.getCalibrationFactors()` or `SpeedFeedPSNDecisionPriorEngine`. The calibration math exists (`recordFeedback → calibrationFactors *= (1-avgError/200)`, applied in its OWN predictX) but its output never reaches a real recommendation; calibration is in-memory only.

**Already built (DON'T rebuild — wire it):** persistent schema-versioned lineage-threaded capture bus (`OutcomeCaptureBus`→speed_feed.jsonl, 5 live SFC engines via `SFCOutcomeCaptureWireEngine`); residual-pairing consumer (`SFCParameterRefinementEngine`, lineage pairing + median-ratio clamps + IQR + confidence) — built, correct, starved + unwired; Page-Hinkley drift canary (`SFCDriftCanaryEngine`) + TTA + 5/25/100% canary ramp + circuit-breaker rollback (more sophisticated than quoting); Bayesian decision prior (`SpeedFeedPSNDecisionPriorEngine`, read-only); event schema already has recommended/actual/delta + chatter/Ra/cycle-time/override kinds.

**Absent/decorative:** the "DeepLearning/Ultimate AI" NN runs `Math.random()`-init weights, never trained — predictions are physics (Kienzle/Taylor/Merchant); the NN is not load-bearing (nn=12). Vendor fine-tune loop is display/return-only — no `vendor_delta` OutcomeKind, never fed back; HSMAdvisor/G-Wizard is EXPORT-only (no ingestion). india meta-bus integration = 0/4 canonical wires (`xproc_outcome_publish`, `xproc_kg_project_features`, `prism_knowledge:tribal_capture`, `xproc_calibration_monitor_record`) — SFC built a parallel slot-local bus (the anti-pattern `PER-SLOT-CLOSED-LOOP-INTEGRATION-2026-05-28.md` forbids).
