## OneDrive desktop redirect (the silent gotcha)

On this PC, OneDrive's "Back up this folder → Desktop" is ON. Consequence:

- `[Environment]::GetFolderPath('Desktop')` returns `C:\Users\wompu\OneDrive\Desktop` (NOT the local `C:\Users\wompu\Desktop`).
- The icons the operator visually sees on the Windows desktop are in `C:\Users\wompu\OneDrive\Desktop\`.
- `C:\Users\wompu\Desktop\` still exists as a legacy folder but is NOT what Windows displays.
- Writing a `.lnk` to the local desktop folder makes it INVISIBLE to the operator.

**Rule:** when creating or modifying desktop shortcuts on this PC, always target `C:\Users\wompu\OneDrive\Desktop\`. Use `[Environment]::GetFolderPath('Desktop')` to resolve dynamically.

## Resolved — `;` collision in wt commandline (2026-05-28 — FIXED)

**Status: CLOSED.** Both the `.bat` and the regenerator that emits it now use `-File slot-tab-boot.ps1 -Slot <name>` instead of `-Command "$env:...; %CLAUDE% ..."`. Verified in `regenerate-launch-fleet.mjs` lines 289-313 (`bootArgsForSlot`) — the `-File` form has zero `;` chars, so wt's action-separator parser cannot split mid-tab.

Original symptom (kept for history): every fleet tab failed with `0x80070002 ERROR_FILE_NOT_FOUND` referencing `H:\Tools\nodejs\claude.cmd --dangerously-skip-permissions '/checkin-<slot>'` as the executable path. Root cause: Windows Terminal's `;` action-separator parser did NOT honor the `;` between `$env:PRISM_BOOT_SLOT='alpha'` and `%CLAUDE%` as INSIDE pwsh's `-Command` quote scope — wt split there, treating `%CLAUDE% --dangerously-skip-permissions '/checkin-alpha'` as a new tab's commandline → CreateProcess rejected with FILE_NOT_FOUND.

The fix in both surfaces means future regens are SAFE. The boot script (`H:/Tools/prism-fleet/slot-tab-boot.ps1`) handles env vars + claude launch via `-File` arg parsing internally; direct `claude.exe` call bypasses the broken `claude.cmd → cmd.exe → claude.exe` indirection that also failed in fleet-tab pwsh context.
