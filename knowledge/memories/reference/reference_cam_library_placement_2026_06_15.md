**BUG FOUND + FIXED (R12, the destination-rule payoff -- "will it REACH the consumer?"):** `HyperMillToolExportEngine.fmt()` (`mcp-server/src/engines/HyperMillToolExportEngine.ts:582`) did `Number(n).toFixed(dec)` -> emitted bareword `"NaN"` for any tool with a missing/undefined numeric dim. In SQL that is (a) a parse error (`no such column: NaN`) and (b) a `NOT NULL` violation on `Tools.total_length` -- so the full-corpus `.hmt` build ABORTED, leaving a 3.3 MB truncated DB that LOOKED placed but was unusable. Fix: `const v = Number(n); return Number.isFinite(v) ? v.toFixed(dec) : "0";` (commit `[MAIN-FORCE] [JM-FULLCORPUS-PLACE]/U-HMT-NAN-FIX`). 14,849 NaN/Inf -> 0 in the placed corpus; rebuilt clean to 118,409 Tools. Mastercam (JSON.stringify -> NaN auto-coerces to null) + Fusion (NaN=0) needed NO exporter fix -- hyperMILL only, because its `.hmt.sql` is built by string-concat with no auto-coercion. Engine is CAM-galaxy (kilo); fixed under cross-galaxy permission, kilo sees it in git log.
