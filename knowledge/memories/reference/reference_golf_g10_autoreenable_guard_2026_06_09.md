**What it does:** the fleet-task-health watchdog now SELF-HEALS. In `runOnce`, after classification, it detects disabled crash-critical tasks and re-enables them automatically.
- `selectReenableTargets(classified, cfg)` [pure, exported] — returns task names SAFE to enable: `status==="disabled"` AND in `CRASH_CRITICAL_TASKS` AND NOT in `EXPECTED_DISABLED_TASKS` AND NOT under the HW-migration freeze. The testable invariant.
- `reenableTasks(targets, io)` [exported, `_spawn`-injectable] — runs `Enable-ScheduledTask -TaskName '<name>'` per target (NON-elevated works for user-owned PRISM tasks). A failed enable (needs elevation) returns `ok:false` WITH the real error — NEVER a false heal (R12). Empty targets fork ZERO shells (the every-Stop common case).
- Wired into `runOnce` (knob `PRISM_FTH_AUTO_REENABLE_DISABLE=1`; skipped on dryRun; `opts.reenabler` injectable). `row.autoReenable = {attempted,healed,failed}`; a heal logs a dedicated `task-health-autoheal` chat-bus entry (bypasses the WARN cooldown). Wrapped in try/catch so a re-enable failure can NEVER abort the audit (structural no-abort guarantee — arm-C P2).
- `buildAdvisory` (Stop hook `fleet-task-health-stop.mjs`) surfaces healed/failed inline ("auto-re-enabled N ... verify next audit" / "N still need an ELEVATED Enable-ScheduledTask"). Back-compat: a row without autoReenable renders the unchanged advisory.

**Soul alignment:** Enable-ONLY, never Disable (grep-confirmed no `Disable-ScheduledTask` in the diff). Restoring a known-good safety net is the INVERSE of the golf-soul refuse ("disabling own watchdog") and is explicitly permitted. The freeze + expected-disabled gates prevent fighting an operator's intentional disable.
