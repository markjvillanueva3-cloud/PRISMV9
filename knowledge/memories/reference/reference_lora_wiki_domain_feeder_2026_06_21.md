**3 LESSONS (compounding):**
1. **R8 / duplicationGuard SAVED a full rebuild -- "existence != content, read the body."** Two existing wiki->LoRA feeders already existed; reading their *bodies* (not just names) proved my premise ("no wiki-lessons lane") STALE and scoped mine to the disjoint subtree: `vault-lessons-to-lora-dataset.mjs` owns `code-tribal/learnings/**` (failure->fix), `wiki-canonical-to-training-pairs.mjs` owns `ideablock-v1` Q&A under `code-tribal/`+`architecture/`. Mine reads the curated domain PROSE dirs and EXCLUDES `architecture`(~36K auto-stubs)/`code-tribal`/`os`/`consensus`. The 4 feeders are now provably disjoint by source dir.
2. **REJECTED the cheap lane as low-signal (R12/R13 quality-over-volume).** The obvious move -- stream the 74K-entry `tribal-embed-index.json` (sharded; via `streamTribalEntries` O(1) heap) and emit a pair per entry -- was wrong: each entry stores only a 400-char flattened LEAD (a doc intro, not a reason-able Q->A), and the index is mostly the SAME wiki flattened. Reading the FULL section bodies off disk is the high-signal source. The cheap path is exactly the volume-over-signal trap vault-lessons-to-lora's own docstring warns against.
3. **scrutiny arm-A P1 -- a partial markup strip leaks junk.** A prose-residue gate that strips only inline `[text](url)` (then whitespace/markup chars) lets a ` ```bash ``` ` code dump, a `[[wiki backlink]]` wall, or an inline-code file-list survive with a large residue and emit a junk pair ("explain: Quick CLI usage" -> a shell transcript). FIX: strip ALL markup -- fenced code blocks, `[[..]]` backlinks, `[..](..)` links/images, `` `inline-code` ``, bare URLs -- BEFORE measuring prose; AND extend the heading blocklist with footer/process headings (Cross-refs/Related/Files changed/Live verification/Quick CLI usage/Bridge engines fed). Removed 118 junk pairs (2832->2714). The Owner-gate heading is excluded so owner-gated numeric/safety values never train the model (the wedm safety-critical promotion boundary).
