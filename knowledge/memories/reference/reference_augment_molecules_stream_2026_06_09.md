# augment-molecules off-heap streaming fix (2026-06-09, slot:sierra, U-VIZ-AUGMENT-MOLECULES-STREAM, commit ae55cea3f7)

**Symptom:** the system-viz on-commit chain (`scripts/system-viz-on-commit.mjs`) failed at stage **"augment molecules" (exit 1)** -- the SessionStart staleness inject showed "system-viz regen FAILED at augment molecules". This is golf's pre-assigned sierra follow-up (golf's note in `system-viz-on-commit.mjs:291`: "the merge fix + the streaming-augment rewrite are sierra's (system-viz) follow-up").

**Root cause:** `scripts/augment-molecules.mjs:40` did `readGraphStreaming(GRAPH)` which MATERIALIZES the entire ~523MB `system-graph.json` (all 333K nodes + edges) on the V8 heap -- but the script only ever read `G.nodes` filtered to layers **L5/L3/L9**, projecting `{id, layer, domain}` and NEVER touching edges. Under this machine's **432MB default V8 heap** (NODE_OPTIONS empty; `v8.getHeapStatistics().heap_size_limit` = 432MB, unusually small), materializing 523MB OOM'd at ~382MB (`FATAL: Ineffective mark-compacts near heap limit`). golf had raised the on-commit heap to REGEN_HEAP_MB=24576 so the spawned child got 24GB, but the stage was still fragile + OOMs under any default-heap invocation.

**Fix:** added `streamGraphArray(filePath, arrayKey, onElement)` to `scripts/lib/graph-io.mjs` -- reads the file as an OFF-HEAP Buffer and parses ONE top-level array element at a time (peak heap O(1 node)), sharing a new private `findArrayContentStart()` with `countGraphArrayStreaming` (refactored to use it; byte-identical behavior). Rewired augment-molecules to stream-project only the L5/L3/L9 nodes it needs (+ a `streamedNodeCount===0 -> exit 2` fail-loud guard). **LIVE: runs under the 432MB default heap, exit 0, 161 nodes / 12,432 molecules** (was OOM). 27/27 graph-io tests (+7 streamGraphArray incl parse-equivalence to readGraphStreaming, string-escape/structural-char, scalar, empty/missing, decoy-key). 3-of-3 scrutiny PASS (live parity stream-vs-count = 333,533==333,533; multibyte-UTF8 slice-safe; merge-augmentations output contract unchanged).

**Lesson (generalize -- fleet audit):** `readGraphStreaming(...).nodes.filter(...)` is an OOM antipattern when you only need to PROJECT a few fields per node -- it holds every element at once. Use `streamGraphArray(path, "nodes", onElement)` for projections. Same family as [[reference_regen_orchestrator_default_heap_oom_2026_06_09]] (off-heap count) + [[reference_viz_graph_truncation_atomic_fix_2026_06_09]] (atomic write).
