## THE FINDING -- live G-Wizard contributes 0 cells because the crib is geometry-only
The sweep's "GW/HSM contributed 0/24 per group" is NOT a comparator matching bug. VERIFIED: all **41,209** rows of the live `toolcrib.csv` have `sfm=0, ipt=0, mfgSFM=0`. G-Wizard stores per-tool GEOMETRY in the crib (diameter/flutes/coating/material) and computes speeds/feeds on-demand in its calculator UI -- it does NOT persist computed S/F back to the crib unless the operator explicitly saves per tool. So there is no live G-Wizard cutting datum to compare against, even though the adapter reads the 41K rows fine.

## What this means for the goal's comparison half
1. **vs published baseline (Sandvik/Kennametal/CNCCookbook/HSMAdvisor-public/Titans): COMPLETE** -- full 144-cell live sweep, deltas above.
2. **vs LIVE G-Wizard app: data-gated, not tooling-gated.** To get live G-Wizard NUMBERS requires operator action (populate computed S/F per tool in G-Wizard's UI -- hundreds of tools) OR driving G-Wizard's calc engine (closed Adobe-AIR desktop app, no API/CLI). Not forceable from PRISM's side.
3. **vs LIVE HSMAdvisor: data-gated, same root cause as G-Wizard (VERIFIED 2026-06-09).** HSMAdvisor IS installed (`%APPDATA%/HSMAdvisor/`) but every local file is definitions/preferences, NOT a queryable material->speed database: `settings_v2.xml` = UI prefs + override percentages (sfm_pc/ipt_pc=100), `machines.xml` (2.8MB) = machine definitions (1066 `<Tool`, machine specs), `user_tool_lib.tooldb2.xml` (116MB) = tool DEFINITIONS (`tool_material_id` + geometry, ZERO sfm/ipt/feed/speed/chipload cut-data tags). HSMAdvisor's material->speed engine that drives its recommendations lives in the app binary; the user AppData carries no computed cut data. So a live HSMAdvisor numeric comparison ALSO requires running the closed calculator (no API) -- same gate as G-Wizard. Every candidate local source was inspected; the gate is proven, not assumed.
4. **Richer published refs** require the Blackwell vision-OCR catalog pass (Kennametal Master 271MB/2032pp font-encoded) -> expand BASELINE_DB. That is the genuine multi-hour GPU unit.

## Lesson
"Blocked on external data" was imprecise. The comparison harness + live adapters were already built and run; the residual gap is that the live G-Wizard crib carries geometry only (sfm=ipt=0), so the comparison defaults to the published 5-vendor baseline. Always verify the SHAPE of the live data before declaring a comparison blocked -- the block was one CSV column being zero, not missing tooling.
