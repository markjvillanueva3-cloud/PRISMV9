**BUG FOUND + FIXED (bug-finding gate): hyperMILL .hmt `tool_length` floor-clamp (4a2f84eacc).** `HyperMillToolExportEngine.buildNCTool` computed `tool_length = max(oal - gauge, 10)`. The holder wire replaced the tool-scaled diameter gauge (50-100mm) with the REAL holder gauge (80-200mm); for the common case a short tool's OAL is LESS than the holder gauge, so `oal - gauge` went negative and silently clamped to the 10mm floor -- corrupting the assembled-tool length (a collision/gouge datum) on most rows. FIX: `tool_length` must derive from tool geometry ONLY (`oal - tool-scaled fallbackGage`); the real holder gauge belongs ONLY in `gage_length` (= `gaugeMm + stickout`, the true spindle-face-to-tip). **Lesson:** when you swap a tool-scaled quantity for a holder/fixture-scaled one inside a subtraction, the sign can flip -> silent clamp; decouple the two columns. Caught by per-file scrutiny (Claude reviewer empirically proved it), NOT by the happy-path test. **Why:** silent-data-corruption class, same family as the OCR truncation bugs. **How to apply:** never reuse one variable for both a tool-geometry gauge and a holder-projection gauge. [[feedback_always_update_wiki_on_bug_finding]]

**Ollama offload caveat (operator directive: use gpt-oss for grunt reads/scrutiny).** gpt-oss:120b puts its reasoning in the `thinking` JSON field, NOT `response`, when `num_predict` is low -> you get an EMPTY response and waste a round-trip. Set `num_predict>=3000` and read `j.response || j.thinking.slice(-N)`. For a small known-schema lookup (e.g. 4 column tokens) a deterministic `grep` beats the offload round-trips. gpt-oss also tends to ESCALATE theoretical reuse-collision findings round after round; pair it with a Claude reviewer (mutation-testing = the grounded arm) and resolve splits per R7 -- pick the more-tested verdict and close real concerns with fail-loud guards, not by argument. [[feedback_utilize_ollama_for_efficiency]]

**Injective-partition pattern (material->type->brand tooling DB, 96b7849416).** `scripts/lib/tool-library-partition.ts`: to organize free-text columns (tool type, vendor) into a directory tree WITHOUT silent merges, key the tree by the RAW (trimmed) values, then assign filesystem-safe slugs PER PARENT with a deterministic `-2`/`-3` suffix on collision (`injectiveSlugs`). Two distinct vendors that slug the same ("YG-1" vs "YG 1") get `yg-1.csv` + `yg-1-2.csv`, never one merged file. Sanitize controlled-enum path segments (`isoSegment` strips `[^A-Z0-9]` -> no traversal) and guard the enum is collision-free at startup (fail-loud). Generator emits `by-type-brand/<ISO>/<type>/<brand>.csv` reusing the proven `CSV_TOOLS_VERSION_1` Fusion format. Honest data note: most JM `tool_vendor` is blank -> filed under `unspecified` (never dropped); richer brand granularity = source from the 62K-tool corpus next.
