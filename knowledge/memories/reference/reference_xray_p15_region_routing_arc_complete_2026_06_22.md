P1.5 region routing (xray blueprint OCR) shipped end-to-end on cad-fusion-live-ms0, slot:xray, 2026-06-22:

- **region-classifier-lib.mjs** -- pure segment->route core, data-loss-safe (full_page on any untrusted segmentation).
- **region-glue-lib.mjs** -- `scaleBboxToPixels` (fractional->integer pixel crop), `mergeRegionResults` (recall-first UNION via `mergeTiledDimensions` + a whole-page overlap tile), `buildRegionRoutedFused`.
- **region-classify.mjs** -- `extractWithRegionRouting(opts, deps={})` DI orchestrator: full-page floor ALWAYS runs; region_route UNIONs per-region crops ON TOP (region routing can only ADD recall).

**The load-bearing design (R15 / dense-page rescue trainability):** the full-page floor is the recall guarantee; region routing's whole VALUE is the *dense-page rescue* -- a page the full-page VLM cannot read (0 dims, no summary) where cropped regions DO. For the **training cron** that rescue must stay TRAINABLE: `buildTrainsetRow`'s corroboration gate is `summary.n_models >= 2` (defaults 0 when summary absent). So `buildRegionRoutedFused(merged, fullFused, {fallbackNModels})` SYNTHESIZES `summary.n_models` from the region ensemble depth ONLY when the full-page summary is absent (a real full-page summary always wins); `summary.n_hallucination_candidates` recomputed over the union in every branch. `extractWithRegionRouting` captures the region depth via `nModelsOf` (max over region passes) -> `regionNModels` -> `fallbackNModels`. Commit `d13211934f` (U-XRAY-P15-DENSE-RESCUE-TRAINABLE).

**Both consumers wired (R15 wire-to-all):** (1) `validate-perfect-parts.mjs --region-route` (step 3a); (2) `blueprint-ocr-training-loop.mjs --region-route` (step 3b, commit `f93c14d6b1`) -- the per-page loop resolves `fused` from EITHER full-page ensemble (default, byte-identical when off) OR the region union; hybrid fused flows into buildTrainsetRow + classifyActiveLearning. Opt-in default-OFF leaves the running cron unchanged. Region crops strip the title block -> units forced to "in" (JM convention); floor unforced unless --force-units (parity with `pageForceUnit`).

**Empirical character (validated live, not speculation):** region routing is a DENSE-PAGE RESCUE, not a universal lift -- ~28 dims vs full-page's 0 on a dense 3400x2200 print, but ~0.43 baseline-parity on 05850 where the full-page already reads. Live cron smoke (`--region-route --real-png extrude_punch.png --calibrate-count 0`): region branch ran end-to-end, 12 labels via hybrid fused + 1 AL row (0 trainable = the calibrate-count-0 uncalibrated-tier artifact, not a routing defect).

**HONEST LIMIT (R12):** on a full-floor-failure rescue, region routing recovers DIMS but gdt/notes/finishes stay empty (the floor never read them). Data-loss-safe (never drops a label the floor DID read). A future per-region FULL-schema merge (gdt by FCF identity, notes by text) would close it.

**REASONED NEGATIVE RESULT (R12, GPU-free code audit 2026-06-23): the merge is NOT the bug.** `mergeTiledDimensions` (vision-tiling-lib.mjs:238-246) picks the clique representative by `confOf` ONLY, but `dimKey` (line 200) buckets by value -- a clique is either all-mm (every instance carries value_mm, same value within tol) or all-raw (none scoreable), so a scoreable floor dim and a non-scoreable instance NEVER share a clique. Floor dims ALWAYS participate in the union (region-glue-lib.mjs:144-148). Hence a scoreable floor dim CANNOT be dropped by the merge -> `merge_or_unit_dropped` is a near-impossible canary, not the likely cause. So the 05850 2/3-page drop is almost certainly `floor_failed_*` (the floor's full-page pass timing out under the heavier segment+floor+crops path on a contended GPU) OR VLM variance -- the new diagnostics will SHOW which on a multi-seed run.
