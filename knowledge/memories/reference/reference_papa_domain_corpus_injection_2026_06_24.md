**GIGO LESSON (3-of-3 arm C P1):** any pipeline that pipes `pdftotext` (or any binary-decoder) output into training data MUST strip C0/C1/DEL control bytes (`/[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]/g`) from BOTH the `output` AND the synthesized `instruction` (the title can carry them too) -- a broken-encoding/scanned PDF emits control bytes that poison the LoRA tokenizer. Latent (the current 65 decoded clean) but a rerunnable script over a growing PDF set WILL hit it. "GIGO-safe" must hold for ALL inputs, not just the batch you tested.
