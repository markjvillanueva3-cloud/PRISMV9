**U-XRAY-ENSEMBLE-NONDIM-UNION shipped (slot:xray, cad-fusion-live-ms0, commit `a783df2419`, 2026-06-23).**

**The finding (R8/R12 read-the-bodies):** `fuseEnsemble` (`scripts/lib/vision-ensemble-fuse.mjs`) fused **dimensions only** and returned `{dimensions, ambiguous_pairs, summary, per_model}` -- it SILENTLY DROPPED the `gdt / notes / profiles / surface_finishes` that each model's `parseVisionResponse` extracts (goal-critical for CAD reconstruction + quoting per the lib header). So the multi-VLM ensemble path discarded every GD&T frame, note, profile, and surface-finish callout it read. Worse: `buildRegionRoutedFused` (`region-glue-lib.mjs:178`) ALREADY ASSUMED the fused carried those fields (its `{...fullPageFused}` spread + docstring), so its pass-through silently propagated nothing -- a latent false-contract. NO consumer read `fused.gdt/notes/...` (the readers in run-ollama-vision-extract/probe/review read off a SINGLE-model `extraction`, not the ensemble fuse).

**What I almost built instead (avoided):** the backlog open-thread "per-region gd&t/notes full-schema merge for the rescue case" -- reading the bodies proved it would feed fields no consumer reads = an orphan. The real gap was upstream: the fuse drops them entirely.

**The fix (producer -> consumer, R13 logical order):**
- **Producer** `fuseEnsemble`: new pure helpers `nonDimKeyNorm/numKeyPart/gdtKey/noteKey/profileKey/surfaceFinishKey/fuseNonDimField`. Recall-first cross-model UNION of the 4 non-dim fields, de-duped by per-field identity (gdt = FCF identity: symbol+tolerance_value+material_condition+SORTED datum_references+applied_to; notes = category+text; profiles = name+type+w/h/dia; finishes = ra_um|raw_text + location). Each entry KEPT (singletons never dropped) + tagged `corroboration/n_models/models/hallucination_candidate` (mirrors the dimension trust metadata; single-model run never false-flags = `corroboration===1 && nModels>=2`). Representative = highest-confidence member, ties -> first model (deterministic). Order = corroboration-desc then identity-key-asc (content-derived -> input-order-independent). New `summary.n_gdt/n_notes/n_profiles/n_surface_finishes`. STRICTLY ADDITIVE (existing dims/summary consumers byte-unaffected).
- **Consumer** `buildTrainsetRow`/`aggregateTrainingLoop` (`ocr-training-loop-lib.mjs`): record `gdt_count/note_count/profile_count/surface_finish_count` + roll up `non_dim_coverage`.
- **Runner wire** `blueprint-ocr-training-loop.mjs`: writes the counts into the trainset JSONL row AND a `this_run_non_dim_coverage` report block; per-page accumulation runs for EVERY ensembled page (independent of trainable>0).

**Scrutiny caught a REAL orphan (the load-bearing lesson):** per-file arm B FAILED the consumer half -- the runner hand-rebuilds the JSONL row with a fixed field set and builds its report inline (never calls `aggregateTrainingLoop`), so the counts I added to the lib were COMPUTED AND DROPPED at the runner. 29/29 green coexisted with a dead destination because the tests were lib-level. Fixed by wiring both runner write sites; the wiring is the unit, not the lib counts. Lesson: a "consumer" that the runner doesn't actually persist is itself an orphan -- verify the destination is REACHED (R15 ultimate-destination), not just that a lib function returns the value.

**Validation:** vision-ensemble-fuse 43/43 (10 new union tests: happy + 4 failure + 3 adversarial incl order-insensitive datums, recall-first singleton-kept, single-model no-false-flag, determinism, rep-by-confidence) + ocr-training-loop-lib 29/29 (3 new). Consumer regression sweep green (region-glue 22, region-classify 17, tiling-extract 14, tiling-lib 24). Per-file 2-arm scrutiny each file + end 3-of-3 (A+B+C all PASS, P2-only). **LIVE (R15 prove-with-numbers):** dense JM scans full-page ensemble-FAILED (the documented ~15% hard-scan class -- a model-read limit, not wiring); a clean SYNTHETIC print through the runner produced report `this_run_non_dim_coverage {gdt:1,notes:1,profiles:0,surface_finishes:1}` -- non-zero, proving the union -> buildTrainsetRow -> per-page accumulation -> report destination end-to-end.

**What this does NOT do (honest scope, R12):** counts only -- GD&T is NOT a trained label yet. The NEXT unit is GD&T/notes label-tiering (extend buildTrainsetRow to emit trainable gdt/note labels with their own corroboration tiers) so the closed-loop corpus trains GD&T reading, not just records its reach. The region-route RESCUE case (dense page, full-page floor fails -> 0 dims AND 0 gdt) still yields empty gdt/notes because `mergeRegionResults` is dims-only; the per-region full-schema merge (gdt by FCF identity) remains the documented open refinement for that path (now the full-page-SUCCESS baseline carries gdt/notes via this union). Deferred P2s: `profileKey` under-merges name-only profiles; runner inline tally vs `aggregateTrainingLoop` (equivalent, could unify); `confidence:null` rep carries null (vs DEFAULT_DIM_CONF).

**Test-state side effect (harmless):** my live runs appended 3 temp-basename entries to `state/shared/ocr-training-loop/processed-cursor.jsonl` (2 dense scans skipped-ensemble-failed + 1 synthetic) + overwrote `training-loop-report.json` with the synthetic test run. Temp basenames never collide with the real worklist (original-PDF basenames); the report regenerates on the next nightly cron. No trainset rows written (calibrate-count 0 -> uncalibrated -> not trainable).
