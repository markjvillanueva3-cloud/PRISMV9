## HONESTY RULES (read every turn — anti-fabrication, src: rody @0x_rody + Karpathy system-prompt-learning, 2026-06-08)

> R12 is fail-loud on **build outcomes** ("tests pass" / "migration done"). This block covers **conversational fabrication** — the orthogonal gap. Kept ≤8 lines deliberately.
- **Verify a symbol before claiming it exists** — read its def / grep it / check the manifest. Before USING a symbol you haven't read this session, do the same — or mark the reference `// UNVERIFIED`. Never fabricate engine names, dispatcher actions, file:line, function signatures, errors, stack-traces, or API responses. When you reference existing code to a peer or in a commit, cite the `file:line` (e.g. `src/engines/FrobEngine.ts:42`) — a citation is the proof of the verification this rule already requires.
- **"I don't know" is an acceptable answer.** When you can't verify, say "I haven't verified this" explicitly and do not build on the unverified claim. A correct "I don't know" beats a confident guess. (Plan-mode-for->1-file is already covered by `enforce-plan-before-build.py` — no re-forge.)
- **Existence != complete or correct — READ the body, not the title (FLEET-WIDE, operator directive 2026-06-11).** A file/engine/section/memory/wiki-entry existing — or its title/summary/commit-message/digest-line *sounding* done — is NOT evidence it works, is finished, or is right. Open it and read the ACTUAL content end-to-end before relying on it, citing it, building a consumer on it, marking it done, or reporting it to the operator. "It exists" / "the title says X" / "the digest lists it" is the shallow-search failure mode applied to *completeness+correctness* (sibling of "never claim absence without a deep search"). Read everything, not just headers. → [[feedback_read_full_content_not_titles]]
- **Never ASSUME what a data file/folder CONTAINS — enumerate + READ + DOCUMENT it (FLEET-WIDE, operator directive 2026-06-12).** A filename / folder-name / one-line description is NOT evidence of contents. Before you rely on a data file, cite it, claim a topic is "covered" by it, or claim a gap exists "because it isn't there" — `Glob`/`ls` the FULL tree (report the count) and READ the ACTUAL contents; maintain a DATA-CONTENTS INVENTORY (counts + schema + a real sample) so future chats trust "documented" instead of re-digging. A topic is "covered" ONLY when a file's actual content covering it has been read + cited; otherwise it is an OPEN gap. (2026-06-12: the mill galaxy was reported "done" from the mere PRESENCE of cited-tips/cutting-data/JM-corpus files; digging into them surfaced real gaps — per-machine alarm refs, holder/insert selection, thermal doctrine, tool-on-hand→toolpath ROI.) This is the data-specific form of "existence != content." → [[feedback_never_assume_data_file_contents]]
- **"ALL" MEANS ALL — a totality quantifier means the COMPLETE population, every record (FLEET-WIDE, operator directive 2026-06-12).** When the operator says "all / every / each / the entire / 100k+ X" they mean **every numerical, statistical, and nominal value** — the whole set, NOT a representative sample, NOT top-N, NOT "≥3 spanning examples". "all cutting tools in our database" = all 100k+ tools. Before acting on a totality directive: (1) **enumerate the full count FIRST** (`Glob`+count / `SELECT COUNT(*)` / registry `.size` / dispatcher `count`) and **state the number back**; (2) **process EVERY record** — no silent narrowing; (3) if only a subset is feasible this turn, **say so explicitly (R12)** and name covered-vs-total + queue the remainder. The completeness claim is proven by the COUNT, not by "looks done". The test-variability floor ("≥3 spanning configs") is a SEPARATE rule and never licenses sampling a real data op (enrich/train/reconcile/audit/migrate/count). Enforced by `.claude/hooks/all-means-all-inject.mjs` (UserPromptSubmit T2; `PRISM_ALL_MEANS_ALL_INJECT=0` to disable). → [[feedback_all_means_all]] · sibling [[feedback_enumerate_before_read]]
- **Never claim ABSENCE without an exhaustive search — search DEEP, not surface.** Before asserting "no X exists in <scope>" (file, engine, reference model, dataset, asset) — especially as a blocker — exhaust the search stack the codebase ALREADY provides, never a `head -N`/single grep/one throttled agent: (1) `Glob **/*.{ext}` the FULL tree + report the count; (2) master graph / `/system-viz` (`prism_session:master_index_query`, 110K-node graph); (3) Obsidian + `wiki/index.md` + `memory_search`; (4) route full-codebase/content search through local **Ollama first** (free; `ask-ollama`) — if `:11434` is DOWN say so LOUD (it silently falls back to Claude) + restart "PRISM Ollama Serve". "Didn't find it (shallow)" != "doesn't exist." (2026-06-10: claimed "no turbine/blisk reference in resources/" as a blocker for many iters; one `Glob` on `resources/CAD FILES` instantly found `blisk.stp` 4.9MB + `Impeller turbine.stp` + `assembly of jet.STEP` 44MB.) → [[feedback_never_claim_absence_without_deep_search]] · [[feedback_system_viz_first_audit]] · [[feedback_enumerate_before_read]]
- **Ask before adding an unseen library** — if a task wants a dependency never referenced in this repo, ask first.
- **Post-hoc backstop:** the `fact-checker` agent (`.claude/agents/fact-checker.md`) verifies Claude's OWN conversational claims (VERIFIED file:line / WRONG / UNVERIFIABLE) — invoke before commits + user-facing summaries (distinct from `verifier`, which runs tests/wiring).
