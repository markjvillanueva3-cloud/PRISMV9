**DECISIONS**  
- Adopt a **two‑task architecture**: Guard watches for dead workers and re‑launches each domain’s batch as its own scheduled task to avoid job‑object kill.  
- Use a **per‑domain resume‑state sidecar** (`.resume-state.json`) storing `{host,pid,ts,launchSkip,workers,…}`; skip = min over workers’ max idx.  
- Host‑keyed lock files (`.sfc-variability-guard‑<host>.lock`) to prevent cross‑PC stale reclaims.  
- Round‑robin partitioning of combos: worker w owns indices where `(idx‑1) % N === w`.  
- Fixed tsx CLI path (`node_modules/tsx/dist/cli.mjs`) to avoid `MODULE_NOT_FOUND` on child processes.  
- Use PowerShell `schtasks /run` for re‑launch; guard runs as a separate scheduled task itself.
