## Real risks I can see

**1. Currently-open chats vs resume UUIDs — this is the biggest one**

Your 18 chats are currently running. The bat resumes 19 chats via `claude --resume <session-uuid>` — those UUIDs are the **same** transcript files (`~/.claude/projects/H--prism/<uuid>.jsonl`) that your live chats are writing to right now. When the new chat tries to open that .jsonl while the old one holds it, you get one of:
- File-lock error → claude exits
- Two claudes writing the same transcript → corrupted state, slot-bind-enforce races
- Silent "session not found" if the jsonl is renamed during the live chat's `/compact`

The bat is designed for **cold-start** (after a system reboot, no claude.exe running). If you double-click it while the fleet is alive, expect breakage.

**2. Self-elevation argv quoting**

```bat
powershell -NoProfile -Command "Start-Process -FilePath '%~f0' -Verb RunAs -ArgumentList '%*'"
```
- `%~f0` expands to `C:\Users\wompu\OneDrive\Desktop\LAUNCH-PRISM-FLEET.bat` — contains spaces. Wrapping in single quotes works inside the PS `-Command` string, but argv-passthrough via `%*` could break if there are any args (there aren't on double-click, but if you run it from a shell with args, untested).
- After elevation succeeds the non-elevated parent does `exit /b 0` — clean exit.
