The registry flip is applied. Your default terminal is now **Windows Terminal** (the modern one) instead of **ConHost** (the legacy one). The current ConHost window you're in is unaffected — but **the next terminal you launch will open in Windows Terminal**, and Claude Code running inside it will let you scroll freely during streaming output.

### How to land in the new terminal

1. **Don't close this current Claude session yet** if you want to keep it. The current ConHost shell stays ConHost until it exits.
2. **Open a NEW terminal** by any of these — they'll all now open Windows Terminal:
   - Win + R → `pwsh` → Enter
   - Start menu → PowerShell
   - Right-click desktop → "Open in Terminal"
   - Win + X → Terminal
3. In that new window: `claude` to start a fresh session. Streaming will now be scrollable.

### Useful Windows Terminal scroll shortcuts (work during streaming)

| Action | Keys |
|---|---|
| Scroll one line | Ctrl + Shift + ↑ / ↓ |
| Scroll one page | Ctrl + Shift + PgUp / PgDn |
| Jump to top / bottom of scrollback | Ctrl + Shift + Home / End |
| Find in scrollback | Ctrl + Shift + F |
| Mark mode (select without mouse) | Ctrl + Shift + M |
| Open new tab | Ctrl + Shift + T |

Scroll wheel also works during streaming in Windows Terminal — that's the key difference from ConHost.

### Why this was the cause (one-liner)

Claude Code uses Ink → alternate screen buffer. ConHost's alternate-buffer scrollback is broken on most builds (it locks scroll while an app is actively repainting). Windows Terminal handles alternate buffer correctly — scrollback stays usable mid-render.

### Revert (if you ever want to go back to ConHost)

Set-ItemProperty 'HKCU:\Console\%%Startup' -Name DelegationConsole  -Value $z
