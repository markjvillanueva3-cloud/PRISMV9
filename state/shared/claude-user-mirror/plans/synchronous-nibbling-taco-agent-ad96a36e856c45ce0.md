### CATEGORY 2 — AUTOMATION CENTER (AC) SCRIPTS

**AC-01: prism_job_setup.py** (TEMPLATE — generated by HyperMillCodeGeneratorEngine)
- What: Sets up a complete hyperMILL job from PRISM parameters: coordinate system, stock definition, safety planes, machining tolerance, job name
- Input (at generation time): PRISM job parameters (part origin, stock dims, tolerance, material)
- Output (when run in AC): Configured hyperMILL job ready for operation addition

- Gap: HyperMillCodeGeneratorEngine already has `job_setup` template category, but no test fixture verifies the generated Python is syntactically valid AC Python

## KEY ARCHITECTURAL NOTES

### USB Key Boundary
- Offline (no key): EX-01 through EX-07, BR-01 through BR-06, all UT scripts, AC script generation
- Live hyperMILL (key required): AC-01 through AC-10 execution, any script using `import om.cam`

### The om.cam API Pattern (from reading StockCalculate.py)
```python
import om.cam.core as core
import om.cam.gui as ui
# Guard: must check hyperMILL is running
if core.IsHyperMillRunning() != True: sys.exit(-1)
doc = om.Application().CurrentDocument.CamModel
```
All generated AC scripts must start with this guard. HyperMillCodeGeneratorEngine should include this header in every generated script.

### IM_Macro_DB vs Standard TDB
The Intelligent Macro system uses a completely separate database schema from the standard tool database. MacroType entries (HOLE, SINK1-3, BACKSINK1-3) map to feature-based drilling/boring/countersinking workflows. These are not covered by any current PRISM engine action and represent a gap in the drilling/holemaking pipeline.

### NcGenerator Config Encoding
The 98 omPP*.xml files are binary-encoded (confirmed by hex inspection — not XML despite extension). The filename heuristics are reliable: `omPPF` = Fanuc, `omPPBr` = Brother, `omPPDeZ` = DMG/Deckel, `omPPFgr` = Fanuc-grinder variants. UT-06 can map controllers from filenames alone without parsing the binary content.
