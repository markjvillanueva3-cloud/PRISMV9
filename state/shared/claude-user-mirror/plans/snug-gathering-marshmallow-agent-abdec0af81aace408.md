# AS9100 / NADCAP Compliance Audit Report -- PRISM v9 Quality System

**Audit Date:** 2026-03-25
**Auditor Role:** AS9100 Rev D Quality Systems Auditor
**Scope:** Frontend quality module readiness for aerospace machine shop deployment
**Files Reviewed:**
- `web/src/pages/QualityPage.tsx` (SPC / Cpk / Tolerance Stack calculator)
- `web/src/pages/QualityManagementPage.tsx` (KPIs, calibration, NCR, traceability, FAI, material certs)
- `web/src/pages/CompliancePage.tsx` (standards templates, gap analysis, audit trail)
- `web/src/pages/SafetyDashboardPage.tsx` (machining parameter safety validation)
- `web/src/pages/ReportsPage.tsx` (report generator: safety audit, setup sheet, cost estimate)
- Supporting types: `api/shopTypes.ts`, `api/quality.ts`, `api/compliance.ts`, `types/compliance.ts`

---

## EXECUTIVE SUMMARY

PRISM v9 has **promising scaffolding** for a shop-floor quality system. It contains stubs for SPC, calibration tracking, nonconformance reports, first article inspection, material certification, traceability, and compliance gap analysis. However, when evaluated against AS9100 Rev D (based on ISO 9001:2015 with aerospace supplements) and NADCAP requirements, the system has **critical structural gaps** that would produce major nonconformances in a registrar audit. The system is currently at a **prototype / demonstration maturity level** and is not audit-ready.

**Overall Verdict: WOULD FAIL an AS9100 Stage 2 audit.**

## SECTION-BY-SECTION ANALYSIS

### 1. TRACEABILITY (AS9100 clause 8.5.2 -- Identification and Traceability)

**What exists:**
- `QualityManagementPage.tsx` has a "Traceability" tab that accepts a Job ID and calls `qualityTraceJob()`.
- A "Material Cert" tab can look up a heat/lot number via `qualityMaterialCert()` and `qualityTraceHeatLot()`.
- The `MaterialCert` type includes `heat_lot`, `material`, `supplier`, `certifications`, `properties`, and `verified`.

**What is MISSING (audit failures):**

| Gap | AS9100 Clause | Severity |
|-----|---------------|----------|
| No linkage chain visible: material cert -> receiving inspection -> job -> operation -> inspection record -> shipment. The trace tab dumps raw JSON; there is no structured forward/backward trace UI. | 8.5.2 | MAJOR |
| No lot/serial number assignment at receiving. No receiving inspection workflow at all. | 8.4.2, 8.6 | MAJOR |
| No indication that material cert verification is mandatory before releasing material to production. The "verified" boolean has no enforcement mechanism. | 8.4.2 | MAJOR |
| Heat lot trace output is raw JSON (`JSON.stringify`), not a structured traceability matrix linking material -> jobs -> parts -> customers. | 8.5.2 | MAJOR |
| No shelf-life or special-storage tracking for materials that require it (e.g., sealants, adhesives in aerostructure work). | 8.5.4 | MINOR |
| No customer property identification (customer-furnished material/tooling per 8.5.3). | 8.5.3 | MAJOR |

**Auditor note:** In aerospace, you must be able to start from a finished part serial number and trace backward to the raw material heat lot, incoming inspection record, material test report, and supplier cert -- AND start from a suspect heat lot and trace forward to every affected part/customer. The current system has the API stubs but no structured UI to demonstrate this bidirectional trace.

### 2. REVISION-CONTROLLED DOCUMENTS (AS9100 clause 7.5 -- Documented Information)

**What exists:**
- `CompliancePage.tsx` references compliance templates with a `version` field.
- The `ComplianceTemplate` type has `id`, `standard`, `version`, and `requirements[]`.

**What is MISSING (audit failures):**

| Gap | AS9100 Clause | Severity |
|-----|---------------|----------|
| **No document control system at all.** There is no concept of controlled documents (work instructions, procedures, quality manual, inspection plans) anywhere in the reviewed code. | 7.5.2, 7.5.3 | MAJOR |
| No revision history tracking on any entity. The compliance template has a `version` string but no change log, effective date, or obsolescence mechanism. | 7.5.2 | MAJOR |
| No approval workflow for document changes. No concept of "draft -> review -> approved -> released" status for any document. | 7.5.2 | MAJOR |
| No mechanism to prevent use of obsolete documents on the shop floor. | 7.5.3.2 | MAJOR |
| No electronic signature / authentication for document approval (21 CFR Part 11 considerations if FDA-adjacent work, but also AS9100 requirement for controlled release). | 7.5.2 | MAJOR |

**Auditor note:** This is the single largest gap. AS9100 requires a documented Quality Management System (QMS) with controlled procedures for every process. PRISM has zero document control infrastructure.

### 4. FIRST ARTICLE INSPECTION -- AS9102 (AS9100 clause 8.6)

**What exists:**
- `QualityManagementPage.tsx` has an FAI tab showing a list and a creation form.
- The `FAI` type has: `id`, `part_number`, `job_id`, `characteristics[]` (with `name`, `nominal`, `actual`, `tolerance`, `pass`), `overall_pass`, `inspector`, `date`.
- FAI creation form collects `part_number`, `job_id`, `inspector`.

**What is MISSING (audit failures):**

| Gap | AS9102 Form | Severity |
|-----|-------------|----------|
| **No AS9102 Form 1 (Part Number Accountability).** The standard requires: part number, part name, serial number, drawing number, drawing revision, organization name, purchase order, and detailed header info. None of this exists. | Form 1 | MAJOR |
| **No AS9102 Form 2 (Product Accountability -- Materials/Processes).** Must include: raw material specification, material supplier, heat lot/batch, special processes (heat treat, NDT, plating), and process source approval. Completely absent. | Form 2 | MAJOR |
| **AS9102 Form 3 (Characteristic Accountability) is partially present** -- the `characteristics[]` array has nominal/actual/tolerance/pass. But it is missing: characteristic number (balloon number), drawing zone, specification limits from drawing, GD&T feature control frame references, measuring instrument used, and gage ID (for calibration traceability). | Form 3 | MAJOR |
| No concept of partial/delta/full FAI types. AS9102 requires that you can perform a partial FAI when only certain characteristics change (e.g., after a drawing revision). | AS9102 sec 4 | MAJOR |
| No FAI approval workflow. No fields for QA approval, customer approval, or engineering sign-off. | AS9102 sec 5 | MAJOR |
| No linkage from FAI characteristics to the measuring instrument used and its calibration status. | AS9102 Form 3 | MAJOR |
| No PDF/report export in AS9102 format. | -- | MAJOR |
| No drawing balloon reference system. | AS9102 Form 3 | MAJOR |

**Auditor note:** The FAI as implemented is essentially a pass/fail checklist with dimensions. AS9102 is a three-form package that provides complete accountability from part identity through material/process to individual characteristic measurement. The current implementation covers roughly 15% of what AS9102 requires.

| Gap | AS9100 Clause | Severity |
|-----|---------------|----------|
| No calibration certificate storage or linking. In aerospace, you must have the certificate from the calibration lab on file and linked to the equipment record. | 7.1.5.2 | MAJOR |

## ITEMS THAT WOULD FAIL AN AS9100 STAGE 2 AUDIT

Listed by clause, each of these would be written as a Major Nonconformance by a registrar:

1. **Clause 7.5 -- No document control system.** No controlled procedures, no revision control, no approval workflows, no obsolescence management.

2. **Clause 8.5.2 -- Traceability is incomplete.** No bidirectional trace (material cert -> receiving -> job -> inspection -> shipment -> customer). The JSON dump is not acceptable evidence.

3. **Clause 8.6 -- FAI does not meet AS9102.** Missing Forms 1 and 2 entirely. Form 3 lacks balloon references, instrument ID, and drawing zone.

4. **Clause 7.1.5 -- Calibration system is incomplete.** No certificate storage, no uncertainty, no NIST traceability, no as-found/as-left, no GRR/MSA.

5. **Clause 8.7 / 10.2 -- NCR system lacks containment, root cause, corrective action, MRB workflow, and closure verification.**

6. **Clause 10.2 -- No CAPA system exists.**

7. **Clause 9.2 -- No internal audit program.** The compliance audit trail is a check-score, not an internal audit management system.

8. **Clause 9.3 -- No management review process.**

9. **Clause 8.4 -- No supplier quality management.** No receiving inspection workflow, no supplier audit tracking, no SCAR process.

10. **Clause 7.2 / 7.3 -- No competence and awareness records** (operator qualification, training records linked to quality operations).

11. **Clause 6.1 -- No risk management framework** (no PFMEA or process risk register).

## WHAT PRISM v9 DOES WELL (credit where due)

- **SPC and Cpk calculations** are present with correct statistical structure.
- **Tolerance stack analysis** with three methods (worst case, RSS, Monte Carlo) is a strong engineering tool.
- **Safety validation** for machining parameters (speed/feed/depth/coolant) is unique and valuable, though it is operational safety rather than AS9100 quality.
- **Quality KPIs** (first pass yield, scrap rate, NCR count, calibration compliance) are the right metrics to track.
- **Material cert lookup by heat lot** shows the right thinking about traceability -- it just needs to be connected end-to-end.
- **NCR severity/disposition taxonomy** is correct (minor/major/critical; rework/scrap/use-as-is/return-to-vendor).
- **Compliance gap analysis concept** is architecturally sound -- it just needs AS9100 templates and real enforcement.
- **Calibration status color coding** (current/due_soon/overdue) is good visual management.

## RECOMMENDED REMEDIATION PRIORITY

### P0 -- Must fix before any aerospace work (blocks certification)

1. Build a **document control module** -- revision tracking, approval workflow, controlled distribution, obsolescence.
2. Implement **full AS9102 FAI** (all three forms) with PDF export.
3. Add **CAPA/corrective action workflow** to the NCR system -- containment, root cause, corrective action, effectiveness verification.
4. Build **bidirectional traceability chain** -- material cert to finished part to customer shipment, and reverse.
5. Add **calibration certificate storage**, NIST traceability chain, as-found/as-left readings, and out-of-calibration impact assessment.
6. Add **user identity and audit logging** on every quality record create/modify/delete.

### P1 -- Required for surveillance audits and customer satisfaction

7. Add AS9100 to the compliance standards list.
8. Build **MRB workflow** for use-as-is / repair dispositions.
9. Build **Certificate of Conformance (CoC)** generator.
10. Connect SPC to production data (not manual paste-in).
11. Build **internal audit scheduling and management**.
12. Implement **electronic signature** for quality record approvals.

### P2 -- NADCAP readiness

13. Add GRR/MSA (Gage Repeatability & Reproducibility) studies.
14. Add PFMEA (Process Failure Mode and Effects Analysis) module.
15. Add **special process tracking** (heat treat, NDT, plating) with NADCAP cert verification.
16. Add **key characteristic tracking** per AS9103.

## CONCLUSION

PRISM v9 has the architectural skeleton of a quality system -- the right tabs, the right API endpoints, the right general categories. But every subsystem stops at the surface level. An AS9100 registrar audits not just "do you have the feature" but "does the feature enforce the requirement" -- meaning approval gates, mandatory fields, immutable audit trails, and bidirectional traceability. In its current state, PRISM would receive 8-10 major nonconformances in a Stage 2 audit, and certification would be denied. The mock/hardcoded data in the reports module would be particularly damaging to credibility.

The good news: the architecture is extensible. The API patterns (`api/shop.ts`, `api/quality.ts`, `api/compliance.ts`) and the type system (`shopTypes.ts`, `compliance.ts`) show a clean separation of concerns. The remediation is additive -- enriching existing types with mandatory fields, adding workflow state machines, and connecting the dots between subsystems -- rather than a rewrite.
