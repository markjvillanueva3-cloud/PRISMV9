Virtual Tool Format Reference
Purpose of this document
This document describes the XML format to define a virtual tool. It is an internal document
and therefore it has no guarantees for the content to work rightly in hyperMILL.
Principle of working with Virtual Tool
In hyperMILL macro database you can connect a macro job with a real reference tool in
hyperMILL tool database. There are three modes to use this reference tool:
• DB Mode -- the reference tool is used in applied job directly
• DB+Auto Mode (for hole only) – Search filter is derived from the reference tool (type,
diameter, folder). Length will be calculated based on the hole data automatically
• DB+Auto+ Mode (for hole only) – Search filter is derived from the reference tool
(type, folder). Diameter and length will be calculated based on the hole data
automatically
All three modes can’t find tool if the reference tool is not existed in the tool database. This
means that the macro is linked in a certain tool database. It is not possible for one macro
database to work with multiple tool databases.

Virtual tool concept provides an intelligent way to find the right tool in applying time.
Basically a virtual tool is defined with an ID and a search filter. A macro job can reference a
virtual tool with this ID (Step1). The macro configurator tries to find a real tool in tool
database using search filter and saves the searching result in a virtual-real tool mapping
table (Step2). The tool mapping table is used then in the macro apply function. As a result
the resulted tool is set in the applied job (Step3).
How to use Virtual Tool
Two steps have to done in order to use virtual tool:
• The virtual tool definition file has its own extension “.vtx”, however the file name has
to be the same as macro database and the location is also the same.
• Tool data mode should be set to VT (Virtual Tool) and the Tool no. is the ID of used
virtual tool.

The UML diagram shows the most of important elements in Virtual Tool Definition File which
is written in XML format. Following segment shows an overview.
<?xml version="1.0" encoding="UTF-8"?>
<Vtdbx Version="1.0">
<Settings>
</Settings>
<VirtualTools>
<VirtualTool Id = "Drilling" Name = "Drilling tool" Comment = "">
<ToolTypes>
<ToolType Type = "drillTool"/>
</ToolTypes>
<SearchFilters>
<RuleFilter Condition = "" Value = "MillingTool.Diameter = Connector.Diameter" />
<RuleFilter Condition = "" Value = "NCTool.UsableLength &gt; Connector.Length" />
</SearchFilters>
</VirtualTool>
</VirtualTools>
</Vtdbx>
Special Character in XML:
Character ‘>’ and ‘>’ are used in XML Tag definition therefore they have to be written in:
&gt; for character ‘>’ (great than)
&lt; for character ‘<’ (less than)

PreSearchAction
Attribute: None
Parent Element: VirtualTools
Children Element: Action
Diese Funktion wird vor der eigentlichen Werkzeugsuche ausgeführt. Innerhalb dieser
Funktionen können Variablen definiert oder DecsionsTables aufgerufen werden.
Für die Definition steht der Befehl <Action> zur Verfügung.
Action
Attribute: Condition, Type, Name, Value
Parent Element: VirtualTools
Children Element: Action
Es stehen drei unterschiedliche Action Typen zur Verfügung
SetUserVariable: Definition einer BenutzerVariablen mit „Name“ und „Value“. Die Benutzervariable
kann nur innerhalb der Makrozuordnung und Werkzeugsuche verwendet werden. Benutzervariablen
die vor der Makrozuordnung nicht definiert waren werden wieder gelöscht.
SetJobCfg: Bei der Übernahme der Arbeitsschritte aus dem Makro können Jobparameter
überschreiben werden. Definition mit „Name“ und „Value“
DesicionTable: Aufruf einer Entscheidungstabelle. Name der Tabelle wird in der „Id“ definiert.
Beispiel
<PreSearchActions>
<Action Condition = "" Type="SetUserVariable" Name="ToolId" Value="Zentrierbohrer" />

-- 6 of 21 --

<Action Condition = "" Type="DecisionTable" Id = "ToolTypeSelect"
</PreSearchActions>
Action 1: hier wird die UserVariable „ToolId“ auf den Wert „Zentrierbohrer“ gesetzt. Damit
kann in der DecisionTable „ToolTypeSelect“ der Suchpfad für den benötigten
Werkzeugordner gesetzt werden.
Action 2: Aufruf der DecisionTable „ToolTypeSelect“. Innerhalb dieser Tabelle wird der
Selectionspfad für die Werkzeugsuche an die unterschiedlichen Werkzeugdatenbänke
angepasst. Der Pfad wird dann als Selectionsfilter verwendet mit dem die Reihenfolge
definiert werden kann welche Werkzeug verwendet wird in dem Fall das mehrere
Werkzeuge die Bedingung erfüllen.
RuleFilter
Attribute: Condition, Value
Parent Element: SearchFilters
Children Element: None
Rule filter is one of types of search filter. More than one rule filter can be defined for one
virtual tool, which are combined together with “And” logic. A rule filter can own condition
which is involved in searching tool only if the condition is true. The following example show
to find a drilling tool with the defined diameter bases on the current hole diameter:
Hole Diameter 5 > D >=1 10 > D >=5 20 > D >=10 D >= 20
Tool Diameter 4 8 15 25
<SearchFilters>
<RuleFilter Condition = "Connector.Diameter &gt;= 1 And Connector.Diameter &lt; 5"
Value = "MillingTool.Diameter = 4" />
<RuleFilter Condition = "Connector.Diameter &gt;= 5 And Connector.Diameter &lt; 10"
Value = "MillingTool.Diameter = 8" />
<RuleFilter Condition = "Connector.Diameter &gt;= 10 And Connector.Diameter &lt; 20"
Value = "MillingTool.Diameter = 15" />
<RuleFilter Condition = "Connector.Diameter &gt;= 20"
Value = "MillingTool.Diameter = 25" />
</SearchFilters>

Parent Element: SearchFilters

PostSearchActions
Attribute: None
Parent Element: VirtualTool
Children Element: ToolFound, ToolNotFound
A post search action is the action which is implanted after searching tool. Basically there are
two kinds of post actions: “ToolFound” where the defined action is fired if a matching tool is
found and “ToolNotFond” in the other situation.
PostSearchAction
Attribute: Condition, Type, Name, Value
Parent Element: ToolFound or ToolNotFound
Children Element: None
There are three action types:
SetUserVariable: A user variable is set with attribute “Name” and “Value”.
SetJobCfg: A CFG parameter in job is set with attribute “Name” and “Value”.
DecisonTable: The action is defined in a decision table.
If a job Parameter is defined with formula then its formula CFG has to be set to empty. The
formula CFG is defined with [internal property name]_F. For example, the Nominal diameter
(CFG: *NOMINAL_DIAMETER) is defined with formula “T:Ndia”, its formula CFG is:
NominlaDiameter_F:
<Action Type="SetJobCfg" Name="*NOMINAL_DIAMETER" Value="5" />
<Action Type="SetJobCfg" Name="NominalDiameter_F" Value="" />
For some reasons a few CFG job parameter is hardcoded therefore the value could not be
seen in the context menu (see picture under).

The way you get this kind of CFG parameter is that you export the job and try to find the CFG
parameter in the exported file:
The following example shows the post search actions:
If tool is found:
• If the tool is located in folder with name “Thread forming” then user variable
“TapingMethod” is set to “Forming”.
• If the tool is located in folder with name “Thread cutting” then user variable
“TapingMethod” is set to “Cutting”.
• “Pitch = [Pitch value] should be shown in job comment
If tool is not found: The user variable “TapingMethod” is set to “Unknown”.
<PostSearchActions>
<ToolFound>
<Action Condition = "NCTool.Folder = Thread forming" Type = "SetUserVariable"
Name = "TapingMethod" Value = "Forming"/>
<Action Condition = "NCTool.Folder = Thread cutting" Type = "SetUserVariable"
Name = "TapingMethod" Value = "Cutting"/>
<Action Type = "SetJobCfg" Name = "*COMMENT" Value = "Pitch = [MillingTool.Pitch]"/>
<Action Condition = "" Type = "DecisionTable" Id = "ThreadCoreDiaMat1" >
<Variable Name = "Designation" Value = "Connector.Designation" />
</Action>
</ToolFound>
<ToolNotFound>
<Action Type = "SetUserVariable" Name = "TapingMethod" Value = "Unknown"/>
</ToolNotFound>
</PostSearchActions>

SelectPriority
Attribute: None
Parent Element: Settings or VirtualTool
Children Element: SelectStrategy
Select priority defines the sort priority for the search result if more than one tool meets the
search filter. Select priority can be defined in Settings for all virtual tools globally. If a virtual
tool needs its own select priority, it can be defined inside virtual tool locally.
SelectStrategy
Attribute: Type, Name, Value
Parent Element: SelectPriority
Children Element: None
Four select strategies are supported now:
• Min: The minimal value will be selected at the first.
• Max: The maximal value will be selected at the first.
• Sequence: The tools are sorted based on the value of the named parameter.
• Condition: The tools meet the condition are selected at the first.
If more than one select strategy is defined the next select strategy will be applied if more
than one tool has the same value after the first select strategy is applied.
The first example shows a global select priority with two select strategies:
• The shorted tool length will be selected firstly
• If more than one tool has the same length the tool with biggest diameter will be
selected firstly.
“NCTool.UsableLength|NCTool.ClearanceLength” means the usable length is used and if the
usable length is zero then the clearance length is used.
<Vtdbx Version="1.0">
<Settings>
<SelectPriority>
<SelectStrategy Type = "Min" Value = "NCTool.UsableLength|NCTool.ClearanceLength"
/>
<SelectStrategy Type = "Max" Value = "MillingTool.Diameter" />
</SelectPriority>
</Settings>
<VirtualTools>
</VirtualTools>
</Vtdbx>

The second example shows a local select priority for a drilling tool with two select strategies:
• The tool will be sorted by tool cutting material VHM, HSS and then
• The tool with the shortest length will be selected firstly.
<VirtualTool Id = "Drilling" Name = "Drilling tool" Comment = "">
<SelectPriority>
<SelectStrategy Type = "Sequence" Name = "Tool.CuttingMaterial" Value = "VHM|HSS" />
<SelectStrategy Type = "Min" Value = "NCTool.UsableLength|NCTool.ClearanceLength" />
</SelectPriority>
<ToolTypes>
<ToolType Type = "drillTool"/>
</ToolTypes>
<SearchFilters>
<RuleFilter Value = "MillingTool.Diameter = Connector.Diameter" />
<RuleFilter Value = "NCTool.UsableLength &gt; Connector.Length" />
</SearchFilters>
</VirtualTool>

Job Cfg Variable
Job Cfg parameter can be used as variable. (‘*’ is allowed only in the first position)
Example: JobCfg.*Comment -- Job Comment
Joblist Variable
Joblist.Machine, selected machine in joblist
Joblist.Material, selected material in joblist
Joblist.CheckMacroMachineGroup = 0/1
Check if the in joblist selected machine belongs to in macro selected machine group. If there
is no machine group in macro the variable value is set to 1
Joblist.CheckMacroMaterialGroup = 0/1
Check if the in joblist selected material belongs to in macro selected material group. If there
is no material group in macro the variable value is set to 1
Macro Variable
Macro.MachineGroup, in macro defined machine group name, variable value is set to
“UNKNOWN” if no machine group is defined in macro
Macro.MaterialGroup, in macro defined material group name, variable value is set to
“UNKNOWN” if no machine group is defined in macro
Window System Environment Variable
EnvVariable.[Environment Variable Name], return the value of window system environment
variable. The value is set to “UNKNOWN” if the variable is not existed.
