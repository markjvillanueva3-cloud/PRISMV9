### Key techniques / claims (terse bullets)
- **Loop engineering = stop prompting, design the system that prompts.** steipete: "you should be designing loops that prompt your agents." bcherny (head of Claude Code): "I don't prompt Claude anymore... My job is to write loops." Leverage point moved, work didn't get easier.
- **Five loop building blocks + a memory spine** (both Claude Code & Codex ship all five): (1) Automations/schedule (`/loop`, cron, hooks, GH Actions), (2) Worktrees (parallel isolation), (3) Skills (intent written down, kills "intent debt"/cold re-derivation), (4) Plugins/connectors (MCP into real tools), (5) Sub-agents (maker≠checker), (6) Memory on disk ("the agent forgets, the repo doesn't").
- **`/loop` re-runs on cadence; `/goal` runs until a verifiable stop-condition a *separate small model* checks** — maker/checker split applied to the stop condition itself.
- **Harness engineering vs loop engineering:** harness = environment one agent runs inside (the "factory model"); loop engineering sits one floor above — the harness on a timer that spawns helpers and feeds itself.
- **Dynamic Workflows (Anthropic):** Claude writes/orchestrates its own JS multi-agent harness; isolated context windows, per-agent model override, journaled resume, deterministic (zero-token) JS coordination between agents; trigger word `ultracode`. Fixes 3 single-context failure modes: **agentic laziness**, **self-preferential bias**, **goal drift**.
- **6 composable patterns:** classify-and-act, fan-out-and-synthesize, adversarial verification, generate-and-filter, tournament, loop-until-done.
- **The 6 agent-loop rules (shann + Opik + Huryn + Martin):** (1) CLOSED-loop by default (open loop on loose standards = "slop machine"), (2) eval-gate every iteration, (3) each pass feeds the next, (4) self-correct the weakest part, (5) orchestrator/specialist/subagent split with ~zero-token coordination, (6) budget is a stop condition.
- **3 failure modes that get SHARPER as the loop improves** (Addy): verification is still on you ("done is a claim, not a proof"); comprehension debt grows faster; cognitive surrender. Mikenevermiss's production version: data quality, tool-call failures (never continue silently), prompt scope-creep — and keep final action (publish/send/execute) with the human; 74% of pilots never scale (BCG 2025).
- **Hermes loop primitives:** ReAct synchronous loop, hard 90-turn cap, SOUL.md identity slot, 3-tier memory (capped markdown→SQLite FTS→external providers), autonomous skill creation on triggers (5+ tool calls / error-recovery / corrections), Curator lifecycle daemon (never auto-deletes), GEPA offline prompt-evolution via execution traces (fixes self-congratulation bias), cron job-chaining via `context_from`.
