# OCR/PDF/Print-Reader Upgrade Roadmap (2026-05-09)

Survey of state-of-the-art open-source tools that could replace or augment the current PRISM stack. Generated by claude-d9860be8 during Docustrata phase 8 grind.

---

## 1. Current PRISM stack (audited)

| Engine | Approach | Pain points |
|--------|----------|-------------|
| `BlueprintOCREngine` | Regex on pre-extracted text | Doesn't OCR — needs upstream feed |
| `BlueprintVisionOCREngine` | Claude Vision API | Cloud-dep, $/page, can't scale to 120K pages |
| `ImageOCRPipelineEngine` | Generic image OCR (Tesseract assumed) | Tesseract is 2018-era; 4-6% drawing-detection rate today |
| `Drawing2DExtractionEngine` | DXF/DWG ASCII parser | Vector-only — useless on raster scans |
| `BlueprintToCADGenerationEngine` | Pipeline glue | Depends on upstream OCR quality |
| **Phase 8 prototype** (this session) | PyMuPDF + Tesseract + image heuristic | Tesseract is the bottleneck; no GD&T-aware extraction |

## 2. Highest-leverage upgrades

Ranked by impact-per-day-of-effort. All Apache 2.0 / MIT / similar.

### A. PaddleOCR 3.0 (PP-OCRv5) — drop-in Tesseract replacement

- **GitHub:** [PaddlePaddle/PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)
- **What you get:** 13% accuracy boost over prior versions, 100+ languages, **PP-StructureV3** module that parses complex PDFs/images into Markdown or JSON natively (titles, tables, layout), single-character coordinates, Windows + Linux + CPU + GPU + NPU
- **Effort:** ~1 day. Same Python API surface as Tesseract; can replace `pytesseract.image_to_string()` with PaddleOCR `PaddleOCR().ocr()`
- **Phase 8 use:** Tier 2 OCR engine (currently Tesseract) → drop in PaddleOCR; expect drawing-detection rate to jump from 4.5% → 7-10%

### B. Qwen2.5-VL — replace `llama3.2-vision:11b`

- **Ollama:** `ollama pull qwen2.5vl:7b` (smaller AND better than llama3.2-vision:11b)
- **Benchmarks:** 96.4% DocVQA, 88.8% OCRBench, near-human on document QA
- **Effort:** ~30 min. One-line swap of the model name in vision-classify scripts
- **Phase 8 use:** Tier 3 vision LLM (currently deferred because llama3.2-vision was wiped)

### C. olmOCR — production-scale document parser

- **GitHub:** [allenai/olmocr](https://github.com/allenai/olmocr)
- **Built on:** Qwen2-VL 7B, fine-tuned for documents. **$176 per million pages** (32× cheaper than GPT-4o, 6× cheaper than MinerU)
- **ELO ranking:** 1800+ (best in class; Marker is 1600, MinerU 1500)
- **Effort:** 1-2 days to integrate batch pipeline
- **Phase 8 use:** alternative to Tier 3 — if we need to scan all 120K pages with vision, this is the cheapest path

### D. MinerU 2.5-Pro — best for our container-PDF problem

- **GitHub:** [opendatalab/MinerU](https://github.com/opendatalab/MinerU)
- **Just released April 2026.** Handles multi-page complex PDFs natively, outputs Markdown + JSON with layout preserved, formulas → LaTeX, tables → HTML, 109 languages, Apache 2.0
- **Hardware:** 4 GB VRAM (pipeline) or 8 GB (VLM). Pure CPU works.
- **Effort:** 1 day to install + integrate
- **Phase 8 use:** This is the right tool for **whole-PDF parse** of our 107K multi-page Docustrata PDFs. Could replace Phases 6+7+8 with one pass.

### E. eDOCr — purpose-built mechanical-drawing extractor

- **GitHub:** [javvi51/eDOCr](https://github.com/javvi51/eDOCr)
- **What you get:** GD&T symbols (`⏥○⌭⌒⌓⏊∠⫽⌯⌖`), dimensions, title-block infoblocks, all via dedicated keras-ocr models. Cited research paper on production QC use.
- **Last commit:** Feb 2023 (stable, not abandoned — niche project)
- **Effort:** ~1 day to integrate as Tier 4 post-processor
- **Phase 8 use:** For pages CONFIRMED as drawings, run eDOCr to extract structured fields. Feeds directly into `BlueprintOCREngine` schema.

### F. Image2CAD — raster → DXF for downstream CAM

- **GitHub:** [adityaintwala/Image2CAD](https://github.com/adityaintwala/Image2CAD)
- **Yield:** 90% success on entity lines, dimensional lines, dimensional text, GD&T symbols, drawing metadata
- **Effort:** 1-2 days
- **Use:** After the print is identified, generate DXF that downstream CAM can consume — closes the print → CAD loop without manual redraw

## 3. Knowledge graph / data linking layer

For tying prints ↔ programs ↔ CAD ↔ customers ↔ machines ↔ materials together.

### Stack recommendation
- **Neo4j** + Cypher for the production knowledge graph ([neo4j.com](https://neo4j.com/))
  - Industry has established patterns: assembly→subassembly→part, shape similarity, machining process route recommendation ([MDPI 2025](https://www.mdpi.com/2079-9292/14/15/3156))
  - GenAI Cypher generation + Knowledge Graph RAG patterns are mature in 2025-2026
- **NetworkX** for in-memory analysis & graph algorithms during dev/exploration
- **Schema sketch:**
  ```
  (Print {id, part_no, customer, material, rev})
    -[:DEPICTS]→ (Part {part_no, family})
    -[:MADE_ON]→ (Machine {model, controller})
    -[:USES_PROGRAM]→ (Program {path, kind: g_code|cam_project, machine_type})
    -[:HAS_CAD]→ (CADFile {path, ext, has_toolpath})
  (Customer)-[:OWNS]→(Part)
  (Print)-[:VARIANT_OF]→(Print)  -- revision history
  (Program)-[:DERIVED_FROM]→(Print)
  ```
- **Backfill source:** `training-triples-v4.jsonl` (50 confirmed) + `jm-die-index-v2.json` (35,625 programs) + `prints-titleblock.jsonl` (228 prints) + Phase 8 output (~5,400 prints when done)

## 4. Recommended sequencing

| Phase | Task | Effort | Win |
|-------|------|--------|-----|
| **9a** | Swap Tesseract → PaddleOCR 3.0 in Phase 8 Tier 2 | 1 day | +50-100% drawing detection rate |
| **9b** | Pull Qwen2.5-VL via Ollama; wire into Tier 3 | 30 min | Tier 3 becomes available without re-pulling old model |
| **9c** | Install MinerU 2.5; run on a 100-PDF sample | 1 day | Compare against Phase 8 yield; may obsolete Phases 6+7+8 entirely |
| **9d** | Add eDOCr as Tier 4 (confirmed-drawing → structured fields) | 1 day | Get GD&T + dimensions + title-block in one pass |
| **9e** | Image2CAD for raster→DXF on confirmed drawings | 1-2 days | Closes print→CAD loop |
| **9f** | Neo4j schema + ETL from training-triples-v4 + jm-die-index-v2 | 2-3 days | Queryable knowledge graph powering all of `prism_cad`/`prism_cam` |
| **9g** | Wire MinerU/PaddleOCR/eDOCr into existing PRISM engines | 1-2 days | `BlueprintOCREngine` actually does OCR; `ImageOCRPipelineEngine` 10× faster |

**Minimum viable upgrade pass:** 9a + 9b + 9d = ~2.5 days, **gets us from 4.5% → likely 12-15% drawing detection rate AND structured GD&T/dimension/title-block extraction.**

**Full upgrade:** ~10 days, end state is a Neo4j-backed manufacturing knowledge graph with print-to-CAD-to-program lineage queryable from any PRISM dispatcher.

---

## 5. Tools we should NOT chase

- **Tesseract upgrades** — we're already using v5; the engine itself isn't getting smarter. Move on.
- **Werk24** — closed-source SaaS API. Not for us.
- **Marker / Docling** — fine general-purpose PDF→MD parsers, but olmOCR is cheaper + better, MinerU is structurally equivalent. No reason to add a 3rd.
- **Adobe / proprietary OCR** — license cost + no JM Die-specific tuning.
