# JM Crib -- CAM Tool Libraries (hyperMILL + Mastercam)

Generated by `mcp-server/scripts/generate-jm-cam-libraries.ts`
([JM-FUSION-TOOLS]/U-CAM-PROPAGATE, slot:romeo).

This is the **propagation** phase of the operator directive: "pass along
EVERYTHING we build for fusion to hypercad/hypermill and mastercam." It carries
JM Die's full 218-tool crib (geometry + holder + per-material cutting data) into
the two non-Fusion tier-1 CAMs, reusing the EXISTING PRISM exporters
(`MastercamToolExportEngine`, `HyperMillToolExportEngine`). Both exporters derive
cutting data from `UltimateSpeedFeedEngine`, so they already inherit the
U-SFC-GAPS additions + the hardened-drilling safety fix (no 344-SFM H drilling).

## Outputs

| File | CAM | Format | Tools | Status |
|------|-----|--------|-------|--------|
| `JM_CRIB.mcam-tools` | Mastercam | `.mcam-tools` JSON | 218 | Import-ready (Mastercam 2025+) |
| `JM_CRIB.hmt.sql` | hyperMILL | SQLite DDL + INSERTs | 218 | **Needs build step + v31 verification** -- see caveat |

## Scope: Option B (per-ISO-group parity), NOT Option A (per-grade x toolpath)

The Fusion library (`JM-CRIB-ALL-families.csv`, U-ALLCOND) is the atomic one:
per-GRADE (14) x per-TOOLPATH (8 strategies) = 4924 presets. These CAM exports
are **per-ISO-group** (6 groups) -- the safety-correct, SFC-improved cutting data
the existing exporters natively emit. Full per-grade x toolpath parity in
hyperMILL/Mastercam (Option A) is a larger per-CAM exporter enhancement, parked
for an explicit operator go-ahead (the hyperMILL Materials table + Mastercam
per-op model may not natively hold 14x8 cleanly).

## CAVEAT -- hyperMILL `.hmt.sql` (read before use)

1. **It is SQL, not a binary `.hmt`.** hyperMILL's tool DB is a SQLite file. This
   file is the DDL + INSERT statements to BUILD one. To use it:
   `sqlite3 JM_CRIB.hmt < JM_CRIB.hmt.sql` then point hyperMILL at `JM_CRIB.hmt`.
2. **Schema targets hyperMILL v33.0** (`-- Compatible with hyperMILL v33.0
   sqlite.sql v1.53 structure`). **JM runs hyperMILL v31.** v31 import
   compatibility is UNVERIFIED -- the v33 tool-DB schema may differ from v31's.
   Verify on a scratch copy before trusting in production, or regenerate against
   a v31 schema reference.
3. **Units:** all geometry is mm (JM crib is inch; the generator converts x25.4
   gated on `tool_unit`). Confirm hyperMILL import unit-system = metric.

The Mastercam `.mcam-tools` has no such caveat -- it is the exporter's native
JSON interchange and imports directly into Mastercam 2025+ tool manager.
