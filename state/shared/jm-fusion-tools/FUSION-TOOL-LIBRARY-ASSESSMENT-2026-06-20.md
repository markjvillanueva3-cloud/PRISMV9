## 3. Findings / limitations (honest)

1. **Brand-catalog geometry mis-parses — 3,101 records, fully enumerated + classified.** The complete flagged set is in `BRAND-TOOL-MISPARSE.{json,csv}` (every brand/designation/Dc/shank, generated by `scripts/enumerate-brand-tool-misparse.mjs`). Two failure modes, distinguished so the fix knows which field to repair:
   - **bad-diameter (2,472)** — an end-mill-type tool with Dc > 80 mm (a solid/indexable end mill cannot be that big; face/shell mills are typed separately). The `cutting_diameter_mm` is the artifact. Confirmed in source `mcp-server/src/data/indexable-tool-catalog.ts`, e.g. `M ECS-A1.00X06-2T` → `cutting_diameter_mm:102.67` on a `shank_diameter_mm:5.99` (a 6 mm connection can't drive a 102 mm cutter).
   - **bad-shank (629)** — a plausible Dc but the shank is impossibly small (Dc/shank > 8), e.g. `ACCU-0.3750-end_mill` Ø9.5 mm (correct 3/8″) / shank 0.8 mm. Here the **diameter is usable**; only the shank is wrong.
   Worst brands: ISCAR 1,792, YG-1 655, Korloy 228, Sumitomo 225, Guhring 55, MA Ford 46. Root cause: the plausibility gate's category ceiling (`indexable_mill ≤320 mm`, sized for real large face mills) is type-blind, so mistyped "indexable" end mills slip through. **JM's cribs and the material-group CSVs are clean (0 flagged).** Not auto-fixed because dropping on the raw `Dc≫shank` ratio alone would discard real tools (the bad-shank class) — the classified list above is the safe basis for a targeted fix (§5).
2. **ISCAR library is mono-type** — all 5,140 entries typed "flat end mill" (the inserts/turning went to the Mastercam/hyperMILL lanes, which Fusion's schema excludes). Low categorization fidelity for browsing.
3. **Named-machine cribs are holder-less clones.** `PRISM_JM_okuma-*`, `haas-*`, `hurco-*`, `roku-*` mirror the VMC/LTH tool sets but with **0% holders** (vs 48–100% on VMC/LTH). They predate the holder-enrichment pass and duplicate the canonical cribs.
4. **Doc drift (fixed this session):** `FUSION-IMPORT-START-HERE.md` referenced `*-6groups.csv`; the regenerated files are `*-allconditions.csv`. Corrected, and a `by-type-brand/` import path added.
