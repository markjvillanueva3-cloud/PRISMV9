  6. git config worktree.baseRef head does NOTHING. worktree.baseRef is not a git config key — git stores it as inert text and never reads it (verified). It's a Claude-Code harness setting (per the EnterWorktree tool doc: fresh=branch-from-origin/<default>, head=branch-from-current-HEAD).   9. git fsck --full on a 43 GB repo takes minutes-to-tens-of-minutes — it appears in 3 units' acceptance with no time budget; use --connectivity-only / --no-dangling or budget ≥10 min.
  10. enforce-handoff-topic.mjs excludes main/master/develop from branch-based topic derivation — but NOT cad-fusion-live-ms0. Today a chat on cad-f gets topic "cad-fusion-live-ms0"; post-rename it's on main → derivation skips the branch step → handoff filenames change form (the "topicless handoff" failure class CLAUDE.md warns about). Add cad-fusion-live-ms0 to that exclusion list now so pre/post-rename behavior matches.

#B. CONSOLIDATED MUST-FIX LIST (prioritized; merges the 3 agents' top-5s)

P0-blocking (do these before any execution):

  1. Renumber the roadmap once, cleanly. It openly has 3 conflicting schemes (U-GC-00…22 in META; U-GC-03/04/04b/05/05cfg/06/06b in phase bodies; the DAG's own) and says "the DAG is authoritative … wait — keep the canonical numbering." For an execution artifact that's a defect. Suggested: P0 = U-GC-01..05 (gitignore+untrack curated-audited, branch-cruft+recovery-ref, worktree.baseRef as a harness setting, gc+repack -adf, /sync-rebase --base fix), P1 = U-GC-06..09 (canonical-trunk shared module, trunk-guard.mjs SessionStart, worktree-commit-route trunk-check, doc reconcile), P2 = U-GC-10..14 (verified backup ×2 off-drive, freeze-hook, dirty-worktree sweep [start day 1], filter-repo+--prune-empty=never, force-push-rewritten-refs-only+resync), P3 = U-GC-15..18 (main/master/claude* analysis ×3, B-vs-C decision gate, execute reconcile, rename→main+retire-as-tags), P4 = U-GC-19..24 (origin-only-branch triage, stale-fork auto-triage script + review + exec, broken-worktree removal, archive/forge-orphans decision), P5 = U-GC-25..27 (partial verify after P0+P1, full verify, document+memory).
  2. worktree.baseRef: set it as a HARNESS setting in H:/.claude/settings.json, not git config (correction A.6). The whole point of the unit fails otherwise.
  3. Add a freeze-enforcement unit (U-GC-FREEZE, executes immediately before the rewrite, removed after the resync verifies). The roadmap names "commit freeze" as the mitigation for F3/F17 but has no mechanism — 8 autonomous YOLO chats that auto-commit after each unit will land a commit on doomed history during the 30–60 min window → silently reset --hard'd away at force-push time. The fix: a temporary bundle-absorbed PreToolUse hard-block hook git-maintenance-freeze.mjs (denies all non-operator git (commit|push|merge|rebase|reset|cherry-pick|filter-repo|worktree add) while state/shared/.git-freeze-active exists), wired into bash-bundle.mjs SUB_HOOKS so stop_on_hook_unregistration + settings-json-addonly-guard don't trip; a Stop-hook clause that skips git-sync-stop's push while the flag is set; PRISM_DISABLE_GIT_SYNC=1 (or the real off-switch — verify one exists) for the window; and a pre-reset assertion in the force-push unit: git log origin/<branch>..<branch> must be empty — else cherry-pick those commits onto the rewritten history first, never reset --hard past unmerged local work. Fully reversible (rm the flag + revert the bundle entry) → "never delete only disable" compliant.
  4. Backup posture: ≥2 independent backups, ≥2 physical volumes, verified, kept until P4+P5 done. The roadmap's single git clone --mirror to H:/prism-git-backup-*.git is on the same (per memory, portable) drive as the repo and is deleted on a fixed 30-day clock while P4 deletions "run incrementally over weeks". Fix: git clone --mirror to a different volume and git bundle create … --all off-drive; git -C <backup> fsck --full + rev-parse cad-fusion-live-ms0 + size-check each; take them before U-GC-05's gc --prune=now (not at U-GC-09); keep until all of P4+P5 complete and verified. (The leave-a-copy-behind-guard.mjs Stop hook may flag a premature backup deletion — aligns with this.)
  5. filter-repo will prune commits that contained only system-graph.json — possibly including HEAD. --invert-paths on a path that was a commit's only change makes that commit empty, and filter-repo prunes empty commits by default; 02720fd64 (the HEAD-adjacent 118.76 MB system-graph.json commit) is exactly such a commit. Fix: run with --prune-empty=never; acceptance must assert git rev-list --count HEAD before == after (modulo a user-approved, reconciled delta) and the rewritten HEAD commit message matches the expected one.
  6. Blind --strip-blobs-bigger-than 20M with no inventory review = "delete history without disable". Generate git rev-list --all --objects | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | awk '$1=="blob"&&$3>20000000' | sort -k3 -rn first, review with the user, prefer explicit --path exclusions for the known-bad ones over the blind cutoff.
  7. U-GC-13 push sequencing leaves a window with no remote trunk + conflates "GitHub default branch" with git config init.defaultBranch. Fix order: push main first → set the GitHub default branch (API/UI) and git remote set-head origin main → re-point all 40 worktrees' upstreams + verify → only then retire origin/cad-fusion-live-ms0 (and as a rename-on-remote origin/archive/cad-fusion-live-ms0-pre-rename-<date>, kept ≥90 days, not a hard push origin :). Drop the redundant raw git symbolic-ref (keep git remote set-head). Note git config init.defaultBranch is repo-local and does NOT change GitHub's default.
  8. U-GC-10 force-push: never --force-with-lease --all from a fresh clone — the no-ref-arg lease checks against this clone's remote-tracking refs (= origin at clone-time), so a push another chat lands between clone and force-push is exactly the unprotected window. Push only the rewritten branches explicitly with per-ref leases: git push --force-with-lease=cad-fusion-live-ms0:<old-sha> --force-with-lease=main:<sha> origin cad-fusion-live-ms0 main. Also: handle partial-push (git ls-remote origin must exactly match the mirror's refs before unfreezing) and stale .git/worktrees/agent-*/index.lock in the per-worktree reset loop (rm -f >1h-old locks; report any worktree it couldn't reset, never silently skip → that's how a worktree ends up orphaned on pre-rewrite SHAs that gc --prune then deletes).
