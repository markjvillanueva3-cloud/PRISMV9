PRISM has **excellent individual tools** (3245 engines, 511 hooks, 184 skills, 97 dispatchers, RGS sidecar, 5+ telemetry streams, 4 ownership systems, 11 CLEAR-bypass surfaces) but **poor composition between them**:

1. **5 silent-degradation bugs** discovered this iter that defeat the documented synergy:

   - **S1-CRITICAL**: `error-pattern-capture` 0-fire (broken matcher) → `error-pattern-promote` 99.8% no-op (1947/1951 below threshold) → `error-fix-vault-bridge` 0 directory entries. **Entire 3-stage error-learning loop is dead** despite all 3 hooks being wired.

Real issue: **46% are "minimal"** (single `/scrutinize` fallback at 0.3 confidence) → V1 W0 `U-RGS-RULE-BACKEND-DEV` is still right, but for different reasons (lift minimal-tier coverage, not unblock production).

3. **8 PreToolUse:Write hooks all do similar work** (5 reimplement asset-type classifier; 3 read `cross-session-asset-registry.json` independently). Composable into ONE composite gate with 8× spawn reduction.

4. **5 telemetry streams join on the same key** (sid 8-char prefix → slot via chat-slots.json) but each has its own dashboard. ONE rolled dashboard + ONE inject badge eliminates the redundancy.

5. **4 ownership systems** (chat-bus / slot-task-claim / per-agent-handoff / legacy `data/claims/`) overlap. The legacy system has 2 stale leaked entries proving no-one releases. Unified `ownership-lib.mjs` front-door is the fix.
