#§1 — Why this matters

PRISM already operates ~480 wired hooks under H:/prism/.claude/hooks/ plus H:/.claude/settings.json, covering PreToolUse / PostToolUse / UserPromptSubmit / Stop / PreCompact. That stack predates the wave of public Claude Code hook patterns that landed late-2025/early-2026 — meaning the wider ecosystem has now codified several techniques PRISM has been doing ad-hoc, and has also shipped patterns PRISM does not yet exploit:

  1. Anthropic shipped hookify as a first-party plugin (markdown rules + YAML frontmatter, auto-rule-discovery from conversation transcripts). PRISM's hooks are hand-rolled .mjs — hookify's .local.md rule pattern is what we should adopt for user-extensible policy without touching the core 480-hook fleet.
  2. Hook event surface expanded to ~31 events in 2.1.x — including PostToolBatch, TeammateIdle, TaskCreated/Completed, PermissionDenied{retry:true}, agent-scoped frontmatter hooks, defer permission decision, conditional if fields, HTTP/MCP/prompt/agent hook types. PRISM still treats hooks as shell-command-only.
  3. **Boris Cherny publicly framed hooks as the enforcement answer** to CLAUDE.md drift ("Hooks are a guarantee. CLAUDE.md is a suggestion"). This is exactly PRISM's enforcement model — meaning we are aligned with the canonical pattern and should compound, not retreat.
  4. Cost-control hooks now exist (read-once, lean-ctx, Ollama-route hooks). PRISM has OllamaHookBridgeEngine but does NOT have a hard read-once PreToolUse gate. That is a gap with a measurable 40% file-read token saving in the wild.
  5. Hook-storm cost incidents are now documented ($6,000 overnight via /loop 30m, context-compact loops, async hook deadlock). PRISM has not audited its 480 hooks for circularity / fanout.

#§4 — Concrete PRISM hook proposals (event, matcher, action, blast-radius, blocks)

PRISM already has 480 wired hooks. These proposals fill specific gaps revealed by §2–§3. Each is graded by blast-radius (B) and what it blocks (X).

#§4.1 — read-once PreToolUse Read dedup

  • Event: PreToolUse
  • Matcher: Read
  • Action: Track {file_path, mtime, session_id} in .claude/cache/read-once.json. On cache hit with unchanged mtime within TTL=1200s, return permissionDecision: "deny" with permissionDecisionReason: "Already in context (read at <ts>). Use partial-Read offset/limit if you need a different range, or wait for mtime change.". On modified, allow read OR return diff-only stdout.
  • B: Low — only blocks redundant Reads.
  • X: Re-Reads of large files that ate context in long sessions (matches read-after-edit.local.md already in PRISM tree, but currently a hookify rule, not a true dedup-with-TTL gate).
  • Source: dev.to/boucle2026 — read-once (40% savings in worked example).

#§4.2 — defer-on-uncertain PreToolUse (Bash danger)

  • Event: PreToolUse
  • Matcher: Bash with if: "Bash(rm -rf *)|Bash(git push --force *)|Bash(npm publish *)"
  • Action: Return permissionDecision: "defer" for headless sessions, "ask" for interactive — pause until human resume with -p --resume. This is the new 2.1.89 capability PRISM has not adopted.
  • B: Low — only fires on hand-curated danger list.
  • X: Catches autonomous-loop runaway scenarios (matches the $6,000 overnight loop incident).
  • Source: Claude Code Changelog 2.1.89.

#§4.3 — permission-denied-retry-classifier PermissionDenied

  • Event: PermissionDenied (new in 2.1.89)
  • Matcher: all
  • Action: Inspect denied tool + args. If matches PRISM's auto-allow patterns (read-only Grep/Glob/Read on state/shared/**), return {retry: true}. Otherwise let denial stand.
  • B: Medium — controls the auto-mode retry surface.
  • X: Classifier false-negatives where PRISM's allowlist is more permissive than Claude's auto-mode default.

#§4.4 — ollama-route-classifier PreToolUse (Edit/Write)

  • Event: PreToolUse
  • Matcher: Edit|Write|MultiEdit
  • Action: Inspect intent (from recent UserPromptSubmit context). If intent is "summarize / docstring / lint / classify / diff-summary," return updatedInput rewriting the call into a prism_ai:ollama_local MCP call instead. Else allow.
  • B: Medium — changes execution surface for ~30% of edit calls per PRISM's existing OllamaHookBridgeEngine heuristics.
  • X: Cloud-billed Claude calls for tasks that qwen2.5-coder:7b handles locally.
  • Source: Confirms PRISM is already directionally correct; adds an explicit PreToolUse-as-router arm.

#§4.5 — agent-scoped-stop-verify (frontmatter)

  • Event: Stop (agent-scoped, in agent frontmatter)
  • Matcher: N/A (per-agent)
  • Action: Each subagent_type declares its own Stop verifier in YAML frontmatter — e.g., physics-reviewer agent enforces "all Kienzle constants came from constants.ts" before returning. Reusable across all Agent() calls of that type.
  • B: Per-agent only — no global blast.
  • X: Drift in long agent loops where the parent Stop hook does not see internal agent traffic.
  • Source: @EricBuess on agent-scoped hooks.

#§4.6 — hookify-style user-extensible rules

  • Event: all
  • Matcher: delegated to rule's pattern
  • Action: Install hookify plugin from anthropics/claude-code/plugins/hookify. Add a /hookify-prism wrapper that knows PRISM's matcher conventions. The 25 existing .claude/hookify.*.local.md files in repo (per git status) are already in this format — formalize the pattern.
  • B: Low if rules are reviewed; high if a user adds an over-broad pattern.
  • X: "I keep forgetting to X" style soft policies that don't deserve a .mjs hook.
  • Source: hookify plugin.

#§4.7 — http-hook-observability PostToolUse (Edit|Write|Bash)

  • Event: PostToolUse
  • Matcher: Edit|Write|Bash
  • Action: Fire HTTP hook to http://localhost:8765/svi-event (existing system-viz server). Streams tool calls into the live system-viz graph for real-time blast-radius display.
  • B: Low — purely observational.
  • X: Blind-spot when multi-chat work happens off-graph.
  • Source: @dickson_tsai HTTP hooks announcement.

#§4.8 — mcp-tool-hook PreToolUse (security_scan)

  • Event: PreToolUse
  • Matcher: mcp__.*__write.*
  • Action: Hook of type: mcp_tool, server: prism_safety, tool: validate_physics — runs PRISM's existing safety gate against any MCP write that might touch physics state. Native MCP→hook bridge, no shell-out.
  • B: Low — only MCP writes.
  • X: External MCP servers bypassing PRISM's safety chain.
  • Source: Hooks ref MCP-tool-hook spec.

#§4.9 — task-created-claim-guard TaskCreated

  • Event: TaskCreated
  • Matcher: all
  • Action: Read task description, cross-check mcp-server/data/claims/<unit>/claim.json. If unit already claimed by another chat (heartbeat < 5 min), return exit-2 to roll back creation.
  • B: Medium — prevents Task() spawn for conflicting work.
  • X: Multi-chat duplicate work (PRISM's #1 coordination failure mode).

#§4.10 — posttoolbatch-fanout-budget PostToolBatch

  • Event: PostToolBatch
  • Matcher: all
  • Action: Sum token cost of just-completed parallel batch. If batch cost > PRISM_BATCH_CEILING (default 50k tokens) AND next-model-call is queued, return {decision: "block"} with reason — forces a checkpoint before another fanout.
  • B: Medium — gates the agentic loop.
  • X: Hook-storm + $6,000-overnight class incidents.
  • Source: @amaanbuilds runaway-loop post.

#§6 — Failure modes (hook storm, infinite loop, hook conflict)

#§6.1 — Hook storm (fanout > budget)

Symptoms: PostToolBatch runs N parallel tools, each fires M PostToolUse hooks, each writes to disk, next model call fans out N more → exponential.

PRISM exposure: 480 hooks + parallel tool calls + 6-concurrent-chat model. High.

Mitigations:

  • §4.10 PostToolBatch budget ceiling.
  • Audit H:/prism/.claude/hooks/ for any hook that fires another hook indirectly (e.g., a PostToolUse that writes a file that triggers FileChanged that triggers another PostToolUse).
  • Use async: true for non-blocking observability hooks so they don't serialize the loop.

#§6.2 — Infinite loop (Stop hook blocks Stop)

The canonical failure: Stop hook returns exit 2 → Claude continues → reaches Stop again → hook returns exit 2 again → forever. Reported in Boris's own ralph-wiggum plugin design context.

PRISM exposure: scrutinize-before-stop already has 3-block escape hatch. Bounded.

Mitigations:

  • Every blocking Stop hook MUST have a "max retries" escape hatch (PRISM convention: 3 attempts).
  • Never have two independent Stop hooks both blocking on different criteria without coordination — one of them will perpetually block the other.

#§6.3 — Hook conflict (settings.json hierarchy ambiguity)

User settings + project settings + local settings + plugin settings + managed-policy settings + skill frontmatter + agent frontmatter all stack. With 480 hooks across all layers, conflicts are statistically inevitable.

PRISM exposure: settings split across H:/.claude/settings.json (user) + H:/prism/.claude/settings.json (project) + ~/.claude/settings.local.json (local, gitignored). Medium.

Mitigations:

  • Audit hook by event-name and matcher-string for duplicates across files (currently dedup is only within-file via Anthropic's command-string dedup).
  • Adopt naming convention <scope>.<event>.<intent>.mjs to surface conflicts in filename.
  • Run hookify:list (after §4.6) to see active rule set in one place.

#§6.4 — Context-compact loop

Documented by @yagudaev: after compact, 0% free context, every message triggers another compact.

PRISM exposure: precompact-handoff.mjs writes large handoff content. If handoff content > post-compact budget, High.

Mitigations:

  • PreCompact hook MUST cap handoff size (target ≤ 4k tokens).
  • PostCompact hook should verify free context > 30% before allowing UserPromptSubmit.
  • PRISM's per-chat handoff (HANDOFF-<id>-<topic>.md) is already topic-suffixed which keeps it scope-limited — preserve that discipline.

#§6.5 — Async hook deadlock

async: true hooks don't block the agent loop but do consume the same disk/network resources. 50 parallel async hooks writing to one log file = lock contention.

Mitigations:

  • Bound async parallelism per event-type.
  • Use append-only JSONL (no read-modify-write) for hook telemetry — avoids lock contention by design.

#§6.6 — Defer-on-defer (new 2.1.89 footgun)

A PreToolUse hook returns defer. Session is resumed with --resume. Hook re-evaluates and returns defer again. Net: silent stall.

Mitigations:

  • Any defer decision should encode a max-defer-count in the hook's own state (e.g., .claude/cache/defer-count-<tool_use_id>.json) and auto-convert to deny after 3 defers.

#§6.7 — HTTP hook PII leak

HTTP hooks can post tool_input bodies to localhost. If the listener logs to disk and disk is synced (e.g., iCloud), secrets exfiltrate.

Mitigations:

  • HTTP hook URLs must be http://localhost:* or http://127.0.0.1:* only — never 0.0.0.0 or external.
  • Body should be redacted at hook-source (the .mjs that posts) for known-secret fields (api_key, token, password, .env paths).
  • Pair with §3's @wilderko reverse-proxy pattern if PRISM ever runs against external Claude API for hooks.
