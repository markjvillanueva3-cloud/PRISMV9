#§1 — Why This Matters

PRISM currently runs a 5-tentacle octopus: Claude (orchestrator) + Codex (CLI peer) + Gemini (CLI peer) + Kimi K2.6 (cloud, mid-tier) + Ollama qwen2.5-coder:7b (local). The existing scrutiny gate is 3-of-3 (Codex + Gemini + Opus). The roadmap target is 5-of-5 with neural-network-coordinated routing across the seven existing neural engines (MillNeuralNetworkEngine, WEDMNeuralTrainingEngine, CrossDisciplinaryDeepLearningEngine, CrossProcessNeuralLearningEngine, etc.).

The 2024-2025-2026 research landscape has converged on four directly applicable patterns:

  1. Mixture-of-Agents (MoA) — layered ensembles that recursively refine peer outputs, beating GPT-4 at 25x lower cost.
  2. Cascade routing (FrugalGPT lineage) — confidence-gated escalation from cheap local models to expensive frontier models, with 98% cost reduction at parity quality.
  3. Topology-aware orchestration (Puppeteer / GraphRouter) — graph neural networks learn which agent to route to next based on shared-memory state, replacing hardcoded chains.
  4. Anthropic orchestrator-worker — 15x token cost for 90.2% quality lift; validated at PRISM scale and now industry-standard.

The strategic question is not "should we go 5-of-5?" — the empirical case is overwhelming. The question is how to wire it without falling into the known failure modes: cascade collapse, consensus deadlock, sycophancy convergence, neural drift, and the 41-86.7% MAST failure rate documented across production multi-agent systems.

#§2 — Reputable Papers (arXiv IDs + URLs verified)

#2.1 Foundational ensemble + reflection

  • Mixture-of-Agents Enhances Large Language Model Capabilities — Wang, Wang, Athiwaratkun, Zhang, Zou (Together AI / Duke / Stanford). arXiv 2406.04692, Jun 7 2024. Layered architecture: each layer of N LLMs takes the prior layer's outputs as auxiliary input. Together-MoA hits 65.1% on AlpacaEval 2.0 vs 57.5% for GPT-4 Omni using only open-source models. https://arxiv.org/abs/2406.04692
  • Reflexion: Language Agents with Verbal Reinforcement Learning — Shinn, Cassano, Berman, Gopinath, Narasimhan, Yao. arXiv 2303.11366, NeurIPS 2023. Verbal RL: agents reflect on task feedback into an episodic memory buffer; no weight updates. Foundational pattern for the Codex/Gemini/Opus reviewer arms in PRISM's 3-of-3 gate. https://arxiv.org/abs/2303.11366

#2.2 Cost-aware routing + cascades

  • FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance — Chen, Zaharia, Zou. arXiv 2305.05176, May 2023 (TMLR 2024). Three strategies: prompt adaptation, LLM approximation, LLM cascade. Cascade matches GPT-4 with 98% cost reduction or beats it by 4% at parity cost. https://arxiv.org/abs/2305.05176
  • A Unified Approach to Routing and Cascading for LLMs — De Koninck et al. (ETH Zürich). arXiv 2410.10347, Oct 2024. Derives provably optimal cascade routing under cost-quality tradeoff. https://arxiv.org/abs/2410.10347
  • GATEKEEPER: Improving Model Cascades Through Confidence Tuning — arXiv 2502.19335, Feb 2025. Cascade-aware confidence calibration; probe-based methods dominate verbalized self-reports for deferral decisions. https://arxiv.org/abs/2502.19335

#2.3 MoA followups (2025)

  • Rethinking Mixture-of-Agents: Is Mixing Different LLMs Beneficial? — Li, Lin, Xia, Jin (Princeton). arXiv 2502.00674, Feb 2 2025. Self-MoA (aggregating outputs from one top model) beats heterogeneous MoA by 6.6% on AlpacaEval. Heterogeneous mixing diluted by weakest model. https://arxiv.org/abs/2502.00674
  • RMoA: Optimizing Mixture-of-Agents through Diversity Maximization and Residual Compensation — Xie, Han, Shi et al. arXiv 2505.24442, May 30 2025 (ACL 2025 Findings). Adds ResNet-style residual connections + embedding-based greedy diversity selection. https://arxiv.org/abs/2505.24442
  • Attention-MoA: Inter-Agent Semantic Attention and Deep Residual Synthesis — arXiv 2601.16596, 2026. Self-attention + cross-attention + semantic aggregation for critique-and-refine. https://arxiv.org/abs/2601.16596

#2.4 Graph-neural agent routing

  • GraphRouter: A Graph-based Router for LLM Selections — arXiv 2410.03834, Oct 2024. Heterogeneous graph (task/query/LLM nodes); edge-prediction GNN predicts (effect, cost) per (query, LLM) pair. >12.3% min improvement over baseline routers; generalizes to unseen LLMs without retraining. https://arxiv.org/abs/2410.03834
  • AgentRouter: Knowledge-Graph-Guided LLM Router for Collaborative Multi-Agent QA — arXiv 2510.05445, Oct 2025. Type-aware heterogeneous RouterGNN; KL divergence vs empirical agent performance. https://arxiv.org/abs/2510.05445
  • PersonalizedRouter: Personalized LLM Routing via Graph-based User Preference Modeling — arXiv 2511.16883, Nov 2025. https://arxiv.org/abs/2511.16883

#2.5 Topology learning + dynamic orchestration

  • Topological Structure Learning Should Be A Research Priority for LLM-Based Multi-Agent Systems — Yang, Zhang, Jin et al. arXiv 2505.22467, May 28 2025. Position paper: three-stage framework (agent selection, structure profiling, topology synthesis). https://arxiv.org/abs/2505.22467
  • Multi-Agent Collaboration via Evolving Orchestration ("Puppeteer") — Dang, Qian et al. arXiv 2505.19591, May 26 2025. RL-trained central controller picks next agent given shared-memory state; emergent cyclic-reasoning structures. https://arxiv.org/abs/2505.19591
  • Towards Adaptive, Scalable, and Robust Coordination of LLM Agents (RAPS) — arXiv 2602.08009, 2026. Reputation-aware publish-subscribe; agents exchange messages by declared intents, no predefined topology. https://arxiv.org/abs/2602.08009
  • Benchmarking LLMs' Swarm Intelligence (SwarmBench) — arXiv 2505.04364, May 2025. 2D grid world, local perception only; tests emergent coordination. https://arxiv.org/abs/2505.04364

#2.6 Frontier model (Kimi)

  • Kimi K2: Open Agentic Intelligence — Moonshot AI / Kimi Team. arXiv 2507.20534, Jul 28 2025. 1T-param MoE, 15.5T tokens pre-training with MuonClip optimizer + QK-Clip stability. Tau2-Bench 66.1, SWE-Bench Verified 65.8, AIME 2025 49.5 — without extended thinking. https://arxiv.org/abs/2507.20534
  • Kimi Linear: An Expressive, Efficient Attention Architecture — arXiv 2510.26692, Oct 2025. Attention redesign that underpins K2.5/K2.6 inference economics. https://arxiv.org/abs/2510.26692

Scores SWE-Bench Pro 58.6, HLE-Full 54.0 with tools (beats GPT-5.4, Opus 4.6, Gemini 3.1 Pro), BrowseComp Swarm 86.3% vs GPT-5.4's 78.4%. Available on Kimi.com, API, Kimi Code CLI, Cloudflare Workers AI, OpenRouter, Ollama, DeepInfra. Weights under Modified MIT.

#§4 — Concrete PRISM Unit Proposals

#4.1 U-KIMI-TRANSPORT (KimiTransportEngine + prism_ai:kimi_dispatch)

Goal: First-class K2.6 tentacle as the mid-tier reasoner between qwen2.5-coder (local, free, fast) and Opus/Sonnet (cloud, expensive). Sweet spot: 256K context, near-Opus quality on agentic tasks, Modified-MIT weights, ~10x cheaper than Opus.

Wiring:

  • KimiTransportEngine.ts (new) — wraps OpenRouter moonshotai/kimi-k2.6 and Cloudflare Workers AI endpoint; supports fallback ordering OR → Cloudflare → DeepInfra → local Ollama.
  • Dispatcher actions: prism_ai:kimi_chat, prism_ai:kimi_swarm (passthrough to K2.6's native 300-sub-agent mode), prism_ai:kimi_long_context (256K analysis).
  • Hook: kimi-context-budget-gate.mjs — refuse kimi_chat for prompts <8K tokens that qwen2.5-coder could handle; cost-class gate.

Tests: round-trip via three dispatchers (prism_ai, prism_intelligence, prism_session), parity assertion against current Opus output on a frozen JM Die spec-editor task.

#4.2 U-MOA-LAYER2 (MoaLayer2Engine + prism_intelligence:moa_synthesize)

Goal: Add a second MoA aggregator layer above the existing 3-of-3 reviewer arms. Codex+Gemini+Opus each produce drafts in parallel (layer 1); then K2.6 acts as aggregator (layer 2), receiving all three outputs and synthesizing. Then either Opus or Kimi acts as Chairman (layer 3) per Karpathy's pattern.

Variants to expose:

  • --moa-heterogeneous (Wang 2024 baseline)
  • --moa-self (Li 2025 Self-MoA — only Opus, multi-sample)
  • --moa-residual (RMoA — diversity-greedy + ResNet residual connections)

Empirically: Self-MoA wins on AlpacaEval, but PRISM tasks are physics+code+manufacturing — domain diversity favors heterogeneous. Default --moa-residual (best of both).

#4.3 U-NEURAL-ROUTING-ENGINE (NeuralRoutingEngine + prism_session:gnn_route)

Goal: Replace the current hardcoded "Codex+Gemini+Opus" reviewer triple with a learned GraphRouter that picks N-of-M reviewers per task, using a heterogeneous graph (task ↔ query ↔ tentacle) with edge attributes (latency, cost, prior success rate per domain).

Inputs:

  • Tentacle embeddings — derived from prior task outcomes per tentacle (already logged in state/shared/SCRUTINY_LEDGER.json and mcp-server/data/state/ollama-offload-stats.json).
  • Task embeddings — reuse existing PRISM embeddings (Qdrant memory, 768-dim).
  • Edge labels — (success | fail | timeout) from ledger replay.

Training data: Bootstrap from 90 days of scrutiny-ledger entries — we already have ~thousands of CLI-arm verdicts.

Wiring: Connect to existing CrossProcessNeuralLearningEngine (which already does cross-domain neural training); feed routing decisions back as supervised labels.

#4.4 U-CASCADE-CALIBRATION (CascadeCalibrationEngine + prism_safety:calibrated_defer)

Goal: Apply GATEKEEPER (arXiv 2502.19335) confidence-tuning to the existing Ollama-offload classifier. The current OllamaHookBridgeEngine decides "offload vs keep" deterministically — replace with a calibrated probe-based confidence head trained on outcome (did Claude have to redo the task afterwards?).

Why: Telemetry already exists in ollama-offload-stats.json. Current offload rate target ≥30%; calibration should push to ≥50% without quality regressions.

Tests: Replay last 1000 offload decisions; show ECE (Expected Calibration Error) drop ≥30%.

#4.5 U-CONSENSUS-QUORUM-TUNER (ConsensusQuorumEngine + prism_safety:quorum_select)

Goal: Make the N-of-M quorum dynamic rather than fixed 3-of-3. Drives from task class and live tentacle health:

  • Safety-critical physics changes → 5-of-5 (all tentacles must agree)
  • Doc-only edits → 2-of-3 (any two of Codex/Gemini/Opus)
  • Skill/hook ergonomics → 1-of-1 (local qwen2.5-coder sufficient)
  • Cross-domain neural (touches engines) → 4-of-5 with Kimi as tiebreaker

Policy source: ConsensusQuorumPolicy.json (schemaVersion 1) — declarative ruleset mapping (changeClass × diffSize × testCoverage) → quorum_n_of_m. Tunable via RMoA-style residual updates from outcomes.

Failure-mode mitigation: Caps any single quorum at 5; if 3 disagreeing verdicts persist, escalate to human-in-the-loop (writes to state/shared/AGENT_WORKBOARD.md and blocks the Stop hook).

#§6 — Failure Modes

#6.1 Cascade collapse

Definition: One agent hallucinates → writes to shared memory → downstream agents treat as fact → exponential error amplification. Documented in MAST taxonomy (arXiv 2503.13657) and Galileo / Augment Code 2026 production reports.

PRISM-specific risk: state/shared/AGENT_CHAT.md and mcp-server/data/state/cross-session-asset-registry.json are exactly the kind of shared-memory surfaces where cascading hallucinations propagate. The existing duplicationGuardEngine is one safeguard; we need more.

Mitigations to wire:

  • Verification quarantine — Any new entry written to AGENT_CHAT or asset-registry must pass a second-tentacle attestation before being readable by other chats. Implement as a chat-write-attestation.mjs PreToolUse hook.
  • TTL on unverified facts — Default 1-hour expiry for any memory not signed by ≥2 tentacles. Already partially modelled by wiki deprecation path; extend to ephemeral chat state.
  • Cascade depth cap — MoaLayer2Engine refuses to chain more than 3 aggregator layers (matches Wang 2024 empirical sweet spot).
  • Reverse-cascade audit — When a regression is detected, walk the shared-memory write log backwards to identify the originating hallucination. regression-hunter agent (already exists) gets a new mode --cascade-trace.

#6.2 Consensus deadlock

Definition: 3+ agents in request-response cycles awaiting mutual confirmation; or resource-lock ordering conflicts. The existing 3-of-3 gate already exhibits a mild form when Codex says PASS, Gemini says FAIL, Opus says PASS — the spec is "all three must pass" but the current ledger fallback (3 block attempts auto-pass with warning) is itself a deadlock-escape that papers over genuine disagreements.

Mitigations:

  • Tiebreaker hierarchy in ConsensusQuorumEngine: when verdicts split, escalate to (1) Kimi K2.6 with shared-memory access, (2) human-in-the-loop via AGENT_WORKBOARD.md. Never silent auto-pass.
  • Bounded discussion rounds — RMoA Sequential Self-MoA pattern: aggregator gets max 3 rounds; after that, lowest-confidence agent is dropped and quorum re-evaluated.
  • Lock-ordering canonicalization — All shared-memory writes acquire prism_context:claim_file locks in lexicographic order by file path (already enforced for wiki; extend to all of state/shared/).
  • Sycophancy guard — From ACL 2025 CONSENSAGENT paper: agents that flip their verdict after seeing another agent's verdict trigger a flag; the flip is logged and the original verdict is given weight in tiebreaker.

#6.3 Neural drift

Definition: A learned router (GraphRouter) becomes miscalibrated as the underlying tentacle quality changes (new K2.6 release, Codex CLI version bump, Gemini cutoff update). The router keeps routing as if quality were yesterday's.

Mitigations:

  • Online calibration — Every routing decision logs an outcome; CascadeCalibrationEngine retrains weekly via cron.
  • Tentacle-version pinning — Edge attributes in GraphRouter include (tentacle_version, last_calibration_date); if any tentacle is >30 days uncalibrated against its current version, force a shadow-mode quorum re-evaluation before trusting its verdicts.
  • Drift detection — Adapt the existing SVI (System Variability Index) monitor to track routing-decision distribution shift; alert when KL-divergence vs 30-day baseline >0.1.

#6.4 MoA quality dilution (Self-MoA finding)

Definition: Li 2025 (arXiv 2502.00674) shows that mixing weaker LLMs with one strong one drags average quality down. Naive "more tentacles = better" is wrong.

Mitigations:

  • Tentacle gating per task class — qwen2.5-coder is in the quorum only when (a) task is local-codegen-friendly, (b) its prior success rate on this task class is >70%. Otherwise it's voiceless.
  • Anchor invariant — From Rohan Paul Aug-2025 finding: every quorum must contain at least one senior anchor (Opus or Kimi K2.6). Junior-only quorums (Codex+Gemini+qwen) are blocked by ConsensusQuorumEngine validator.

#6.5 Token-cost runaway (the 15x problem)

Definition: Anthropic's data shows multi-agent runs cost 15x baseline chat. 5-tentacle MoA layered consensus could push 30-50x. Easy to blow daily budgets.

Mitigations:

  • Per-quorum token budget — ConsensusQuorumPolicy declares a budget; prism_session:budget_audit blocks dispatch if quorum would exceed.
  • Cascade-first — Always try cheapest tentacle first (qwen2.5-coder); only invoke heavier tentacles on cascade escalation. Aligns with FrugalGPT lineage.
  • Telemetry on token spend — Extend ollama-offload-stats.json schema to track 5-tentacle costs; existing /token-dashboard skill surfaces.
  • Diminishing-returns audit — Per Anthropic's "token usage explains 80% of variance" finding, after a certain token threshold the marginal lift collapses. Auto-detect inflection and cap.

#6.6 Failure-rate baseline (MAST production data)

Definition: Production multi-agent systems fail 41-86.7% of tasks per MAST (arXiv 2503.13657). PRISM cannot afford this rate.

Mitigations:

  • Adopt the 14-mode MAST taxonomy as the standard failure classification in state/shared/findings/; each new chat-bus error is classified to a MAST mode.
  • Acceptance-criterion enforcement — Every new unit's tests must demonstrate it doesn't regress any MAST mode. Add tests/mast-regression.test.ts.
  • Specification ambiguity audit — Top MAST cause. Every quorum's prompt template is reviewed by the prism-review skill (physics + wiring + test rubric) before going live.
