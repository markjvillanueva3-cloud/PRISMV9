#§1 — Why this matters

PRISM already runs four reinforcing knowledge surfaces, each high-quality in isolation but only loosely coupled:

SurfacePathVolumeOwner
Wiki (Karpathy-style)H:/prism/knowledge/wiki/722 entries (engines/dispatchers/memories)Ollama 70% maintenance + Claude synthesis
Memory (per-project)~/.claude/projects/H--prism/memory/~188 indexed feedback_* / reference_* notes + MEMORY.mdClaude (autosync)
Skills~/.claude/commands/ + .claude/commands/440+ skills, YAML+MDMixed (forge-skills, manual)
CLAUDE.mduser-global + project2 files, ~600 linesClaude (back-flow from corrections)

Externally, 2025–2026 has converged hard on a single design pattern across cyrilXBT, Greg Isenberg, Boris Cherny, Karpathy, Kepano (Obsidian CEO), Brian Petro (Smart Connections), and Andy Matuschak: the vault is the agent's working memory; the agent writes more of the vault than the human does; CLAUDE.md (or equivalent schema doc) is the rulebook that prevents drift; skills are reusable trigger-on-keyword micro-prompts. PRISM has all four ingredients already — what's missing is a unified contract for how fleeting captures promote, how skills back-write to memory, how CLAUDE.md absorbs regressions, and how the wiki is the canonical "long-term store" the other three feed.

This card maps the external evidence for that contract so PRISM can unify rather than re-invent.

#§4 — Concrete PRISM unit proposals

All units below assume current state from MEMORY.md (722 wiki entries, ~188 memory files, 440+ skills, dual CLAUDE.md). Each lists depends_on, blocks, and projected viz_node_id for the live system-viz graph.

#U-VAULT01: Unified knowledge-vault schema doc

Create H:/prism/WIKI_VAULT_SCHEMA.md as the canonical contract between wiki / memory / skills / CLAUDE.md. Lifts Karpathy's three-layer model + adds PRISM's fourth (skills as keyword-triggered micro-ingest) + fifth (memory as session-scoped append-only).

  • depends_on: [WIKI_SCHEMA.md (exists), CLAUDE.md (exists, both levels)]
  • blocks: U-VAULT02..06
  • viz_node_id: L0-vault-schema-doc

#U-VAULT02: Memory → Wiki promotion engine

Build MemoryToWikiPromotionEngine.ts that scans ~/.claude/projects/H--prism/memory/feedback_*.md and reference_*.md, scores promotion-worthiness (touched ≥3 sessions OR cited from CLAUDE.md OR cross-referenced from another memory), and promotes to H:/prism/knowledge/wiki/lessons/ or H:/prism/knowledge/wiki/patterns/. Adds promoted-from-memory frontmatter pointer.

  • depends_on: [U-VAULT01]
  • blocks: U-VAULT04, U-VAULT05
  • viz_node_id: L2-engine-memory-promote

#U-VAULT03: CLAUDE.md back-flow agent

Build hook claude-md-backflow.mjs (PostToolUse Stop) — on user-correction patterns (e.g., user message contains "update CLAUDE.md" OR "don't do that again" OR Edit reverts in same session), prompt Claude to append a one-line learning to a section of CLAUDE.md gated by Cherny's rule: "Ruthlessly iterate on these lessons until mistake rate drops." Adds rotation: section auto-prunes entries older than 90 days that haven't been re-cited.

  • depends_on: [U-VAULT01, existing enforce-handoff-topic.mjs (Stop hook pattern)]
  • blocks: U-VAULT06
  • viz_node_id: L3-hook-claude-md-backflow

#U-VAULT04: Skill ↔ Wiki cross-trigger registry

Extend code-system-index.json to index every skill's description: frontmatter against the 722-entry wiki. When a skill fires, auto-inject top-3 wiki entries matching the skill's keyword set. When a wiki entry is read by an agent ≥3 times in a session, suggest skill creation. Mirrors Anthropic's "description field is the single most important line in your entire Skill" doctrine.

  • depends_on: [U-VAULT01, U-VAULT02, existing wiki-precheck-inject.mjs]
  • blocks: U-VAULT05
  • viz_node_id: L4-registry-skill-wiki-xref

#U-VAULT05: MOC (Map of Content) generator for PRISM domains

Generate Nick Milo-style MOCs in H:/prism/knowledge/wiki/moc/ for each domain (lathe, mill, WEDM, CAM, CAD, AI, hooks, dispatchers) — one MOC per domain that links rather than contains. MOCs auto-rebuild nightly from wiki-index. PRISM equivalent of index.md already exists but is flat — MOCs add domain-scoped navigation layers.

  • depends_on: [U-VAULT04, existing WikiIndexMaintainerEngine]
  • blocks: U-VAULT06
  • viz_node_id: L3-engine-moc-generator

#U-VAULT06: Vault-rot sentinel

Daily cron job that scans the four surfaces for rot signals: (a) wiki entries with broken [[wikilink]] targets, (b) memory entries referencing deleted files, (c) skills whose description: matches another skill within Jaccard ≥0.8, (d) CLAUDE.md sections >180 lines or >90 days stale. Emits one-line digest to state/shared/VAULT_HEALTH.md. Matches Karpathy's /lint-wiki operator + Boris's pruning discipline.

  • depends_on: [U-VAULT02, U-VAULT03, U-VAULT04, U-VAULT05]
  • blocks: (terminal)
  • viz_node_id: L5-cron-vault-rot-sentinel

Multiplicative effects of unifying:

  1. Memory → Wiki promotion (U-VAULT02) means observations bias toward eventual permanence, matching Matuschak's "better thinking" over "better note-taking."
  2. CLAUDE.md back-flow (U-VAULT03) institutionalises Cherny's "update CLAUDE.md so you don't make that mistake again" — currently relies on Claude remembering to do it.
  3. Skill ↔ Wiki cross-trigger (U-VAULT04) makes wiki entries discoverable at the moment of need, and makes skill descriptions semantically aligned with the 722-entry corpus.
  4. MOC overlays (U-VAULT05) give domain navigation without forcing destructive folder reorgs (Milo's "non-restrictive, non-limiting perspectives").
  5. Vault-rot sentinel (U-VAULT06) bounds entropy — Karpathy's pattern only works if maintenance cost stays near zero.

#§6 — Failure modes (vault rot, fleeting drift, skill name collision)

#§6.1 Vault rot

Mode: Wiki entries reference deleted/moved files; promoted memories cite stale paths; CLAUDE.md grows past token budget (Mnimiy cites Cherny: "14% you lose to CLAUDE.md before typing a word"); MOCs link to orphaned entries. Mitigation: U-VAULT06 cron sentinel. Also: enforce file-path-in-frontmatter validation on every wiki write (already partial via WikiIndexMaintainerEngine). Indicator: % broken [[wikilinks]] weekly trend.

#§6.2 Fleeting drift (memory hoarding)

Mode: Memory directory grows unbounded; >50% of feedback_*.md files never promote and never re-cite (matches Engineering Ideas substack observation that pure-evergreen "is not optimal for skill acquisition"). Mitigation: U-VAULT02 promotion-or-prune. Memories untouched for 30 days AND not cited from CLAUDE.md AND not promoted → archived to ~/.claude/projects/H--prism/memory/archive/. Hard cap memory dir at 250 active files. Indicator: memory-dir cardinality, mean access age.

#§6.3 Skill name collision

Mode: Anthropic doctrine "the description field is the primary mechanism that determines whether Claude invokes a skill" — two skills with overlapping descriptions race; wrong skill fires; rare skill never fires because more-general skill always wins. Mitigation: Pre-existing PRISM dedup//audit-duplicates covers engines/hooks; extend coverage to skills via U-VAULT04 Jaccard ≥0.8 detection. Already 440+ skills — collision risk is non-zero. Indicator: skill-invocation logs, "which skill fired when both matched" telemetry.

#§6.4 CLAUDE.md token explosion

Mode: Boris's "ruthlessly iterate" loop without a "ruthlessly prune" counter-loop. CLAUDE.md grows to 5k+ tokens; pre-injection cost on every session exceeds savings; rule contradictions emerge. Mitigation: U-VAULT03 with explicit prune step. 90-day stale-without-recitation auto-archive to wiki under lessons/archive/. Hard budget: keep CLAUDE.md ≤ 2,500 tokens (Cherny's stated target). Indicator: CLAUDE.md token count, % entries cited in last 30 days.

#§6.5 Wiki ↔ Skill description divergence

Mode: Skill A says "use SpecificCuttingEnergyEngine for SCE work" but wiki entry for SCE moves to EnergyCoefficientEngine. Skill description rots silently. Mitigation: U-VAULT04 cross-trigger registry validates skill→engine refs match wiki→engine refs on every regenerate. Lint failure blocks Stop hook. Indicator: % skills with valid wiki-entry resolution.

#§6.6 Multi-chat write contention

Mode: 6 concurrent chats all want to back-flow to CLAUDE.md or promote memories simultaneously. Existing commit-ownership-guard covers commits; not all four surfaces. Mitigation: Reuse DistributedLockManager.withLock (already present per CLAUDE.md "Coordination" table) wrapping every U-VAULT0[2-6] write operation. Surface-scoped locks: wiki/, memory/, CLAUDE.md, skills/. Indicator: Lock contention events; conflicting-write rollback rate.

#§6.7 Over-reliance on Karpathy pattern

Mode: Pure-Karpathy three-layer ignores Matuschak's caution: evergreen-only systems harm skill acquisition. PRISM is partly a learning system (lathe-learn, mill-learn, wedm-learn skills exist) — over-flattening fleeting notes into wiki may hurt operator-shadow drills. Mitigation: Preserve journals/ lane in memory for raw learning logs that explicitly do not promote. Tag with frontmatter promotable: false. This is the Matuschak-Karpathy synthesis. Indicator: % learning sessions with intact journal trail.
