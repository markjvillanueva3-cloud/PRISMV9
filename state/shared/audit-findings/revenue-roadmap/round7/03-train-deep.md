# Round-7 Agent 3 — Model-Training Fronts (full detail folded into v7.4 §R8.3)

**`MS-TRAIN-DEEP` = 26 units, ~15.5 single-lane dev-wk / ~7 calendar wk @ 2.2× — extends the existing 20-unit MS-TRAIN (v7.3 §R5, lines ~2016-2239).** Three fronts the user named: (1) Print→CNC program, (2) Print→CAD/CAM, (3) SFC accuracy.

**What exists (the key finding — the plumbing is wired, nothing is trained):** Print corpus — `Docustrata/manifest.json` = 111,745 docs (73,506 needed OCR, 13,960 image-only); `phase15-deep-rescan-parallel.jsonl` = 99,542 deep-rescanned pages; `blueprint-program-join-full-v4.jsonl` = 5,384 part-number joins (≈2,200-3,500 usable print↔g-code pairs at confidence≥0.85); `training-triples-v4.jsonl` = 228 verified prints → 55 with program (38 exact >0.95). `JM DIE/` = 38,834 files (17,023 G-code, 6,726 CAD, 1,892 PDF/DXF/DWG); `LATHE_AI_TRAINING_REPORT.json` parsed 16,558 lathe programs (38,199 mistakes catalogued — and 92.5% missing M30, 56% missing G50 cap → the archive is a NOISY teacher); `MILL_AI_TRAINING_REPORT.json` = 27 (cold). CAD corpus — `cad-corpus-manifest.json` = 11,695 entries (5,877 .ipt, 2,882 .dxf, 453 .step; die 3,239 / general 8,212; only 29.8% classified). `CADSequenceTrainerEngine.ts` has the LoRA lifecycle + injectable `ModelBackend` (currently a count-table Markov stub). **LoRA infra** — ~80 LoRA engines; the **Lathe LoRA cluster is the most complete** (pipeline/cadence/cron/registry/dataset-builder+validator/tribal-extractor+augmentation/drift-detector/master-orchestrator/ollama-deployer/quantization-optimizer/health-monitor/physics-augmented-inference (the `/lathe-lora` skill — gates output against canonical Kienzle bounds)/benchmark-suite/training-script/training-monitor/experiment-tracker/hyperparam-optimizer) + per-process cadence engines (milling/mill-turn/grinding/wedm/laser/waterjet/sinker-edm/5axis, each + dataset-builder) + cross-cutting (`MachineLoRABaseEngine`, `LoRAAdapterRegistryEngine`, `LoRACompositionEngine`, `LoRAMoEGatingEngine`, `AdaLoRARankAllocatorEngine`, `ContinualLoRAEngine`, `FederatedLoRAEngine`, `DetachedLoRARunnerEngine`, `PRISMLoRAAdapterEngine`) — **but every checkpoint = `status:"not_trained", samples:0`. Base model = mistral-7B-v0.1.** The 220-course catalog (`extracted_modules/complete_extraction/PRISM_220_COURSE_CATALOG.js`) = algorithm-provenance metadata, NOT a training corpus.

**Front 1 — Print→CNC program (8 units):** data ≈ 2,200-3,500 print↔g-code pairs + 16,558 lathe programs (program-language pretraining) + ~4,500 net-new prints from the 99,542 Docustrata pages once OCR'd. Pipeline: `phase8-tiered-blueprint-classifier.py` → `BlueprintOCREngine`/`BlueprintVisionOCREngine` → structured `PartFeature` → `BlueprintProgramJoinEngine`/`PairedPrintProgramBundleEngine` → `LatheLoRADatasetBuilderEngine`/`MillingLoRADatasetBuilderEngine`/`WEDMLoRADatasetBuilderEngine` → `LatheLoRADatasetValidatorEngine` → `P2P_TRAINING_CORPUS_<process>.jsonl`. **Validation = TWO-TIER (the noisy-archive landmine): (1) functional-equivalence via `cnc_simulate_physics` is the GATING metric; (2) edit-distance-to-archive is a SOFT flag only.** Held-out = 10-15% stratified by (process, customer, material, feature-class) → `P2P_HELDOUT_SET.json`; upgrade `PrintToProgramRegressionHarnessEngine` from synthetic-fixture to real-file replay. Cadence: one LoRA per process, composed at inference via `LoRACompositionEngine`+`LoRAMoEGatingEngine`; initial train at ≥500 pairs/process; re-train drift-triggered + monthly floor. Target ≥85% functional-equiv held-out (lathe), ≥75% (mill/mill-turn), ≥70% (multi-axis/EDM). Units `U-TRAIN-P2P-01..08`.

**Front 2 — Print→CAD/CAM (7 units):** ~1,500-2,500 print↔CAD pairs (the 6,726 JM-Die CAD files that part-number-match a drawing). Pipeline: `CADCorpusIngesterEngine`+`CADCorpusFeaturePrevalenceLearnerEngine` finish the 70% unclassified → `CADTrainingCorpusOrchestratorEngine` → `CAD_TRAINING_CORPUS.jsonl` → `CADSequenceTrainerEngine` 90/10 split; print→CAD pairs via `BlueprintToCADGenerationEngine`+`cad_blueprint_*`. Validation = geometric-similarity (`CADRegenerationTestEngine` rubric: volume Δ<5%, bbox<2%, topology Jaccard>80%, feature-count<20%) + feature-recognition F1; held-out 15% stratified by part-class; CAM half via `CAMFeatureLearningEngine` against the 9 known-good CAM projects + toolpath functional-equiv through `cam_simulate`. Cadence: wire a real HF/llama.cpp backend into `CADSequenceTrainerEngine` (replace the stub); re-train at ≥300 new classified files or geometric drift. Target ≥80% geometric-pass-rate, ≥0.75 feature-F1. Units `U-TRAIN-CAD-01..07`.

**Front 3 — SFC accuracy (6 units; the *calibration/training loop* — the *vs-HSMAdvisor benchmark* is §R8.4/round7-04):** the 3 round-3.5 gaps + fills — spindle-power telemetry → MTConnect/OPC-UA tap (`prism_machine_live:mtconnect_spindle_load`/`opcua_machine_status`) → `bayesian_predict_force` residuals; tool-life cold-start → bootstrap from Taylor C/n + `LatheLoRATribalExtractorEngine` mining "tool changed at" comments → refine with operator log when pilot is live; 4.5h FRF downtime → defer FRF chatter calibration to one-time per-machine commissioning, use analytical SLD with conservative damping until then. Methodology: Bayesian calibration of Kienzle `kc1.1`/`mc` + Taylor `C`/`n` per (ISO-group × machine × tool-class) cell via `prism_adaptive_control:bayesian_calibrate`+`calibration_kienzle`/`calibration_taylor` + secondary `calibration_drift`/`calibration_thermal`/`calibration_model_select`/`calibration_surface_bias`, state via `prism_calc:physics_calibrate_submit`→`physics_calibrate_state` (populate the currently-empty `calibration*.json`). Each (op × machine × material × tool-coating × engagement-regime) cell must hit ≥85% empirical conformal coverage before claiming Omega 1.0. LoRA-per-machine cadence (the Lathe LoRA cluster already does it: `LatheLoRACadenceOrchestratorEngine` schedules, `LatheLoRADatasetBuilderEngine` builds the per-machine set, `LatheLoRAOllamaDeployerEngine` deploys to local Ollama, `LatheLoRAPhysicsAugmentedInferenceEngine` gates against Kienzle bounds) — initial per-machine train at commissioning (~10h onboarding + overnight GPU), re-train drift-triggered + quarterly floor; JM-Die fleet order Haas TM-1P → 7 Okuma OSP → Hurco WinMAX → Mitsubishi sinker/wire. Target ≥90% of predictions within ±15% measured Fc / ±20% measured tool-life per calibrated cell (envelope baseline ≈±30%). Units `U-TRAIN-SFC-01..06`.

**Cross-cutting (5 units):** `U-TRAIN-X-01` unified extract→label (Docustrata phase8/9/15 → `PartFeature` JSON, shared Fronts 1+2) · `02` deterministic stratified split utility (generalize `CADSequenceTrainerEngine.splitCorpus`) · `03` detached-GPU training runner (`DetachedLoRARunnerEngine`+`LatheLoRATrainingScriptEngine` — real HF/peft backend, the one piece every front needs that's stubbed; one CUDA GPU ≥16GB for mistral-7B QLoRA, overnight; CPU-only inference after 4-bit quant) · `04` adapter registry + deploy (`LoRAAdapterRegistryEngine`+`LatheLoRAModelRegistryEngine`+`LatheLoRAOllamaDeployerEngine`, versioned, quantized) · `05` drift-monitor + re-train trigger (`LoRADriftCoordinatorEngine` → `CAM_ML_DRIFT_LOG.jsonl`). Cron (via `cron-bootstrap`/`cron-manage`): nightly drift-check, weekly corpus-rebuild, monthly LoRA re-train floor per process, quarterly per-machine re-train. Orchestration: `prism_orchestrate:cognitive_learning_*`/`cognitive_neural_*`/`cognitive_meta_orchestrate`; `/lathe-lora`/`/lathe-learn`/`/mill-learn`/`/grinder-learn`/`/sinker-learn`/`/learn-everything` skills.
