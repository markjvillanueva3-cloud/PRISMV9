# Round-6 Agent 3 — Minimum Payment Path Gap (+ 1 security hole)

**Verdict:** ~90% of billing logic exists across two parallel impls; 3 missing welds; 1 SECURITY HOLE. The v7.1 "5-unit P0 hoist" mistakes signature-primitives+tax+SOC2 for "take a card."

**The literal minimum to take a card (Stripe Checkout):** (1) Stripe account + Product/Price objects, live `STRIPE_SECRET_KEY`; (2) `POST /create-checkout` → `stripe.checkout.sessions.create({mode:'subscription', line_items, metadata:{userId,plan}, success_url, cancel_url})` → return `session.url`; (3) `POST /webhook` (raw-body, no auth) → `stripe.webhooks.constructEvent(rawBody, sig, STRIPE_WEBHOOK_SECRET)` → on `checkout.session.completed`, **persist `user.tier = metadata.plan`**; (4) `requireTier('feature')` middleware; (5) `POST /billing/portal` (optional MVP); (6) one pricing config. That's it — everything else in MS1 (tax, dunning, SOC2, GDPR, Paddle, proration, VAT, refund-atomicity, anti-fraud) is compliance/scale hardening, not "take a card."

**What exists:**
- **`BillingEngine.ts`** (748 ln, wired to `prism_business` 8 actions `billing_get_plans/get_post_prices/calc_post_price/create_checkout/create_portal/create_post_checkout/handle_webhook/stats`): real plan catalog (free $0 / Shop $49 / Team $199 / Enterprise $999 — *platform* catalog), real tiered usage pricing (`calcPostPrice` correct), `createCheckout` returns Stripe-shaped session, **`handleWebhook` does real HMAC-SHA256 sig verification** (Stripe `t=…,v1=…`, 5-min replay window, `timingSafeEqual`) + **idempotency dedup keyed by `event.id`** + `applyWebhookEvent` mutates state on `checkout.session.completed`. ⚠️ Zero network calls (mock URLs `https://billing.prism.local/…`). ❌ **Does NOT flip `user.tier`** — creates a `Subscription` row in `billing-state.json`, nothing reads it back into `req.user.plan`.
- **`StripeBillingEngine.ts`** (412 ln, wired to `routes/billing.ts`): real live-mode path (`STRIPE_SECRET_KEY` → native `fetch` to `api.stripe.com/v1` for `checkout/sessions/create`, `subscriptions/retrieve|cancel`), `createCheckoutSession` builds proper `price_data` payload (`mode:'subscription'`, card, success/cancel URLs), `handleWebhookEvent` handles 7 event types. ⚠️ Defaults `testMode:true`. ❌ **Webhook sig verification is a NO-OP in live mode** (`return JSON.parse(payload)` — "signature verification requires Stripe SDK"); the route's check is a *comment* `// In production, verify Stripe signature here` — **SECURITY HOLE: anyone can POST `checkout.session.completed` and self-grant a paid tier.** ❌ `handleWebhookEvent` returns `{action:'subscription_created', data:{userId,plan}}` but the route says "DB calls are fire-and-forget here" — the write that sets `user.plan` is unimplemented.
- **`tierGate.ts` middleware** — ✅ fully real: `TIER_LIMITS` table (free/starter/pro/shop/enterprise), pure `checkTierAccess`, `requireTier('feature')` factory, 403 + structured body, fail-safe-to-free. The paywall TEETH exist — just not bitten down on most routes, and `req.user.plan` is never refreshed from billing state.

**The 5-unit P0 hoist is missing the Checkout+grant unit.** `U-SUB-00` (dispatcher scaffold) · `U-SUB-19` (Stripe webhook *security primitives* — `StripeSignatureVerifierEngine`: HMAC, raw-body, replay, dedup — necessary not sufficient) · `U-SUB-22` (Stripe Tax bridge — compliance gating, NOT payment; you can charge a US customer with zero tax config) · `U-SUB-28` (SOC2 immutable audit hash-chain — compliance, not payment) · `U-SUB-04` (license-validator middleware). **No unit says "create a Checkout Session, on `completed` set `user.tier`, redirect."** And `U-REV-MS0-ACT-SUBTIER-01 depends_on [U-SUB-22, U-SUB-30]` = the INVERTED dependency (tier-flip blocked by tax compliance).

**Pricing is hardcoded in 4 disagreeing places:** `BillingEngine.PLAN_CATALOG` (free/Shop$49/Team$199/Enterprise$999 — platform); `StripeBillingEngine.PLAN_PRICES` (free/starter$29/pro$79/shop$199/enterprise$499 — what `tierGate` keys off); `StripeBillingEngine.POST_PROCESSOR_PRICES` ($9/mo·controller, $79/yr, $199 perm, $799/5-bundle, $2499 all — doesn't match the roadmap's "$299/controller / $1499 unlimited"); SFC tiers (`round3-5/02`: free/hobbyist$9/pro$39/shop$249/enterprise$999). **`state/shared/feature-tiers.json` (referenced by `U-SUB-03`/`FeatureTierEngine` as "canonical") DOES NOT EXIST on disk.**

**Proposed `MS-PAY` (~6 units, ~5 working days of integration):** `U-PAY-01` Stripe Checkout link + webhook → tier flag (create Product/Price objects in one config module; wire `routes/billing.ts /webhook` to call `BillingEngine.handleWebhook` THEN `userStore.setPlan(metadata.userId, metadata.plan)`; flip `STRIPE_TEST_MODE=false`) — ~70% exists, the join + persistence write missing · `U-PAY-02` webhook sig verification on the live route (replace the no-op + comment with `BillingEngine.verifySignature`) — **THE SECURITY BLOCKER** · `U-PAY-03` apply `requireTier` to the SFC + Master-Post + CAD-CAM routes — middleware exists, not mounted · `U-PAY-04` `user.plan` refresh per-request from billing state (read `Subscription` row in auth middleware) — the dangling link · `U-PAY-05` Stripe Billing Portal route (`createPortalSession` exists; route exists; needs live keys + "Manage Billing" button) · `U-PAY-06` one canonical `state/shared/pricing-config.json` (collapse the 4 tables; create `feature-tiers.json`; `BillingEngine`/`StripeBillingEngine`/`tierGate.TIER_LIMITS`/every SFC page reads from it; Stripe Price objects generated from it). Everything else (Paddle RSA, VAT/VIES, tax-exempt certs, proration math, dunning, GDPR cascade, refund atomicity, SOC2, anti-fraud, PCI scan, multi-seat) = the full ~37-unit MS1 build, correctly deferred.
