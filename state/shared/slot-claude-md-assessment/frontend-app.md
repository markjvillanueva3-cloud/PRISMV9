### 4. Domain-specific safety rules (NOT in current file)

- **NEVER call raw `fetch()` to the 3100 bridge** — always route through `src/lib/resilientFetch.ts` (has retry, timeout, offline detection). A raw fetch that silently returns `{}` on MCP timeout is the #1 silent-zero regression class.
- **Dispatcher response envelope check mandatory** — every `prism_*` response must be checked for `{result, error}` shape before rendering; a `200 OK` with `error: "..."` is NOT a success. Pattern: `if (res.error) throw new DispatcherError(res.error)`.
- **Service worker cache invalidation** — after any dispatcher mutation (ERP write, quote update), explicitly invalidate the relevant sw.ts cache bucket or the offline cache serves stale data to the next operator who loads the page.
- **Polish/Spanish safety strings are P0** — alarm decode text, G-code fault descriptions, machine-load alerts, E-stop confirmations: these MUST be in the operator's `navigator.language` primary language. English fallback is acceptable; English-only is a safety failure.
- **No physics constants in frontend** — G-code preview tooltips, feed/speed display values: derive from `prism_calc` dispatcher responses, never hardcode Kienzle/Taylor constants in TSX files.

### 5. What NOT to do in this domain

- Do NOT import from `mcp-server/src/engines/` directly — frontend is a pure HTTP consumer of the 3100 bridge; no direct engine imports ever.
- Do NOT inline dispatcher response types — codegen from Zod schemas (`papa`-coordinated) or import from `src/types/`; never hand-write `interface QuoteResponse { ... }`.
- Do NOT use `useEffect` for dispatcher fetches without an `AbortController` + request key (verified regression class: tab-switch race condition).
- Do NOT debounce spindle-load WebSocket at the component level — debounce at the hook/store layer; component re-renders at 10 Hz × 5 machines × N charts = re-render storm.
- Do NOT ship a page without an `<EnhancedErrorBoundary>` (verified component exists at `src/components/EnhancedErrorBoundary.tsx`).
- Do NOT add pages to `src/pages/` without a route entry and a Playwright smoke test in `e2e/`.
- Do NOT use `localStorage` for dispatcher state — use Zustand stores + sw.ts cache for offline tolerance.

### 6. Top tribal gotchas for frontend-app

- **Polish character mis-encoding (silent Latin-1 corruption)** — every storage boundary and HTTP response header must declare `charset=utf-8`; the `Ä`/`ę`/`ł` class of corruption is silent and only surfaces at runtime with Polish operators.
- **WebSocket room naming convention** — `ws_room_send` room IDs must match the machine identifier convention (`VMC-01`, `EDM-01`, etc.) — if a frontend subscribes to `"vmc01"` (no dash) it gets zero events from the bridge.
- **`OptimisticSyncManager` idempotency keys** — every POST through `OptimisticSyncManager.ts` needs a client-generated UUID idempotency key; shop-floor WiFi drops cause double-submits without it.
- **Cold-boot budget** — the service worker pre-caches critical dispatcher responses; if a new page does not register its critical queries in the sw.ts precache manifest it will be blank on first offline load.
- **`prism_business` scheduling vs ERP vs time-clock** — these are separate action groups within the same dispatcher; mixing scheduling actions into an ERP call returns a dispatcher error that silently renders as empty table rows.
