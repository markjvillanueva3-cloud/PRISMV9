WIRE EDM STUDIO WIZARD — ARCHITECTURE REVIEW SUMMARY
================================================================================

RATING: 42/100

EXECUTIVE ISSUES (Fix Before Starting):
1. [CRITICAL] 16 files is too many — merge to 6 files (60% reduction)
2. [CRITICAL] useReducer + cascading invalidation over-engineered — use useState
3. [CRITICAL] THREE.ExtrudeGeometry fails on self-intersecting DXF profiles
4. [CRITICAL] localStorage autosave has no versioning/migration — use URL params
5. [CRITICAL] 2-column layout breaks on mobile, not addressed

SECONDARY ISSUES (Fix During Build):
6. [HIGH] Bundle impact: 6 lazy chunks + Monaco + Three.js — consolidate
7. [HIGH] Error recovery path unclear — step 3 failure loses steps 1-2 data
8. [HIGH] No DXF validation before 3D render — corrupt files crash viewer
9. [HIGH] Cascading async calls can deadlock on back-button
10. [MEDIUM] ProfileMesh re-renders on any parent state change (unmemoized)

================================================================================
KEY INSIGHTS
================================================================================

✓ GOOD DECISIONS:
  - Wizard pattern is right for the feature
  - Lazy loading is appropriate
  - Reusing Viewer3D + GcodeEditor is smart
  - Follow PpgContext pattern for autosave (but fix for structured data)

✗ BAD DECISIONS:
  - 16 files for a single feature (violates cohesion)
  - useReducer for simple multi-step form (use useState)
  - ExtrudeGeometry on arbitrary DXF profiles (architectural mismatch)
  - localStorage without versioning (data loss risk)
  - No mobile strategy for 2-column layout

⚠ MISSING:
  - Error recovery: step failure erases downstream data
  - Validation: no checks before rendering/advancing
  - Testing: no test plan for complex workflow
  - Undo/redo: but breadcrumb savepoints cheaper alternative
  - Accessibility: no mention of keyboard nav, screen readers
