## CRITICAL ISSUES

C1: Division by Zero in Hardness (Line 208)
- Issue: vc *= math.pow(ref_h.get(iso, 200) / hardness, 0.3)
- Risk: ZeroDivisionError if hardness=0
- Severity: CRITICAL
- Fix: Check if hardness > 0 before division

C2: Float Infinity in RPM Calculation (Line 210)
- Issue: rpm = min(round((vc * 1000) / (math.pi * d)), max_rpm)
- Risk: If d=0, produces inf; cascades to NaN in force/power/deflection
- Severity: CRITICAL
- Fix: Validate d > 0.001 before calculation

C3: selectedItem.name Without Null Check (Lines 514, 520, 447, 469)
- Issue: Calling .name on None if dropdown is empty
- Risk: AttributeError crash on panel open if PRISM offline
- Severity: CRITICAL
- Fix: Check if selectedItem is not None before accessing .name

C4: JSON Parsing Without Exception Handler (Line 29)
- Issue: json.loads() not wrapped in try-except for JSONDecodeError
- Risk: Crash if PRISM returns invalid JSON (500 error HTML)
- Severity: CRITICAL
- Fix: Catch json.JSONDecodeError explicitly

C5: activeDocument Can Be None (Line 604)
- Issue: No null check before calling .products on doc
- Risk: AttributeError if Fusion has no open document
- Severity: CRITICAL
- Fix: Check if doc is not None before using

C6: Dictionary Access Without .get() (Lines 56, 70, 103)
- Issue: Code uses r["result"] instead of r.get("result")
- Risk: KeyError if API response format changes
- Severity: CRITICAL
- Fix: Use .get() with fallback defaults

C7: Network Timeout Hidden in Generic Exception (Lines 26-30)
- Issue: socket.timeout caught by except Exception, no differentiation
- Risk: Silent fallback without alerting user of slow server
- Severity: CRITICAL
- Fix: Catch socket.timeout separately with logging

C8: Moment of Inertia Underflow (Lines 230-232)
- Issue: I calculation with d=0 produces denormalized floats/NaN
- Risk: Deflection becomes NaN, UI displays garbage
- Severity: CRITICAL
- Fix: Validate d > 0.1 before I calculation
